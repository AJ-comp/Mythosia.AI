# Розділювачі тексту

Розділювачі ділять документи на чанки перед ембеддингом. Розмір чанка та перекриття суттєво впливають на якість пошуку.

## Доступні розділювачі

### CharacterTextSplitter

Розбиває за кількістю символів. Швидкий і простий, але може розрізати текст посеред речення:

```csharp
.WithTextSplitter(new CharacterTextSplitter(500, 50))
```

### RecursiveTextSplitter (рекомендований за замовчуванням)

Намагається розбивати за смисловими межами у порядку пріоритету: абзаци → речення → слова → символи. Дає більш зв'язні чанки:

```csharp
.WithTextSplitter(new RecursiveTextSplitter(500, 50))
```

### TokenTextSplitter

Розбиває за кількістю токенів, а не символів. Точніше враховує ліміти контекстного вікна LLM:

```csharp
.WithTextSplitter(new TokenTextSplitter(256, 32))
```

Корисний, коли модель ембеддингу має суворі обмеження за кількістю токенів.

### MarkdownTextSplitter

Структурно-обізнаний розділювач, який розуміє ієрархію заголовків Markdown (H1–H6), блоки коду та таблиці, розбиваючи вміст на семантично значущі одиниці:

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500, 50))
```

Оптимальний для документації, README та вихідних даних структурованих завантажувачів документів (Office, HWP).

> [!TIP]
> Завантажувачі Word, Excel, PowerPoint та HWP внутрішньо перетворюють документи на Markdown. Використання `MarkdownTextSplitter` для цих документів гарантує збереження структури таблиць і блоків коду при розбитті.

#### Якість розбиття таблиць

`MarkdownTextSplitter` розбиває Markdown-таблиці **порядково**. Рядок ніколи не розрізається навпіл, а кожен результуючий чанк автоматично містить **рядок заголовка та розділювач**:

```
Вихідна таблиця:
| Ім'я   | Відділ | Зарплата |
|--------|--------|----------|
| Аліса  | Розроб. | 150 000    |
| Борис  | PM     | 140 000    |
| Віра   | Дизайн | 130 000    |

→ Чанк 1:
| Ім'я   | Відділ | Зарплата |
|--------|--------|----------|
| Аліса  | Розроб. | 150 000    |
| Борис  | PM     | 140 000    |

→ Чанк 2:
| Ім'я   | Відділ | Зарплата |
|--------|--------|----------|
| Віра   | Дизайн | 130 000    |
```

Кожен чанк є самостійною коректною таблицею, що гарантує якість ембеддингів та пошуку.

#### Захист блоків коду

Блоки, обмежені кодовими огорожами (`` ``` ``), обробляються як **атомарні одиниці**. Блок коду ніколи не розривається, навіть якщо він перевищує розмір чанка, зберігаючи семантику коду.

#### Хлібні крихти заголовків

Кожен чанк автоматично отримує префікс зі шляхом заголовків, що ведуть до його вмісту, збагачуючи контекст для векторного пошуку:

```
# Керівництво з продукту
## Встановлення
### Windows

(вміст цього розділу)
```

Ця функція керується властивістю `IncludeHeadingBreadcrumb` (за замовчуванням: `true`).

## Підбір параметрів

| Параметр | Вплив |
|----------|-------|
| `chunkSize` (більше) | Більше контексту на чанк, менше чанків, дешевший ембеддинг |
| `chunkSize` (менше) | Точніший пошук, більше чанків, більше ембеддингів |
| `chunkOverlap` | Запобігає втраті інформації на стиках чанків |

Добра відправна точка: `chunkSize: 500, chunkOverlap: 50`.

## Розмір чанка та кількість токенів (багатомовність)

`chunkSize` вимірюється в **символах**, але обмеження моделей ембеддингів — в **токенах**. Однакова кількість символів може давати зовсім різну кількість токенів залежно від мови:

| Мова | 1 000 символів ≈ токенів | Рекоменд. chunkSize |
|------|--------------------------|---------------------|
| Англійська | ~250 токенів | 500–2 000 |
| Корейська / Японська / Китайська | ~800–1 500 токенів | 300–1 000 |

> [!WARNING]
> CJK-текст (корейська, японська, китайська) має значно вище співвідношення токенів до символу, ніж англійська. Якщо чанки перевищать ліміт токенів моделі ембеддингів (напр., 2 048 токенів), виникне помилка. Зменшуйте `chunkSize` із запасом при роботі з CJK-документами.

Наприклад, при моделі ембеддингів з лімітом 2 048 токенів:

```csharp
// Англійські документи: 2000 симв. ≈ 500 токенів → із запасом
.WithTextSplitter(new MarkdownTextSplitter(2000, 200))

// Корейські документи: 1000 симв. ≈ 1000 токенів → безпечний діапазон
.WithTextSplitter(new MarkdownTextSplitter(1000, 200))
```

## Розділювач для кожного документа

У `RagBuilder` можна призначити окремий розділювач для кожного документа:

```csharp
.WithRag(rag => rag
    .AddDocuments(new PlainTextDocumentLoader(), "readme.md", new MarkdownTextSplitter(600, 60))
    .AddDocuments(new PlainTextDocumentLoader(), "data.txt",  new RecursiveTextSplitter(300, 30))
    .WithTextSplitter(new RecursiveTextSplitter(500, 50))  // за замовчуванням для решти
)
```

## Власний розділювач

Реалізуйте інтерфейс `ITextSplitter` для повністю користувацької логіки розбиття:

```csharp
public class SentenceSplitter : ITextSplitter
{
    public IReadOnlyList<RagChunk> Split(RagDocument document)
    {
        var sentences = document.Content.Split(". ");
        return sentences.Select((s, i) => new RagChunk
        {
            Content = s,
            Index = i,
            DocumentId = document.Id
        }).ToList();
    }
}

// Реєстрація:
.WithTextSplitter(new SentenceSplitter())
```
