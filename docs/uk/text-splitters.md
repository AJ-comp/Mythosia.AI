# Розділювачі тексту

Результату пошуку потрібен контекст для відповіді, але цілий документ як один фрагмент ускладнює вибір потрібного місця. Розбиття балансує розмір і контекст. Ці розділювачі працюють локально за правилами без моделі ШІ. Обирайте за структурою документа й перевіряйте пошук власними запитаннями.

## Доступні розділювачі

### CharacterTextSplitter

Для звичайного тексту, коли достатньо простого обмеження розміру. Надає перевагу заданому роздільнику, але може розрізати речення. Типово `RagBuilder` використовує `CharacterTextSplitter(300, 30)`; розширення `.md` не обирає Markdown-розділювач автоматично.

```csharp
.WithTextSplitter(new CharacterTextSplitter(500, 50))
```

### RecursiveTextSplitter (рекомендований за замовчуванням)

Для тексту, де абзаци та слова бажано залишати разом. Типовий порядок: порожній рядок → перенесення рядка → `. ` → пробіл → окремі символи. Це текстові правила, а не оцінка змісту моделлю; крапка з пробілом лише наближено визначає межу речення.

Повторювані елементи `Separators` застосовуються один раз, у порядку першої появи. Дублювання розділювача не додає проходу поділу. Довгі списки обробляються без глибоко вкладених рекурсивних викликів.

```csharp
.WithTextSplitter(new RecursiveTextSplitter(500, 50))
```

### TokenTextSplitter

Лише для приблизного підрахунку слів, розділених пробільними символами. Попри назву, `MaxTokensPerChunk` і `TokenOverlap` рахують одиниці `TokenSeparators` (типово пробіли, табуляції та перенесення рядків), а не токени моделі. У результаті роздільники нормалізуються до пробілів. Текст без пробілів може залишитися однією довгою одиницею; ліміт токенів моделі не гарантується.

```csharp
.WithTextSplitter(new TokenTextSplitter(256, 32))
```

### MarkdownTextSplitter

Для Markdown-документів або Markdown із завантажувачів Office/HWP, коли потрібно зберегти заголовки, рядки таблиць і блоки коду. Розпізнає ATX-заголовки (`#`–`######`), огороджені блоки коду та таблиці. Це розділювач за правилами, не повний синтаксичний аналізатор Markdown. Конструктор приймає лише `chunkSize`; аргументу чи налаштування overlap для Markdown немає.

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500))
```

#### Якість розбиття таблиць

Розпізнані GFM-таблиці діляться між рядками; заголовок і рядок-роздільник повторюються в кожному табличному чанку. Зовнішні вертикальні риски необов’язкові (`Name | Value` підтримується). Так зберігаються назви стовпців; якість пошуку також залежить від документів, ембедингів і запитань.

Жирний текст у комірці належить її рядку: наприклад, `**Без повернення**` у рядку компанії A не має стати умовою для B. Комірки таблиць і блоки коду не перетворюються на повторювані текстові мітки. Окремий рядок `**мітка**` розпізнається лише на початку абзацу або текстового блоку, після порожнього рядка чи структурної межі. Жирний рядок усередині наявного абзацу не створює нового абзацу чи повторюваної мітки. Розпізнана мітка може повторюватися в частинах свого блоку; таблиця, огорожа коду, заголовок або наступна розпізнана мітка завершує її область дії.

```
Вихідна таблиця:
| Ім'я   | Відділ | Зарплата |
|--------|--------|----------|
| Аліса  | Розроб. | 150 000    |
| Борис  | PM     | 140 000    |
| Віра   | Дизайн | 130 000    |

→ Чанк 1:
| Ім'я   | Відділ | Зарплата |
|--------|--------|----------|
| Аліса  | Розроб. | 150 000    |
| Борис  | PM     | 140 000    |

→ Чанк 2:
| Ім'я   | Відділ | Зарплата |
|--------|--------|----------|
| Віра   | Дизайн | 130 000    |
```

#### Захист блоків коду

Блоки з огорожею зі зворотних лапок або тильд залишаються цілими. Закривальна огорожа має той самий символ і не меншу довжину, ніж відкривальна; коротша огорожа всередині не завершує блок. Для збереження цілого блоку допускається перевищення `ChunkSize`.

Відступ відкривальної огорожі зберігається разом із кодом, тому поділ не змінює відступи відображеного коду. Дані відкривальної огорожі аналізуються один раз на блок, без повторного сканування довгої огорожі для кожного рядка вмісту.

#### Хлібні крихти заголовків

Типово `IncludeHeadingBreadcrumb` дорівнює `true`: кожен чанк повторює шлях заголовків, зберігаючи контекст знайденого уривка. `false` вимикає лише повторення, а початкові заголовки залишаються. Розділи лише із заголовком також зберігаються.

`MinSplitHeadingLevel` приймає 1–6 та визначає рівні заголовків, які починають розділ; типове значення — 1. Коли батьківський заголовок змінюється, попередній вкладений розділ завершується, щоб його старий шлях заголовків не застосовувався до нового вмісту.

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500)
{
    IncludeHeadingBreadcrumb = false
})
```

## Підбір параметрів

`CharacterTextSplitter`, `RecursiveTextSplitter` і `MarkdownTextSplitter` вимірюють кодові одиниці UTF-16 (`string.Length`), а не токени моделі чи видимі знаки. Сурогатна пара, наприклад емодзі, не розрізається. За розміру 1 пара з 2 одиниць може перевищити ліміт. Цілісність комбінувальних символів і повних графем не гарантується.

Розмір має бути додатним, перекриття — невід’ємним. Неправильні налаштування спричиняють `ArgumentOutOfRangeException` до обробки; змінювані властивості перевіряються повторно під час розбиття. Перекриття не менше розміру вимикається для сумісності. У Character/Recursive це цільове значення, узгоджене з роздільниками, межами Unicode та місцем у наступному чанку; `0` означає відсутність перекриття. Додатковий кінцевий чанк лише з останнього перекриття не створюється.

Для Markdown `ChunkSize` — бюджет вмісту **без повторюваного шляху заголовків**. Цілий блок коду чи заголовок таблиці з одним повним рядком може його перевищити. Звичайний текст дотримується розміру з наведеним винятком для сурогатної пари.

Повторення заголовків і шапок таблиць не повинно перетворювати малий документ на необмежений обсяг тексту для ембеддингу. Тому Markdown має загальний бюджет виводу документа `max(65536, 32 × document.Content.Length)` одиниць UTF-16 — суму довжин усіх кінцевих чанків, включно з повторюваними шляхами заголовків, шапками та мітками. Бюджет перевіряється до створення надмірних повторів; у разі перевищення виникає `InvalidOperationException`, без обрізання вмісту чи повернення часткового результату. `ChunkSize` та винятки для неподільних блоків діють у межах цього загального ліміту. У типовій індексації RAG помилка поділу виникає до ембеддингу або заміни записів, тож попередній індекс документа зберігається. Це ліміт вихідного тексту, а не токенів моделі чи пам’яті процесу. Бюджет діє для кожного виклику `Split` і зростає з довжиною входу; це не фіксований ліміт розміру документа.

Почніть, наприклад, із `RecursiveTextSplitter(500, 50)` для тексту чи `MarkdownTextSplitter(500)` для Markdown і перевірте типові запитання. Більші чанки зберігають більше контексту; перекриття повторює текст і збільшує роботу ембедингу. Поліпшення пошуку не гарантується.

Для суворого ліміту рахуйте кожен кінцевий чанк, включно з повтореними заголовками, токенізатором цільової моделі. Кількість символів/слів і мовні коефіцієнти не є безпечним бюджетом токенів. За потреби реалізуйте `ITextSplitter` із цим токенізатором.

Виправлення змінюють межі чанків відповідних документів. Переіндексуйте ті самі ID документів, замінивши старі чанки, та оновіть пов’язані кеші ембедингів і базові результати оцінювання. Збережені чанки не переписуються автоматично.

## Розділювач для кожного документа

У `RagBuilder` можна призначити окремий розділювач для кожного документа:

```csharp
.WithRag(rag => rag
    .AddDocuments(new PlainTextDocumentLoader(), "readme.md", new MarkdownTextSplitter(600))
    .AddDocuments(new PlainTextDocumentLoader(), "data.txt",  new RecursiveTextSplitter(300, 30))
    .WithTextSplitter(new RecursiveTextSplitter(500, 50))  // за замовчуванням для решти
)
```

## Власний розділювач

Якщо хочете створити власний модуль розбиття й підключити його, реалізуйте інтерфейс `ITextSplitter`:

Індексація не має повідомляти про успіх, якщо один фрагмент перезаписує інший. Надайте кожному фрагменту непорожній ID, унікальний у колекції, і скопіюйте метадані документа, щоб зберегти фільтри за компанією або правами доступу. Приклад поєднує ID документа та номер фрагмента. Конвеєр відхиляє відсутні ID й дублікати в межах документа; замінні ID не генеруються. Див. [перевірку індексації](rag-pipeline.md#indexing-validation).

```csharp
public class SentenceSplitter : ITextSplitter
{
    public IReadOnlyList<RagChunk> Split(RagDocument document)
    {
        var sentences = document.Content.Split(". ");
        return sentences.Select((s, i) => new RagChunk
        {
            Id = $"{document.Id}_chunk_{i}",
            Content = s,
            Index = i,
            DocumentId = document.Id,
            Metadata = new Dictionary<string, string>(document.Metadata)
        }).ToList();
    }
}

// Реєстрація:
.WithTextSplitter(new SentenceSplitter())
```
