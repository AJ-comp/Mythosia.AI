# Гібридний пошук

> 📍 **Пайплайн запитання-відповіді:** [Переписування запитів](rag-query-rewriting.md) → Ембеддинг → Фільтрація → **`Пошук`** → [Переранжування](rag-reranking.md) → Побудова контексту

## Навіщо потрібен гібридний пошук

Чистий векторний пошук чудово справляється із семантичним зіставленням — запит «скасувати підписку» збігається з «припинити членство», навіть якщо слова не перетинаються. Проте він може пропустити **точні терміни** — назви продуктів, коди помилок або ідентифікатори, які користувач вводить дослівно.

Ключовий пошук BM25 прекрасно обробляє такі випадки, але не розуміє семантики. **Гібридний пошук поєднує обидва підходи**, даючи найкраще з двох світів: семантичне розуміння плюс точний збіг за ключовими словами.

## Налаштування

Об'єднайте щільний векторний пошук із ключовим пошуком BM25 одним викликом методу:

```csharp
.WithRag(rag => rag
    .UseHybridSearch(vectorWeight: 0.6f)  // 60% вектор, 40% BM25
    .AddDocument("knowledge-base.txt")
)
```

`vectorWeight` приймає значення від 0.0 (чистий BM25) до 1.0 (чистий вектор). Значення в діапазоні **0.5–0.7** підходить для більшості завдань.

## Рекомендації щодо вибору

| Сценарій | Рекомендована вага |
| --- | --- |
| Загальні запитання природною мовою | 0.7–0.8 (більше вектора) |
| Технічна документація з конкретними термінами | 0.4–0.5 (збалансований) |
| Пошук коду або кодів помилок | 0.2–0.3 (більше BM25) |

## Приклад

```csharp
var service = new OpenAIService(apiKey, http)
    .WithRag(rag => rag
        .UseHybridSearch(vectorWeight: 0.5f)
        .AddDocument("product-catalog.txt")
        .AddDocument("error-codes.txt")
    );

// "ERR-4012" зіставляється через BM25; семантичний контекст — через вектор
var answer = await service.GetCompletionAsync("How do I fix ERR-4012?");
```
