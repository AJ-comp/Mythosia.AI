# Гібридний пошук

Коди товарів зручно шукати за словами, а питання з іншим формулюванням — за змістом. Вибраний компонент готує лише потрібне представлення: лексичний пошук більше не вимагає попереднього ембеддингу запиту.

## Вбудовані режими

```csharp
// Семантичний пошук (стандартний)
.UseVectorSearch()

// Лексичний пошук без ембеддингу запиту
.UseKeywordSearch()

// Зважений гібридний пошук
.UseHybridSearch(new HybridSearchOptions
{
    VectorWeight = 0.7f,
    CandidateMultiplier = 4,
    RrfK = 60
})
```

`HybridSearchOptions`: `using Mythosia.VectorDb;`

`UseKeywordSearch()` пропускає ембеддинг запиту. Документи досі розбиваються і векторизуються для наявного сховища; це не суто текстове індексування. Відкладена ініціалізація може викликати ембеддинги документів під час першого питання.

## Поєднання лексичних і семантичних результатів

`VectorWeight` задає вагу векторного пошуку (0–1), `1 - VectorWeight` — лексичного. `CandidateMultiplier` керує кандидатами кожної гілки, `RrfK` — згладжуванням рангів у зваженому Reciprocal Rank Fusion. Вони окремі від множника RAG-переранжування. Перевіряйте їх на своїх документах і питаннях.

Суто векторний і лексичний режими зберігають власні оцінки. Налаштовуваний гібрид використовує нормалізований зважений RRF навіть з однією гілкою; вага вектора 0 пропускає ембеддинг запиту. Оцінки не є ймовірностями. `WeightedBlend` змішує оцінки без калібрування; для некаліброваного лексичного пошуку рекомендовано `RerankerOnly`.

```csharp
using Mythosia.AI.Rag;
using Mythosia.VectorDb;

var service = new OpenAIService(apiKey, http)
    .WithRag(rag => rag
        .AddDocument("manual.txt")
        .UseHybridSearch(new HybridSearchOptions
        {
            VectorWeight = 0.7f,
            CandidateMultiplier = 4,
            RrfK = 60
        }));

string answer = await service.GetCompletionAsync("What is the refund policy?");
```

## Підтримка сховищ і сумісність

InMemory, PostgreSQL і Qdrant підтримують новий лексичний пошук та налаштовуваний зважений RRF. Текстові оцінки різні: BM25 в InMemory, налаштований повнотекстовий або триграмний пошук у PostgreSQL, розріджений індекс у Qdrant. Оцінки різних рушіїв не рівнозначні.

Pinecone зберігає нативний гібридний шлях через `UseHybridSearch()` зі стандартними налаштуваннями на сумісному індексі `dotproduct`. Адаптер не підтримує лексичний режим або налаштовуваний зважений RRF з обома гілками. Іншим сховищам потрібні відповідні додаткові інтерфейси. Непідтримувані режими чи опції явно викликають помилку, без прихованого переходу до векторного пошуку чи ігнорування ваг.

Наявні адаптери InMemory, PostgreSQL і Qdrant не встановлюють нейронну модель і не переносять індекси. Розрізнення `C#` та `C++` залежить від аналізатора. Для варіанта PIXIE нижче також потрібно перевірити точний пошук ідентифікаторів.

Див. [режими та підтримку](rag.md#retrieval-modes) і [власні пошукові компоненти](rag-pipeline.md#custom-retriever).

## Порівняння локального нейронного пошуку з PIXIE

Якщо запитання й документ сформульовані по-різному, навчений розріджений пошук може додати пов’язані слова. Необов’язковий пакет `Mythosia.AI.Rag.Search.Pixie` локально кодує документи й запити за допомогою PIXIE та поєднує результати з наявними щільними ембедингами. Для PIXIE не потрібні сервер Python і ключ API; вибрані постачальники щільних ембедингів чи відповідей можуть і далі використовувати зовнішній API.

```csharp
using Mythosia.AI.Rag;
using Mythosia.AI.Rag.Search.Pixie;
using Mythosia.VectorDb;

using var encoder = new PixieSparseEncoder(new PixieOptions());
var searchStore = new PixieInMemoryStore(encoder);
RagStore rag = await RagStore.BuildAsync(builder => builder
    .UseEmbedding(embeddings)
    .UseStore(searchStore)
    .AddDocument("manual.txt")
    .UseHybridSearch(new HybridSearchOptions { VectorWeight = 0.7f }));

RagProcessedQuery result = await rag.QueryAsync("refund policy");
```

З цим сховищем `UseKeywordSearch()` обирає нейронний розріджений пошук: щільний ембединг запиту не створюється, але PIXIE обробляє запитання. Завантаження документів RAG і далі створює щільні ембединги. `UseHybridSearch(...)` поєднує ранги розрідженого скалярного добутку й щільної косинусної подібності налаштованим зваженим RRF.

Попередня версія надає `PixieInMemoryStore` з індексом у пам’яті. Вона не підключає PIXIE до PostgreSQL, Qdrant або Pinecone. Після перезапуску чи зміни моделі/налаштувань перебудуйте індекс. Зберігайте кодувальник до завершення всіх операцій, а потім звільніть його. Наявний пошук залишається типовим: порівняйте ті самі документи й запитання з оціненою релевантністю перед переходом. PIXIE не гарантує точного розрізнення `C#`/`C++` або дотримання умов виключення.
