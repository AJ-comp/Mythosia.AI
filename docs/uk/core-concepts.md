# Основні поняття

На цій сторінці зібрані базові поняття, на які посилається решта документації. З часом тут з'являтимуться нові поняття.

## Що таке раунд?

> [!NOTE]
> **Раунд (Round)** — це одна повна поїздка туди й назад між вашим застосунком і моделлю: застосунок надсилає промпт, модель відповідає, і цей обмін — один раунд. Звичайне повідомлення в чаті — це 1 раунд. Function calling та агенти можуть ланцюжком об'єднувати кілька раундів для одного повідомлення користувача.

### Найпростіший випадок: 1 раунд

У звичайному повідомленні чату вся розмова вміщується в один раунд.

```
застосунок  →  "Скільки буде 2 + 2?"  →  модель
застосунок  ←  "Чотири."                ←  модель
```

`RoundUsage` спрацьовує один раз із токенами цього раунду. `Completion.Usage` спрацьовує наприкінці stream із тим самим підсумком, адже раунд лише один.

### Кілька раундів: function calling

Раунди накопичуються, коли модель не може відповісти сама. Припустімо, користувач запитує *«Яка зараз погода в Києві?»* — у моделі немає доступу до погоди в реальному часі, тож вона має викликати інструмент.

**Раунд 1 — модель вирішує викликати інструмент**

Застосунок надсилає моделі повідомлення користувача разом зі списком зареєстрованих інструментів (наприклад, `GetWeather`). Модель бачить таку розмову:

```
system: Ти — погодний асистент. Ти можеш викликати GetWeather(city).
user:   Яка зараз погода в Києві?
```

Замість фінальної відповіді модель повертає **запит на виклик інструменту**:

```
tool_call: GetWeather(city="Kyiv")
```

Хід моделі завершується, і раунд 1 також. `RoundUsage` спрацьовує з токенами, витраченими в раунді 1. **Фінальної відповіді для користувача ще немає.**

**Між раундами — застосунок виконує функцію**

Цей крок **не** є викликом LLM. Runtime Mythosia.AI викликає вашу зареєстровану реалізацію `GetWeather` і отримує `«15°C, хмарно»`. Токени не витрачаються.

**Раунд 2 — модель пише фінальну відповідь**

Застосунок додає до розмови **function_call моделі з раунду 1 разом із результатом виконання інструменту** і викликає модель **ще раз**. Модель тепер бачить:

```
system:      Ти — погодний асистент. Ти можеш викликати GetWeather(city).
user:        Яка зараз погода в Києві?
assistant:   [викликав GetWeather(city="Kyiv")]
tool_result: 15°C, хмарно
```

Маючи всю потрібну інформацію, модель пише текст:

```
Зараз у Києві 15°C і хмарно.
```

Раунд 2 завершується. `RoundUsage` спрацьовує вдруге — цього разу лише з токенами раунду 2 (вхідних токенів зазвичай більше, ніж у раунді 1, бо розмова стала довшою). Коли stream закривається, `Completion.Usage` спрацьовує один раз із **сумою раундів 1 та 2**.

### Коротко

| Крок | Виклик LLM? | Що відбувається | Подія |
|---|---|---|---|
| Раунд 1 | ✅ | Модель вирішує викликати `GetWeather` | `RoundUsage` (`RoundIndex=1`) |
| Між раундами | ❌ | Застосунок виконує функцію, отримує `«15°C, хмарно»` | `FunctionCall`, `FunctionResult` |
| Раунд 2 | ✅ | Модель бачить результат і пише фінальну відповідь | `RoundUsage` (`RoundIndex=2`, `IsFinalRound=true`) |
| Stream завершено | — | — | `Completion` (Usage = раунд 1 + раунд 2) |

### Більше інструментів — більше раундів

Якщо моделі потрібно ланцюжком зробити кілька викликів інструментів, раунди накопичуються. Для *«Порівняй погоду в Києві та Львові»*:

1. **Раунд 1** — модель викликає `GetWeather("Kyiv")`
2. Застосунок виконує → `«15°C, хмарно»`
3. **Раунд 2** — модель бачить результат і також викликає `GetWeather("Lviv")`
4. Застосунок виконує → `«12°C, сонячно»`
5. **Раунд 3** — модель поєднує обидва результати у фінальну відповідь

Загалом три раунди, і `Completion.Usage` підсумовує всі три. Індикатор контексту в UI має використовувати `RoundUsage.Usage.InputTokens` останнього раунду — у цьому прикладі раунду 3.

Числовий приклад того, як індикатор контексту змінюється від раунду до раунду, див. у розділі [Token Usage — Як змінюється розмір контексту](token-usage.md#how-context-size-changes).
