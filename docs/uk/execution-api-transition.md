# Керування поточними завданнями ШІ через Run

> Ці API потребують `Mythosia.AI` версії 7.1.0 або новішої, що включає `Mythosia.AI.Abstractions` версії 3.1.0 або новішої. Для прикладів RAG потрібен `Mythosia.AI.Rag` версії 7.6.0 або новішої.

## Навіщо керувати завданням під час виконання?

Підготовка звіту може вимагати кількох пошуків у документах, звернень до API та етапів написання. Поки робота триває, користувач може захотіти побачити перебіг, зупинити її або додати вимогу, наприклад: «Використовуйте лише дані за цей рік». Застосунку потрібен спосіб пов’язати ці дії з уже запущеним завданням.

Run надає об’єкт завдання, який можна зберегти в застосунку. Наприклад, екран чату може показувати текст у міру надходження та виклики інструментів, пов’язувати кнопку «Стоп» зі скасуванням і надсилати додаткові вказівки, якщо модель їх підтримує. Усі ці дії стосуються одного виконання.

| Що потрібно застосунку | Що використати |
| --- | --- |
| Отримати готову відповідь без керування поточною роботою | Продовжуйте використовувати `GetCompletionAsync`, зокрема типізовані та RAG-перевантаження. |
| Показувати текст у міру надходження та отримати його повністю після завершення | Запустіть завдання з `onText`, потім очікуйте `run.Result`. |
| Показувати роботу інструментів або асинхронно обробляти вивід | Читайте події з `run.StreamAsync()`. |
| Дозволити користувачу зупинити роботу | Викличте `run.Cancel()` у збереженого об’єкта. |
| Додати вимогу до завершення завдання | Перевірте `run.CanSteer`, а потім викличте `run.SteerAsync(...)` для підтримуваної моделі. |

`StartRunAsync` запускає одне завдання моделі й повертає `AIRun`. Воно продовжується незалежно від того, чи читаєте ви вивід. Один об’єкт використовується для потокового виводу, накопиченого результату, скасування та підтримуваних додаткових вказівок. `GetCompletionAsync`, зокрема типізовані та RAG-перевантаження, залишається публічним зручним API для отримання готового результату.

## Показ тексту через зворотний виклик

У чаті або консолі показ перших фрагментів одразу після надходження дає користувачу змогу стежити за довгою відповіддю, поки вона ще формується.

```csharp
await using var run = await service.WithMaxRounds(10).StartRunAsync(
    "Прочитайте документи й підготуйте звіт.",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);

string answer = await run.Result;
```

`onText` — необов’язковий `Action<string>`, який реєструється до початку роботи. Він отримує текст послідовно, але не виконує інструменти. Якщо потрібен лише результат, не передавайте його. Виняток у зворотному виклику скасовує завдання й призводить до помилки в `Result`. Не передавайте до `onText` лямбду `async`: вона перетвориться на `async void`, тож завдання не зможе очікувати її завершення або обробити її помилки. Для асинхронного передавання використовуйте потік подій. Зворотні виклики не перемикаються на потік UI автоматично.

`Result` об’єднує текстові події завдання, включно з проміжним текстом між викликами інструментів і текстом, виданим до додаткової вказівки. Це не другий запит до моделі й не заново переписана відповідь. Якщо потрібна попередня семантика завершеної відповіді, можна й надалі використовувати `GetCompletionAsync`.

## Читання подій тексту, інструментів і використання токенів

Коли завдання шукає документи або звертається до бізнес-API, самого тексту може бути замало, щоб пояснити очікування. Типізовані події дають змогу показувати роботу інструментів поряд із відповіддю та обліковувати використання токенів, якщо провайдер передає ці відомості.

```csharp
await using var run = await service.StartRunAsync(
    "Знайдіть документи й поясніть результат.",
    cancellationToken: cancellationToken);

await foreach (var item in run.StreamAsync())
{
    switch (item.Type)
    {
        case StreamingContentType.Text:
            Console.Write(item.Content);
            break;
        case StreamingContentType.FunctionCall:
            Console.WriteLine("\n[Виклик інструмента]");
            break;
        case StreamingContentType.FunctionResult:
            Console.WriteLine("\n[Отримано результат інструмента]");
            break;
        case StreamingContentType.Completion when item.Usage != null:
            Console.WriteLine($"\n[Усього токенів: {item.Usage.TotalTokens}]");
            break;
    }
}

string answer = await run.Result;
```

`run.StreamAsync()` приймає необов’язковий токен скасування спостереження, але не промпт. Він спостерігає за завданням, уже запущеним через `StartRunAsync`. Зареєстровані обробники функцій виконує бібліотека: не запускайте інструмент повторно після отримання події для відображення. Параметри показу тексту не вимикають зареєстровані інструменти завдання.

Зворотний виклик під час запуску та `run.StreamAsync()` можуть одночасно спостерігати за тим самим завданням; потік подій підтримує одного читача. Наприклад, показуйте текст у `onText`, а в потоці обробляйте лише події інструментів, щоб не виводити текст двічі. Буфер зберігає до 1 024 непрочитаних подій, навіть якщо підключено зворотний виклик. Пізній читач отримує події від початку, доки вони вміщуються в буфер. Якщо ліміт перевищено, читання потоку явно завершується помилкою, але зворотний виклик, виконання й `Result` продовжуються. Не сприймайте потік як необмежений журнал для повторного відтворення. Очікування `Result` не вимагає вичитування потоку подій.

Run із пошуком в інтернеті чи документах також може показувати джерела відповіді. Приклади `WithWebSearch`, `WithFileSearch`, `run.Citations` і подій джерел наведено в [посібнику з міркування та пошуку](reasoning-and-search.md).

## Асинхронна обробка виводу

Очікуйте асинхронну операцію всередині циклу читання замість передавання асинхронного зворотного виклику в `onText`:

```csharp
using var writer = new StreamWriter("report.txt");
await using var run = await service.StartRunAsync(
    "Підготуйте звіт.", cancellationToken: cancellationToken);

await foreach (var item in run.StreamAsync())
{
    if (item.Type == StreamingContentType.Text && item.Content is string text)
        await writer.WriteAsync(text);
}
string answer = await run.Result;
```

## Скасування та звільнення ресурсів

- Вихід з `await foreach` або скасування токена, переданого лише в `run.StreamAsync(token)`, зупиняє спостереження; завдання продовжує виконуватися.
- `run.Cancel()`, токен, переданий у `StartRunAsync`, і звільнення активного об’єкта Run скасовують виконання.
- `await using` гарантує, що `DisposeAsync()` дочекається завершення виробника подій та очищення провайдера. Інструментам без підтримки скасування може знадобитися час для завершення; звільнення ресурсів не скасовує вже здійснених дій.
- Один сервіс допускає одне активне завдання `StartRunAsync`. Спроба одночасного запуску другого відхиляється. Для незалежних паралельних завдань використовуйте окремі сервіси; під час виконання не змішуйте старі виклики й не змінюйте налаштувань сервісу.

До фонового виконання завдання фіксує вхідні дані та політику окремого запиту, що очікує застосування. Вбудований текстовий, графічний та аудіовміст, а також масиви медіабайтів копіюються. Користувацькі підкласи `MessageContent` зберігають свою ідентичність і не повинні змінюватися до завершення завдання.

Зафіксоване значення `FunctionCallingPolicy.TimeoutSeconds` задає один спільний строк для підготовки завдання та всіх раундів моделі й інструментів. Його сплив спричиняє `AIServiceException`; скасування користувачем переводить результат у скасований стан. Очищення й надалі чекає на обробники, що не підтримують скасування.

## Додаткові вказівки під час роботи

Припустімо, користувач почав складати план проєкту, а потім зрозумів, що потрібно вкластися у два тижні. Steering дозволяє надіслати цю вимогу, поки модель іще працює. Це корисно для виправлень і змін обсягу тривалого завдання. Якщо після завершення виникло нове запитання, почніть наступний запит звичайним способом.

```csharp
await using var run = await service.StartRunAsync(
    "Складіть план проєкту.",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);

// Викликайте з обробника додаткових вказівок у UI, поки завдання виконується.
async Task SendUpdateAsync(string instruction)
{
    if (!run.CanSteer)
        throw new NotSupportedException("Це завдання не підтримує додаткових вказівок.");

    await run.SteerAsync(instruction, cancellationToken);
}

string answer = await run.Result;
```

Додаткові вказівки під час виконання підтримує GPT-6 Astra через WebSocket-з’єднання Responses API. Інші провайдери та непідтримувані моделі можуть виконувати звичайні завдання Run, але `CanSteer` у них дорівнює false, а спроба steering повідомляє про відсутність підтримки замість прихованого створення наступного звичайного запиту. `CanSteer` не гарантує, що завдання залишатиметься активним на момент наступного виклику.

Завдання Astra відкривають окремий сокет. Переданий `HttpClient` і його обробники повідомлень продовжують обслуговувати HTTP-запити та не перехоплюють цей сокет. Для власного транспорту можна перевизначити `OpenAIService.ConnectRunWebSocketAsync`.

Успішний `SteerAsync` означає, що сервер прийняв вхідні дані до черги, а не що модель уже врахувала їх. Продовжуйте спостерігати за тим самим завданням або очікувати результат подальшої відповіді. Уже переданий текст і здійснені дії не відкочуються; запущені інструменти не скасовуються лише через надсилання нової вказівки. Бібліотека обробляє продовження й зіставлення результатів інструментів у тому самому з’єднанні. Див. [настанову OpenAI щодо додаткових вказівок](https://developers.openai.com/api/docs/guides/steering) та [режим WebSocket](https://developers.openai.com/api/docs/guides/websocket-mode). Не можна вважати, що черга вказівок поточного з’єднання пережила розрив: не надсилайте прийняту вказівку повторно без перевірки.

## Завдання з інструментами та старі агентні методи

Запитання на кшталт «Перевірте умови повернення і статус цього замовлення» потребують кількох джерел. Зареєструйте інструменти пошуку документів і перевірки замовлення, щоб модель могла вибрати потрібні виклики. Ліміт раундів обмежує кількість подальших запитів інструментів: завдання має завершитися або повідомити про помилку.

Звичайний виклик функцій уже підтримує повторювані раунди моделі й інструментів. `StartRunAsync` використовує ті самі зареєстровані функції та політики виконання; окремий агентний режим, планувальник чи перемикач `WithAgentic` не потрібен.

`RunAgentAsync` і `RunAgentStreamAsync` залишаються доступними, але тепер видають попередження `[Obsolete]`. На час переходу зберігаються попередні сигнатури, типове значення `maxSteps = 10` і попередні помилки перевищення ліміту. Нові місця виклику оформлюйте так:

```csharp
await using var run = await service.WithMaxRounds(10).StartRunAsync(
    "Знайдіть політику, перевірте замовлення й поясніть результат.",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);
string answer = await run.Result;
```

Звичайне типове значення `FunctionCallingPolicy.MaxRounds` дорівнює 20, тому для збереження попереднього агентного ліміту вкажіть 10. `WithMaxRounds` задає перевизначення політики на один запит і не змінює `DefaultPolicy`. Налаштуйте його до запуску. Старі агентні методи натомість копіюють поточну типову політику й застосовують свій аргумент `maxSteps`. Новий Run використовує спільний контракт помилок виконання й не обіцяє попереднього перетворення на `AgentMaxStepsExceededException` із `PartialResponse`. Якщо це важливо для застосунку, зберігайте старий виклик до перенесення обробки винятків.

## RAG, MCP та межі пакетів

- `RagEnabledService.StartRunAsync` приймає рядок або `Message`, `onText`, `RagQueryOptions` для окремого запиту, `streamOptions` і скасування. Пошук відбувається до запуску внутрішнього завдання; зображення, аудіо й метадані зберігаються, початковий ввід залишається в історії, а доповнений текст передається через контекст запиту. Доповнення прив’язане до початкового запитання користувача, тому наступні результати інструментів і додаткові вказівки не замінюються початковим RAG-промптом. Steering передає уточнення моделі, але не запускає RAG-пошук повторно автоматично.
- `WithAgenticRag` і далі реєструє інструмент пошуку. Використовуйте його через `StartRunAsync`, і модель зможе запитувати подальші пошуки за потреби. Реєстрація MCP через `WithMcpServerAsync` також не змінюється. Спільні MCP-з’єднання звільняйте окремо від завдань, що їх використовують.
- `IAIRunService` — необов’язкова можливість у `Mythosia.AI.Abstractions`; до `IAIService` не додаються обов’язкові члени. Щоб підтримувати запуск RAG Run, користувацький сервіс має реалізувати `IAIRunService`. Непідтримувані сервіси відхиляються до початку індексації RAG.
- RAG зберігає залежність від Abstractions, а провайдери в окремих пакетах — публічні перевизначення методів генерації та доступні точки розширення. Цей перехід не оголошує застарілими API векторних сховищ, завантажувачів документів чи адміністрування серверів.

## Сумісність і наступна мажорна версія

| API | Поточний стан |
| --- | --- |
| `GetCompletionAsync` / `GetCompletionAsync<T>` | Публічні й підтримувані, включно з варіантами інтерфейсу, провайдерів і RAG. |
| `StartRunAsync` / `AIRun` | Спільний API виконання та керування. |
| `RunAgentAsync` / `RunAgentStreamAsync` | Попередження про застарілість; попередня поведінка збережена для сумісності. |
| `service.StreamAsync` і RAG `StreamAsync`, що приймають ввід | Доступні в цій мінорній версії; заплановано вилучення з публічного API в наступній мажорній. |
| `run.StreamAsync()` | Спостереження за виводом наявного завдання без нового вводу. |
| `BeginStream(...).As<T>()` / `StructuredStreamRun<T>` | Попередній API типізованого потокового виводу збережений; його вихідний `Stream()` не є старим методом запуску запиту на сервісі. |

Наступна мажорна версія змінить публічні точки входу потокових запитів, зберігши виконання й потрібні точки розширення провайдерів. Зміна public-методу на private або protected усе одно порушує сумісність вихідного та бінарного коду, навіть якщо тіло методу збережене. Ланцюжки повідомлень, разові виклики, підсумовування, переписування запитів і переранжування не стають застарілими лише тому, що використовують наявні методи виконання.
