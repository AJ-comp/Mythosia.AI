# Переранжування та налаштування пошуку

> 📍 **Пайплайн запитання-відповіді:** [Переписування запитів](rag-query-rewriting.md) → Ембеддинг → Фільтрація → [Пошук](rag-hybrid-search.md) → **`Переранжування`** → Побудова контексту

## Навіщо потрібне переранжування

Векторний пошук повертає кандидатів, відсортованих за близькістю ембеддингів, але ця близькість — лише **наближення**. Чанк з оцінкою 0.82 може бути насправді релевантнішим за чанк з оцінкою 0.85 — ембеддинг просто не зміг їх розрізнити.

**Переранжування** бере початковий список кандидатів і оцінює кожен чанк відносно вихідного запиту потужнішою моделлю, що дає значно точніше ранжування за релевантністю. Це особливо цінно, коли:

- У корпусі багато схожих чанків (наприклад, записи FAQ)
- Топ-результати векторного пошуку здаються «близькими, але не зовсім тими»
- Потрібна висока точність відповідей для критично важливих сценаріїв

## Варіанти переранжування

### LLM Reranker

Використовує ваш AI-сервіс для оцінки результатів. Ефективний, але додає затримку:

```csharp
.WithRag(rag => rag
    .WithReranker(new LlmReranker(aiService))
    .AddDocument("corpus.txt")
)
```

### Cohere Reranker

Звертається до Cohere Rerank API — швидкий і точний:

```csharp
.WithRag(rag => rag
    .WithReranker(new CohereReranker(cohereApiKey))
    .AddDocument("corpus.txt")
)
```

### vLLM Reranker

Використовує локально розгорнутий vLLM-ендпоінт переранжування:

```csharp
.WithRag(rag => rag
    .WithReranker(new VllmReranker("http://localhost:8000"))
    .AddDocument("corpus.txt")
)
```

## Параметри витягування

Керування кількістю кандидатів і фільтрацією перед фінальним відбором:

```csharp
.WithRag(rag => rag
    .WithTopK(5)                   // Підсумкова кількість чанків
    .WithRetrievalMultiplier(3)    // Витягти topK × 3 кандидатів (для переранжування)
    .WithMinScore(0.6)             // Мінімальна оцінка схожості
    .AddDocument("corpus.txt")
)
```

- **`TopK`** — скільки чанків потрапить до контексту LLM
- **`RetrievalMultiplier`** — розширює воронку, щоб переранжування мало більше матеріалу для роботи. Множник 3 означає, що витягуються 15 кандидатів, з яких після переранжування залишаються найкращі 5.
- **`MinScore`** — відсіює все нижче за цей поріг схожості, навіть якщо результатів буде менше за `TopK`

## Режим фінального відбору

При використанні переранжування можна обрати спосіб розрахунку фінальної оцінки:

```csharp
using Mythosia.AI.Rag;

// За замовчуванням: враховуються лише оцінки переранжування
.WithFinalSelectionPolicy(RagFinalSelectionMode.RerankerOnly)

// Змішування оцінок пошуку та переранжування
.WithFinalSelectionPolicy(RagFinalSelectionMode.WeightedBlend, retrievalWeight: 0.65)  // 65% пошук, 35% переранжування
```

**`RerankerOnly`** — безпечний варіант за замовчуванням: оцінка переранжування повністю замінює початкову оцінку пошуку.

**`WeightedBlend`** — зберігає вихідний сигнал пошуку, доповнюючи його оцінкою переранжування. Корисний, коли ембеддинги вже високої якості й переранжування має виступати в ролі арбітра, а не повної заміни.
