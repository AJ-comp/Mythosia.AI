# Ембеддинг

> 📍 **Пайплайн запитання-відповіді:** [Переписування запитів](rag-query-rewriting.md) → [Фільтрація](rag-filtering.md) → **`Ембеддинг (за потреби)`** → [Пошук](rag-hybrid-search.md) → [Переранжування](rag-reranking.md) → [Побудова контексту](rag-context-build.md)

Етап запиту `Embedding` залежить від компонента; лексичний пошук його не повідомляє. Власний компонент може повідомляти етапи через `request.ProgressAsync`. Ембеддинги документів не змінюються.

## Що таке ембеддинг?

Ембеддинг — це процес перетворення тексту в **числові вектори** (масиви чисел), що відображають зміст. У цьому векторному просторі **тексти зі схожим значенням опиняються поруч**.

Уявіть міста на карті: географічно близькі міста розташовані поруч. Так само фрази «Як скасувати підписку?» та «Хочу припинити членство» породжують близькі вектори — попри різні слова.

У RAG-пайплайні ембеддинг використовується двічі:

1. **Індексація документів** — кожен чанк векторизується та зберігається
2. **На етапі запиту** — питання користувача векторизується для пошуку за схожістю

Ця сторінка присвячена ембеддингу запиту (крок 2).

## Вбудовані провайдери

Вибирайте провайдера ембедингів за мовою документів, середовищем розміщення та потребами пошуку.

### Perplexity

Стандартні ембеддинги обробляють уривки незалежно й реалізують `IEmbeddingProvider` для наявного RAG-побудовника. Контекстні зберігають порядок сусідніх фрагментів і групи документів. Окремий API запобігає об'єднанню непов'язаних документів у плоский ввід.

[Perplexity Agent API, пошук та ембеддинги](perplexity.md).

### OpenAI

```csharp
var embedder = new OpenAIEmbeddingProvider(
    apiKey: "sk-...",
    httpClient: new HttpClient(),
    model: "text-embedding-3-small",
    dimensions: 1536
);
```

Скорочений запис через Builder:

```csharp
.WithRag(rag => rag
    .UseOpenAIEmbedding(apiKey, model: "text-embedding-3-small", dimensions: 1536)
    .AddDocument("docs.txt")
)
```

<a id="openai-dimensions"></a>

`text-embedding-ada-002` має фіксовану розмірність **1536**. Провайдер не передає непідтримуване поле `dimensions` в одиничних і пакетних запитах; налаштування іншої розмірності спричиняє `ArgumentOutOfRangeException` до виклику API. Для `text-embedding-3-small` і `text-embedding-3-large` запити й надалі містять налаштоване значення `dimensions`.

### Ollama (локально)

Запуск ембеддингів локально через [Ollama](https://ollama.com/):

```csharp
var embedder = new OllamaEmbeddingProvider(
    httpClient: new HttpClient(),
    model: "qwen3-embedding:4b",
    dimensions: 1024,
    baseUrl: "http://localhost:11434"
);
```

<a id="ollama-dimensions"></a>

Вектори документів і запитів мають використовувати однакові модель і розмірність. `OllamaEmbeddingProvider` передає налаштоване значення `dimensions` до `/api/embed` і перевіряє довжину кожного отриманого вектора. Типово провайдер і далі використовує `qwen3-embedding:4b` та **запитує 1024 виміри**; власна розмірність моделі — 2560. Сервер Ollama та вибрана модель мають підтримувати запитану розмірність. Непідтримуваний запит або відповідь, що ігнорує налаштування, спричиняє помилку, а не приховану зміну `Dimensions` чи локальну зміну довжини векторів.

Якщо змінюєте модель або розмірність, заново створіть ембеддинги документів із тими самими налаштуваннями, що й для запитів, і відповідно налаштуйте векторне сховище. Наявні вектори автоматично не перетворюються.

### vLLM (власний хостинг)

Для команд із власним сервером [vLLM](https://docs.vllm.ai/):

```csharp
var embedder = new VllmEmbeddingProvider(
    httpClient: new HttpClient(),
    model: "Qwen/Qwen3-Embedding-0.6B",
    dimensions: 1024,
    baseUrl: "http://localhost:8002"
);
```

### Local (без API)

Легкий провайдер на основі хешування ознак, без ключа API та зовнішніх сервісів. Проте якість ембедингів значно поступається нейромережевим моделям, тому **не рекомендується для робочого використання**.

```csharp
.WithRag(rag => rag
    .UseLocalEmbedding(dimensions: 1024)
    .AddDocument("docs.txt")
)
```

> **Порада:** Використовуйте натомість `OpenAIEmbeddingProvider` з моделлю `text-embedding-3-small`. Вартість майже нульова, а результати значно кращі.

## Пакетна обробка

При індексації чанки обробляються пакетами:

```csharp
var options = pipeline.Options.Clone();
options.EmbeddingBatchSize = 100; // за замовчуванням: 100 чанків за виклик
pipeline.Options = options;
```

`EmbeddingBatchSize` має бути додатним. Конвеєр перевіряє та фіксує значення на початку кожного виклику індексації документа, до ембеддингу або заміни записів. Це запобігає циклам порожніх пакетів і пропуску чанків у разі зміни налаштування під час асинхронного очікування. Наступні виклики можуть використовувати нове значення.

<a id="embedding-validation"></a>

## Відповідність кожного вектора своєму фрагменту

Успішна HTTP-відповідь може містити пропущені вектори або неправильний порядок. Тоді текст буде пов’язаний зі змістом іншого фрагмента. Користувацький `IEmbeddingProvider` має повертати рівно один ненульовий `float[]` на кожен вхід у початковому порядку та задавати додатне значення `Dimensions`. Довжина кожного вектора має дорівнювати цій розмірності, а всі значення мають бути скінченними, без `NaN` та нескінченності.

Під час індексації документів конвеєр відхиляє некоректні розмірності, кількість відповідей чи вектори з `InvalidOperationException` до збереження або `onDocumentEmbedded`. Кожен прийнятий вектор копіюється до запиту наступного пакета, тому повторне використання буфера провайдера згодом не змінить попередні фрагменти. Повернуті дані мають залишатися стабільними під час читання; одночасна зміна під час перевірки або копіювання не підтримується. Помилка перевірки зберігає попередні записи документа.

`OpenAIEmbeddingProvider` вимагає коректного унікального `index` для кожного елемента відповіді та відновлює початковий порядок. `VllmEmbeddingProvider` застосовує те саме правило за наявності індексів; для сумісності також дозволені відповіді, де `index` відсутній у всіх елементах, зі збереженням порядку відповіді. Частково відсутні, дубльовані або позадіапазонні індекси відхиляються. Користувацький провайдер чи відповідь без індексів відповідають за порядок; перевірка структури не перевіряє зміст вектора.

<a id="query-embedding-validation"></a>

## Захищати вектор запитання перед пошуком

Повторне використання буфера не має змінювати запитання під час очікування сповіщень чи пошуку. Вбудований щільний пошук, зокрема адаптер `IRetrievalStrategy`, вимагає додатного `Dimensions`, ненульового вектора саме такої довжини й скінченних значень. Некоректний результат спричиняє `InvalidOperationException` до пошуку. Прийнятий вектор копіюється одразу після повернення, до наступних сповіщень і пошуку. Провайдер має зберігати дані сталими під час читання; власний `IRagRetriever` відповідає за підготовку та перевірку самостійно.

`OllamaEmbeddingProvider` також перевіряє структуру, точну кількість векторів, розмірність і скінченність значень за прямих одиночних та пакетних викликів. Некоректний JSON або вектори спричиняють `InvalidOperationException` замість неповного результату. Переданий `HttpClient` залишається власністю викликача; звільнення HTTP-запитів і відповідей не звільняє клієнт.

## Власний провайдер

Реалізуйте `IEmbeddingProvider`:

```csharp
public class MyEmbeddingProvider : IEmbeddingProvider
{
    public int Dimensions => 768;

    public async Task<float[]> GetEmbeddingAsync(
        string text, CancellationToken cancellationToken = default)
    {
        // Виклик вашого API
    }

    public async Task<IReadOnlyList<float[]>> GetEmbeddingsAsync(
        IEnumerable<string> texts, CancellationToken cancellationToken = default)
    {
        // Пакетний виклик
    }
}
```

## Внутрішній механізм

```
Питання користувача (string) → EmbeddingProvider.GetEmbeddingAsync() → Вектор запиту (float[])
```
