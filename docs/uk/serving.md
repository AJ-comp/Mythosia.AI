# Керування запущеними серверами моделей

Інтерфейсу вибору моделей або панелі експлуатації перед надсиланням запиту потрібні стан сервера, доступні моделі та стан їх завантаження. Пакети Serving уніфікують ці перевірки для Ollama, llama.cpp і vLLM, залишаючи специфічні операції явними.

Використовуйте їх для наповнення списку вибору моделей, відображення доступності сервера, керування перебуванням моделей у пам’яті, якщо середовище це підтримує, або читання метрик рушія. Після зміни середовища виконання спільний код перевірок застосунку може залишитися незмінним.

Ці клієнти підключаються до наявного HTTP-сервера. Установлення чи розміщення рушія, оренда GPU, чат і створення ембеддингів належать до окремих компонентів. Чат і далі працює через відповідний сервіс ШІ, наприклад `QwenService` для vLLM; провайдери ембеддингів RAG залишаються окремими. Виявлення не завантажує моделі автоматично. SGLang не реалізовано.

## Отримання відомостей без зміни стану

Встановіть конкретний пакет свого середовища. Приклад використовує Ollama; для інших серверів виберіть `VllmServer` або `LlamaCppServer` із відповідного простору імен. Виявлення виконує лише запити читання, без команд завантаження в пам’ять, генерації чи скачування.

```bash
dotnet add package Mythosia.AI.Serving.Ollama --version 1.0.0
```

```csharp
using System;
using System.Net.Http;
using System.Threading;
using Mythosia.AI.Serving;
using Mythosia.AI.Serving.Ollama;

using var http = new HttpClient { Timeout = TimeSpan.FromMinutes(10) };
using var cancellation = new CancellationTokenSource();
IModelServer server = new OllamaServer("http://localhost:11434", http,
    apiKey: Environment.GetEnvironmentVariable("MODEL_SERVER_API_KEY"));

var health = await server.GetHealthAsync(cancellation.Token);
var info = await server.GetInfoAsync(cancellation.Token);
var capabilities = await server.GetCapabilitiesAsync(cancellation.Token);
var models = await server.GetModelsAsync(cancellation.Token);

foreach (var model in models)
    Console.WriteLine($"{model.Id}: {model.InstallationState} / {model.LoadState}");
```

Кінцева точка — корінь сервера, за потреби з префіксом шляху зворотного проксі. Необов’язковий ключ API передається в кожному запиті як облікові дані Bearer. Клієнт не змінює `HttpClient.DefaultRequestHeaders` і не звільняє переданий `HttpClient`; повторно використовуйте та звільняйте його відповідно до життєвого циклу застосунку. У цьому прикладі Ollama тайм-аут також охоплює потокове читання тіла відповіді, тому передбачте достатньо часу для скачування моделі.

## Спільні й додаткові контракти

| Контракт | Призначення |
| --- | --- |
| `IModelServer` | Інформація, стан, моделі та спостережені можливості сервера. |
| `IModelLifecycle` | Явні команди завантаження в пам’ять і вивантаження; додатково. |
| `IModelDownloader` | Явне скачування з прогресом; додатково. |
| `IModelMetricsProvider` | Виміри метрик зі збереженням міток; додатково. |

Реалізований інтерфейс означає наявність операції в клієнті; `ServingCapabilities` повідомляє підтверджені можливості підключеної кінцевої точки. `Supported` не гарантує дозволів або успіху для кожної моделі. `Unsupported` означає недоступність у спостереженому режимі чи endpoint. `Unknown` означає брак доказів, зокрема через помилки автентифікації або з’єднання; це не відсутність підтримки.

`InstallationState` і `LoadState` описують різні спостереження. `Unknown` не означає відсутність моделі чи її вивантаження. Невідомі `SizeBytes`, `MemoryBytes` і `ContextLength` залишаються `null`, а не нулем. Справність API керування не доводить готовності конкретної моделі до інференсу.

## Відмінності середовищ виконання

| Операція | Ollama | llama.cpp, одна модель | llama.cpp Router | vLLM |
| --- | --- | --- | --- | --- |
| Інформація, стан і перелік моделей | Так | Так | Так | Так |
| Явне завантаження в пам’ять / вивантаження | Так, за допомогою порожніх запитів генерації | Не підтримується | Так, після підтвердження режиму Router | Не підтримується цим клієнтом |
| Скачування моделі | Так, із потоковим прогресом | Не підтримується | Явна операція; потрібні кінцева точка скачування та події SSE | Не підтримується цим клієнтом |
| Метрики | Не реалізовано | Метрики сервера, якщо ввімкнено | Спеціалізоване перевантаження для моделі; модель уже має бути завантажена | Метрики сервера, якщо доступні |

Таблиця описує операції клієнтів і не обіцяє їх підтримки для кожної версії сервера, набору дозволів чи моделі. Перевіряйте можливості підключеної кінцевої точки й обробляйте помилки операцій.

**Ollama:** `/api/tags` повертає зареєстровані моделі, `/api/ps` — запущені. Віддалена модель може бути зареєстрована без локальних ваг; без локального процесу стан завантаження залишається невідомим. Попереднє завантаження використовує порожній `/api/generate` і стандартний keep-alive сервера. Моделі лише для ембеддингів не перенаправляються на інший API. Вивантаження застосовує `keep_alive: 0`, не видаляючи файлів. Метрики не реалізовано.

**llama.cpp:** перед командами життєвого циклу чи скачування `/props` має явно підтвердити режим маршрутизатора. Режим однієї моделі не підтримує цих команд і зберігає спостережений стан сну. Скачування маршрутизатора спочатку підписується на `/models/sse`, потім надсилає `POST /models` і вважається успішним лише за подією `download_finished` цільової моделі. Сама доступність SSE залишає можливість скачування невідомою. Загальносерверні метрики стосуються режиму однієї моделі; маршрутизатор потребує конкретного перевантаження `GetMetricsAsync(modelId, token)` із `autoload=false`, щоб перевірка не завантажувала модель.

**vLLM:** зберігаються псевдоніми та необов’язкове поле `root`, але спільні стани встановлення й завантаження залишаються невідомими. Моделі й метрики перевіряються за фактичними відповідями; життєвий цикл і скачування не підтримуються. Наявні методи й DTO `VllmServer` залишаються в конкретному клієнті; спільні методи стану, моделей і метрик доступні через явно реалізовані інтерфейси.

## Явне виконання операції керування

Скачування та зміни перебування моделі в пам’яті споживають мережевий трафік, дисковий простір або пам’ять пристрою. Виконуйте їх, коли цього потребує застосунок. Продовження прикладу Ollama нижче скачує невелику модель і ненадовго завантажує її, щоб перевірити стан. Використовуйте точні ідентифікатори моделей сервера, зокрема тег Ollama або тег квантування llama.cpp.

```csharp
if (server is IModelDownloader downloader &&
    capabilities.ModelDownloading == ServingFeatureSupport.Supported)
{
    var progress = new Progress<ModelDownloadProgress>(p =>
        Console.WriteLine($"{p.ModelId}: {p.Stage} {p.CompletedBytes}/{p.TotalBytes}"));
    await downloader.DownloadModelAsync("qwen2.5:0.5b", progress, cancellation.Token);
}

if (server is IModelLifecycle lifecycle &&
    capabilities.ModelLoading == ServingFeatureSupport.Supported &&
    capabilities.ModelUnloading == ServingFeatureSupport.Supported)
{
    try
    {
        await lifecycle.LoadModelAsync("qwen2.5:0.5b", cancellation.Token);
        var afterLoad = await server.GetModelsAsync(cancellation.Token);
        foreach (var model in afterLoad)
            Console.WriteLine($"{model.Id}: {model.LoadState}");
    }
    finally
    {
        using var cleanup = new CancellationTokenSource(TimeSpan.FromSeconds(30));
        await lifecycle.UnloadModelAsync("qwen2.5:0.5b", cleanup.Token);
    }
}
```

У прикладі використовується окрема тестова модель, яку потім вивантажують. Робочий застосунок сам визначає, коли звільняти модель; не вивантажуйте модель, яку ще використовують інші запити. Очищення має власний термін очікування й може завершитися помилкою, якщо сервер недоступний.

Прогрес стосується окремого артефакту або етапу. Відсутні лічильники байтів — не нуль і не відсоток усієї моделі. Успішний виклик завантаження підтверджує команду, а не готовність моделі чи безстрокове перебування в пам’яті; якщо готовність важлива, спостерігайте за `LoadState` з обмеженим часом очікування. Протокол скачування Router у llama.cpp та обмеження версій описані в посібнику конкретного пакета. Явно запитану операцію можна спробувати виконати за підтримки `Unknown`, попередньо перевіривши конфігурацію сервера; саме виявлення можливостей ніколи її не запускає.

## Скасування та помилки

Передавайте токен скасування запитам і командам. Скасування припиняє HTTP-роботу й очікування цього клієнта, але не гарантує віддаленого скасування, відкату чи видалення скачаних шарів. Налаштуйте переданий `HttpClient` відповідно до тривалості операції; клієнти не перебирають його у власність.

Зберігайте мітки метрик під час порівняння моделей або рушіїв. Відсутня метрика — не нуль; значення можуть містити `NaN` або нескінченність. Спільний тип помилки — `ServingException`; спільні помилки керування не містять сирих тіл відповідей чи облікових даних. Наявні виклики vLLM зберігають попередні подробиці помилок.

`GetHealthAsync` подає збої кінцевої точки як стани працездатності, але й далі передає скасування від коду, що його викликав. Інші операції можуть викидати `ServingException`, а завідомо непідтримуваний режим llama.cpp — `NotSupportedException`. Ні тайм-аут, ні невдалий запит не доводять, що віддалену дію відкочено. Метод скачування завершується успішно лише після повідомлення середовища про завершення: кінцевого успіху з подальшим EOF для Ollama або відповідної події `download_finished` для llama.cpp Router.

## Що перевірено

Офлайн-тести охоплюють контрольований успіх, некоректні відповіді, помилки й скасування. Окремі перевірки на реальних серверах виконувалися з однією NVIDIA A40, невеликими загальнодоступними моделями Qwen і такими збірками рушіїв:

| Середовище виконання | Перевірена модель | Перевірені операції керування |
| --- | --- | --- |
| Ollama 0.34.4 | `qwen2.5:0.5b` | Виявлення, скачування без локальної копії, завантаження/вивантаження, помилки відсутньої моделі без чутливих даних, попереднє скасування та скасування після часткового прогресу скачування. |
| llama.cpp b11146, Router | `Qwen/Qwen2.5-0.5B-Instruct-GGUF:Q4_K_M` | Виявлення, події скачування, завантаження/вивантаження, метрики моделі без автозавантаження, помилки та скасування скачування. |
| llama.cpp b11146, одна модель | Та сама модель GGUF | Виявлення, метрики сервера, скасування та явне відхилення команд життєвого циклу Router. |
| vLLM 0.30.0 | `Qwen/Qwen2.5-0.5B-Instruct` | Виявлення, метрики сервера та попереднє скасування. |

Короткі нативні HTTP-запити інференсу також повернули згенерований текст у всіх чотирьох конфігураціях. Ці запити підтверджують роботу рушіїв, але не чат-адаптери сервісів ШІ, якість моделей, пропускну здатність чи сумісність з усіма збірками рушіїв. Наведені профілі — перевірені конфігурації, а не мінімальні підтримувані версії. Для перевірок скасування скачування використовувалися окремі більші тестові моделі; віддалений відкат не стверджувався. Перше скачування Ollama завершилося помилкою; повторна спроба й нове скачування після видалення моделі пройшли, але точну причину першого збою не встановлено.

Скористайтеся [посібником із перевірки на реальному сервері з явним увімкненням](https://github.com/AJ-comp/Mythosia.AI/blob/main/tests/Mythosia.AI.Serving.Live/README.md), щоб перевірити розгорнуту кінцеву точку. Він розрізняє включений до репозиторію засіб перевірки керування та додаткові проби інференсу й скасування, використані під час перевірки. Докладні звіти про виконання залишаються поза опублікованою документацією.
