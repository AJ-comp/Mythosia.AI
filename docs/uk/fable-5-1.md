# Спостерігайте за тривалими завданнями Claude Fable 5.1

[Claude Opus 5.5](providers.md#claude-opus-55) доступний із Mythosia.AI 8.1.0 / Abstractions 4.1.0: мислення завжди активне, типове зусилля medium, відображення приховане. Читабельний прогрес треба запитати явно; типові значення й прив’язка до моделі відрізняються від Fable 5.1.

> Налаштування Fable 5.1 потребують `Mythosia.AI` 8.0.0 і `Mythosia.AI.Abstractions` 4.0.0 або новіших версій. Для наявних API Run, міркування й пошуку та GPT-6 Astra мінімальними залишаються версії 7.1.0 / 3.1.0.

## Навіщо потрібні ці налаштування?

Дослідження документів може потребувати кількох пошуків і викликів інструментів, перш ніж буде готова відповідь. Застосунку може знадобитися показувати перебіг роботи, вимагати певної перевірки лише для поточного ходу або продовжувати роботу після зміни попереднього вмісту розмови. Fable 5.1 додає налаштування для цих випадків, проте збережене міркування також робить історію розмови частиною контракту запиту.

Використовуйте [Run API](execution-api-transition.md), щоб спостерігати за завданням і скасовувати його, [спільні налаштування міркування та пошуку](reasoning-and-search.md), щоб вибирати рівень зусиль і джерела, а наведені нижче налаштування Claude — щоб керувати відображенням перебігу роботи й обробкою історії. Вбудовані можливості моделі не означають, що Mythosia надає доступ до кожного API провайдера.

## Явно виберіть модель і рівень зусиль

```csharp
using Mythosia.AI.Models;
using Mythosia.AI.Services.Anthropic;

var service = new AnthropicService(apiKey, httpClient);
service.ChangeModel(AIModels.Anthropic.ClaudeFable5_1);
service.WithAdaptiveThinkingParameters(ClaudeReasoningEffort.High);

string answer = await service.GetCompletionAsync("Перевір цей план міграції.");
```

`ClaudeFable5_1` вибирає `claude-fable-5-1`. `ClaudeMythos5_1` вибирає `claude-mythos-5-1` і потребує доступу до Project Glasswing. Наявні константи Fable 5 і Mythos 5 залишаються доступними. Обидві моделі 5.1 приймають текст і зображення та генерують текст; контекстне вікно становить 1 млн токенів, а максимальний обсяг відповіді — 128 тис. токенів. [Огляд моделі](https://platform.claude.com/docs/en/models/fable-5-1/overview).

Власне значення моделі за замовчуванням — `high`, проте Mythosia зберігає наявне перетворення `ThinkingBudget` для `ClaudeReasoningEffort.Auto`: увімкнений бюджет відповідає `High`, від 32 768 — `XHigh`, а від 100 000 — `Max`. Запит із вимкненням міркування використовує адаптивне міркування з низьким рівнем зусиль без доступного для читання тексту міркування. Якщо вам потрібна саме поведінка `High`, виберіть її явно: `Auto` не означає, що бібліотека завжди пропускає параметр зусиль і покладається на значення моделі за замовчуванням.

## Показуйте перебіг роботи між викликами інструментів

`ClaudeThinkingDisplay.Updates` запитує доступні для читання повідомлення про перебіг роботи, залишаючи міркування прихованим. `Summarized` також містить стислий виклад міркування, а `Omitted` приховує доступні для читання блоки міркування. Повідомлення залежать від того, чи створить їх модель, і не є сигналами активності з фіксованим інтервалом. [Повідомлення про перебіг роботи](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1#progress-updates-between-tool-calls-beta).

```csharp
using Mythosia.AI.Models.Streaming;

service.WithAdaptiveThinkingParameters(
    ClaudeReasoningEffort.High, ClaudeThinkingDisplay.Updates);

await using var run = await service.StartRunAsync(
    "Використай зареєстровані інструменти, щоб дослідити звіт.",
    options: StreamOptions.FullOptions);

await foreach (var item in run.StreamAsync())
{
    if (item.Type == StreamingContentType.Reasoning)
        Console.WriteLine($"Перебіг роботи: {item.Content}");
    else if (item.Type == StreamingContentType.Text)
        Console.Write(item.Content);
}
string result = (await run.Result).Text;
```

Повідомлення використовують наявну подію `StreamingContentType.Reasoning`; увімкніть спостереження за міркуванням через `StreamOptions.FullOptions` або `StreamOptions.Default.WithReasoning()`. Для відповіді без потокового передавання прочитайте `service.LastThinkingContent` після виклику. Текст про перебіг роботи відокремлений від остаточної відповіді й не розкриває необроблений ланцюжок міркувань.

## Додавайте зміни для поточного ходу, не переписуючи попередню історію

Блоки міркування Fable 5.1 прив’язані до системної інструкції, інструментів і попередніх повідомлень, на основі яких їх було створено. Переписування цих даних зі збереженням подальшого міркування може зробити його недійсним. Інструкція для одного ходу корисна, наприклад, коли перед відповіддю в цьому ході потрібно перевірити правила підтримки: вона додається до розмови й залишається в ній, але перестає діяти після наступного повідомлення користувача. Це дає змогу не переписувати системну інструкцію верхнього рівня щоразу. Зміна рівня зусиль і додавання інструкцій для ходу — окремі налаштування.

```csharp
await service
    .WithTurnInstruction("Перед відповіддю в цьому ході перевір зареєстрований інструмент правил підтримки.")
    .GetCompletionAsync("Чи можу я повернути товар у відкритій упаковці?");

await service
    .WithConversationInstruction("До кінця розмови відповідай українською.")
    .GetCompletionAsync("Поясни наступний крок.");
```

Обидва допоміжні методи фіксують інструкції для наступного логічного запиту. Mythosia додає системне повідомлення після введення користувача або результатів інструментів, зберігаючи попередні повідомлення. `WithTurnInstruction` використовує `clear_at: "next_user_message"`; у межах одного логічного запиту бібліотека знову додає інструкцію після кожного ходу з результатами інструментів, щоб вона діяла до завершення цього запиту. `WithConversationInstruction` продовжує діяти в наступних ходах. Налаштовуйте ці методи до початку роботи: жоден із них не є `run.SteerAsync` і не вставляє інструкцію у відповідь, яка вже генерується.

Щоб змінювати рівень зусиль між запитами зі збереженням придатного для кешування префікса, використовуйте `.WithReasoning(ReasoningLevel.High, cache: CachePreservation.Required)` із `Mythosia.AI.Extensions`. Бібліотека надсилає оновлення зусиль на рівні повідомлення й зберігає його в історії. Підтримувані поєднання описано у [спільному посібнику](reasoning-and-search.md). У версії 5.1 системні префікси й суфікси окремого запиту з `AIRequestContext` стають доданими інструкціями для ходу, а не переписують попередню системну інструкцію.

Fable 5.1 може використовувати міркування попередніх моделей Claude, але попередні моделі не можуть використовувати її міркування. Mythos 5.1 має спільні можливості версії 5.1, проте не виконує перевірку прив’язки до префікса, яку застосовує Fable. Вважайте редагування історії, перемикання моделей і відкидання міркування змінами, які потрібно відстежувати, замість припущення, що те саме міркування збереглося. [Посібник із міграції](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide).

## Діагностуйте навмисну зміну історії

`ThinkingPrefixMismatchBehavior = null` залишає застосування перевірок політиці облікового запису провайдера. `WithThinkingBinding(ClaudeThinkingPrefixMismatchBehavior.Error)` явно запитує перевірку на сервері. Зміни, які користувач вносить до історії, `SystemMessage` або інструментів, надсилаються Anthropic; невідповідність префікса з `Error` призводить до відповіді провайдера зі статусом 400. Повторення того самого некоректного запиту не виправляє проблему.

Якщо застосунок навмисно змінює попередній вміст і допускає втрату пов’язаного міркування, увімкніть `DropBlock`. Mythosia надсилає цей параметр Anthropic, а не непомітно видаляє міркування перед запитом.

```csharp
service.WithThinkingBinding(ClaudeThinkingPrefixMismatchBehavior.DropBlock);
service.SystemMessage = "Ти перевіряєш оновлені правила.";
await service.GetCompletionAsync("Повторно оціни рекомендацію.");

foreach (ClaudeInputTransformation change in service.LastInputTransformations)
    Console.WriteLine($"{change.Type}: {change.Reason} ({change.Model})");
```

`LastInputTransformations` надає повідомлені провайдером `Type`, `Path` і `Reason`, а також `ResponseId` і `Model` для визначення джерела. `prefix_binding_mismatch` означає змінений префікс, а `model_binding_mismatch` — міркування, яке цільова модель не може прочитати. Відкидання означає, що міркування видалено, а не відновлено. Якщо потрібне збереження, не змінюйте запис розмови; якщо хочете його скинути, почніть нову розмову.

Mythosia зберігає історію у форматі передавання до API, щоб внутрішня обробка RAG і контексту не вносила ненавмисних змін. Ці знімки зберігаються всередині конкретного сервісу для відповідного `ChatBlock`: перенесення лише початкового `ChatBlock` до нового сервісу не переносить знімки раніше надісланих доповнень RAG і контексту. Автоматичне локальне ущільнення блокується для звичайних розмов Fable 5.1 за замовчуванням і в режимі `Error`. `DropBlock` дозволяє його, проте може відкинути міркування й не гарантує влучань у кеш. Окремий параметр `CachePreservation.Required` зберігає суворіші перевірки історії. Спільні налаштування, як-от `WithWebSearch()`, витрачаються після кожного запиту. Якщо не вказати їх у наступному ході, масив вбудованих інструментів зміниться, що може спричинити невідповідність префікса. Для збереження історії повторно застосовуйте ті самі налаштування інструментів і пошуку; для навмисної зміни використовуйте `DropBlock` або нову розмову. Ці параметри не переносяться автоматично до наступних запитів.

## Використовуйте звичайний вибір інструментів

Fable 5.1 і Mythos 5.1 відхиляють примусовий вибір інструментів. Залишайте `ForceFunctionName` незаданим і описуйте в запиті, коли слід використовувати зареєстрований інструмент. `FunctionsDisabled` залишається доступним, коли хід не повинен викликати інструменти. Для типізованої відповіді використовуйте наявний API структурованого виводу, а не примусовий виклик функції лише для отримання JSON.

## Розрізняйте налаштування бібліотеки й зміни на сервері

| Вбудований параметр | Потрібна бета-версія Anthropic |
| --- | --- |
| Рівень зусиль на рівні повідомлення | `mid-conversation-output-config-2026-07-01` |
| Системне повідомлення для одного ходу | `mid-conversation-system-clear-at-2026-08-21` |
| `thinking.display: "updates"` | `thinking-display-updates-2026-08-18` |
| Керування прив’язкою міркування та `input_transformations` | `thinking-binding-controls-2026-08-01` |

Mythosia додає відповідний заголовок, коли ввімкнено підтримуване налаштування. Увімкнення однієї бета-версії не вмикає решту. Ця інтеграція не додає ущільнення на сервері, вбудованих блоків додавання чи видалення інструментів або автоматичного переходу на іншу модель у разі невдачі.

Обидві моделі потребують відповідного режиму зберігання даних провайдера протягом 30 днів; для ZDR потрібен явний дозвіл Anthropic. Адаптивне міркування завжди ввімкнене; ручний `budget_tokens` і вимкнення міркування недоступні, а нестандартні параметри семплювання не надсилаються. Доступ облікового запису та зберігання даних — вимоги сервера. [Вимоги міграції](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide).

Текстові водяні знаки, підтримувані відомості про походження медіа й тарифи на читання кешу застосовує Anthropic. Для них не потрібен новий параметр запиту Mythosia. Ця інтеграція не додає API створення відомостей про походження медіа, перемикача водяних знаків або керування оплатою. Див. [що змінилося у Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1).
