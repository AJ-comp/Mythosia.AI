# จัดการเซิร์ฟเวอร์โมเดลที่ทำงานอยู่

หน้าจอเลือกโมเดลหรือเครื่องมือดูแลระบบต้องทราบสถานะเซิร์ฟเวอร์ โมเดลที่มี และสถานะการโหลดก่อนส่งพรอมป์ต์ แพ็กเกจ Serving ทำให้ตรวจสอบข้อมูลเหล่านี้ผ่านอินเทอร์เฟซเดียวสำหรับ Ollama, llama.cpp และ vLLM ส่วนคำสั่งเฉพาะของแต่ละระบบยังต้องเรียกอย่างชัดเจน

ใช้แพ็กเกจเหล่านี้เพื่อแสดงรายการในตัวเลือกโมเดล แสดงว่าเชื่อมต่อเซิร์ฟเวอร์ได้หรือไม่ จัดการการคงอยู่ของโมเดลในหน่วยความจำเมื่อระบบรองรับ หรืออ่านเมตริกของเอนจิน เมื่อเปลี่ยนระบบ โค้ดตรวจสอบส่วนกลางของแอปพลิเคชันยังคงใช้ได้

ไคลเอนต์เหล่านี้เชื่อมต่อกับเซิร์ฟเวอร์ HTTP ที่มีอยู่ การติดตั้งและโฮสต์เอนจิน การเช่า GPU การแชต และการสร้าง embedding เป็นหน้าที่ของส่วนประกอบอื่น การแชตยังใช้บริการ AI ที่เหมาะสม เช่น `QwenService` สำหรับ vLLM ส่วนผู้ให้บริการ embedding ของ RAG แยกต่างหาก การสำรวจไม่โหลดโมเดลโดยอัตโนมัติ ยังไม่มีการรองรับ SGLang

## ตรวจสอบโดยไม่เปลี่ยนสถานะเซิร์ฟเวอร์

ติดตั้งแพ็กเกจของระบบที่ใช้งาน ตัวอย่างนี้ใช้ Ollama ส่วนเซิร์ฟเวอร์อื่นให้เลือก `VllmServer` หรือ `LlamaCppServer` จาก namespace ที่ตรงกัน การสำรวจใช้คำขออ่านอย่างเดียวและไม่ส่งคำสั่งโหลด สร้างผลลัพธ์ หรือดาวน์โหลด

```bash
dotnet add package Mythosia.AI.Serving.Ollama --version 1.0.0
```

```csharp
using System;
using System.Net.Http;
using System.Threading;
using Mythosia.AI.Serving;
using Mythosia.AI.Serving.Ollama;

using var http = new HttpClient { Timeout = TimeSpan.FromMinutes(10) };
using var cancellation = new CancellationTokenSource();
IModelServer server = new OllamaServer("http://localhost:11434", http,
    apiKey: Environment.GetEnvironmentVariable("MODEL_SERVER_API_KEY"));

var health = await server.GetHealthAsync(cancellation.Token);
var info = await server.GetInfoAsync(cancellation.Token);
var capabilities = await server.GetCapabilitiesAsync(cancellation.Token);
var models = await server.GetModelsAsync(cancellation.Token);

foreach (var model in models)
    Console.WriteLine($"{model.Id}: {model.InstallationState} / {model.LoadState}");
```

endpoint คือที่อยู่รากของเซิร์ฟเวอร์ และอาจมีคำนำหน้าเส้นทางของ reverse proxy คีย์ API เป็นตัวเลือกและจะส่งเป็นข้อมูลรับรอง Bearer ในแต่ละคำขอ ไคลเอนต์ไม่เปลี่ยน `HttpClient.DefaultRequestHeaders` และไม่กำจัด `HttpClient` ที่ส่งเข้ามา ให้ใช้ซ้ำและกำจัดตามอายุการใช้งานของแอปพลิเคชัน ในตัวอย่าง Ollama นี้ timeout ครอบคลุมเนื้อหาคำตอบแบบสตรีมด้วย จึงควรเผื่อเวลาให้เพียงพอสำหรับการดาวน์โหลดโมเดล

## อินเทอร์เฟซร่วมและส่วนเสริม

| อินเทอร์เฟซ | หน้าที่ |
| --- | --- |
| `IModelServer` | ข้อมูลเซิร์ฟเวอร์ สุขภาพระบบ โมเดล และความสามารถที่ตรวจพบ |
| `IModelLifecycle` | คำสั่งโหลดและนำโมเดลออกจากหน่วยความจำอย่างชัดเจน เป็นส่วนเสริม |
| `IModelDownloader` | การดาวน์โหลดอย่างชัดเจนพร้อมรายงานความคืบหน้า เป็นส่วนเสริม |
| `IModelMetricsProvider` | ค่าตัวอย่างเมตริกที่เก็บป้ายกำกับ เป็นส่วนเสริม |

การใช้อินเทอร์เฟซหมายความว่าไคลเอนต์มีการทำงานนั้น ส่วน `ServingCapabilities` ระบุสิ่งที่ยืนยันได้จาก endpoint ที่เชื่อมต่อ `Supported` ไม่รับประกันสิทธิ์หรือความสำเร็จสำหรับทุกโมเดล `Unsupported` หมายถึงใช้ไม่ได้ในโหมดหรือ endpoint ที่ตรวจพบ `Unknown` หมายถึงหลักฐานไม่พอ รวมถึงการยืนยันตัวตนหรือการเชื่อมต่อล้มเหลว จึงไม่ควรตีความว่าไม่รองรับ

`InstallationState` และ `LoadState` เป็นข้อมูลคนละด้าน `Unknown` ไม่ได้แปลว่าไม่มีโมเดลหรือโมเดลถูกนำออกจากหน่วยความจำ ค่า `SizeBytes`, `MemoryBytes`, `ContextLength` ที่ไม่มีรายงานจะคงเป็น `null` ไม่ใช่ศูนย์ endpoint จัดการที่ทำงานปกติไม่ได้ยืนยันว่าโมเดลใดพร้อมสำหรับการอนุมาน

## ความแตกต่างระหว่างระบบ

| การทำงาน | Ollama | llama.cpp โมเดลเดี่ยว | llama.cpp Router | vLLM |
| --- | --- | --- | --- | --- |
| ข้อมูล สุขภาพระบบ และรายการโมเดล | รองรับ | รองรับ | รองรับ | รองรับ |
| โหลด / นำออกจากหน่วยความจำอย่างชัดเจน | รองรับ โดยใช้คำขอสร้างผลลัพธ์ว่าง | ไม่รองรับ | รองรับ หลังยืนยันว่าเป็น Router | ไคลเอนต์นี้ไม่รองรับ |
| ดาวน์โหลดโมเดล | รองรับ พร้อมความคืบหน้าแบบสตรีม | ไม่รองรับ | ต้องเรียกอย่างชัดเจน และต้องมี endpoint ดาวน์โหลดกับเหตุการณ์ SSE | ไคลเอนต์นี้ไม่รองรับ |
| เมตริก | ยังไม่มี | เมตริกเซิร์ฟเวอร์เมื่อเปิดใช้งาน | overload เฉพาะโมเดลของคลาสโดยตรง โดยต้องโหลดโมเดลไว้แล้ว | เมตริกเซิร์ฟเวอร์เมื่อมีให้ใช้ |

ตารางนี้อธิบายการทำงานของไคลเอนต์ ไม่ได้รับประกันว่าเซิร์ฟเวอร์ทุกเวอร์ชัน ชุดสิทธิ์ หรือโมเดลจะรองรับ ให้ตรวจสอบความสามารถของ endpoint ที่เชื่อมต่อและจัดการความล้มเหลวของคำสั่ง

**Ollama:** `/api/tags` ให้รายการโมเดลที่ลงทะเบียน ส่วน `/api/ps` ให้รายการที่กำลังทำงาน โมเดลระยะไกลอาจลงทะเบียนโดยไม่มีน้ำหนักโมเดลในเครื่อง หากไม่มีโปรเซสในเครื่อง สถานะโหลดจะยังไม่ทราบ การโหลดล่วงหน้าใช้คำขอ `/api/generate` ว่างและ keep-alive เริ่มต้นของเซิร์ฟเวอร์ โมเดลสำหรับ embedding เท่านั้นจะไม่ถูกเปลี่ยนไปใช้ API อื่นโดยอัตโนมัติ การนำออกจากหน่วยความจำใช้ `keep_alive: 0` และไม่ลบไฟล์ ยังไม่มีเมตริก

**llama.cpp:** ต้องยืนยันโหมด router อย่างชัดเจนจาก `/props` ก่อนส่งคำสั่งวงจรชีวิตหรือดาวน์โหลด โหมดโมเดลเดี่ยวไม่รองรับคำสั่งเหล่านี้และคงสถานะพักที่ตรวจพบไว้ การดาวน์โหลดผ่าน router จะสมัคร `/models/sse` ก่อนส่ง `POST /models` และสำเร็จเฉพาะเมื่อได้รับ `download_finished` ของโมเดลนั้น การมี SSE เพียงอย่างเดียวยังยืนยันความสามารถดาวน์โหลดไม่ได้ เมตริกระดับเซิร์ฟเวอร์ใช้กับโหมดโมเดลเดี่ยว ส่วน router ต้องใช้ overload `GetMetricsAsync(modelId, token)` ของคลาสโดยตรง ซึ่งส่ง `autoload=false` เพื่อไม่ให้การตรวจสอบโหลดโมเดล

**vLLM:** ยังคงมีชื่อแทนที่ให้บริการและฟิลด์ `root` ที่อาจไม่มี แต่สถานะติดตั้งและโหลดในอินเทอร์เฟซร่วมยังเป็นไม่ทราบ ตรวจสอบโมเดลและเมตริกจากคำตอบจริง ไม่รองรับคำสั่งวงจรชีวิตและดาวน์โหลด เมธอดและ DTO เดิมของ `VllmServer` ยังใช้ผ่านคลาสโดยตรงได้ ส่วนเมธอดร่วมสำหรับสถานะ โมเดล และเมตริกใช้อินเทอร์เฟซแบบ explicit


## เรียกคำสั่งจัดการอย่างชัดเจน

การดาวน์โหลดและเปลี่ยนการคงอยู่ในหน่วยความจำใช้เครือข่าย ดิสก์ หรือหน่วยความจำอุปกรณ์ ให้เรียกเมื่อแอปพลิเคชันต้องการทำงานนั้น โค้ดต่อจากตัวอย่าง Ollama นี้จะดาวน์โหลดโมเดลขนาดเล็กและโหลดชั่วคราวเพื่อตรวจสถานะ ใช้ ID โมเดลของเซิร์ฟเวอร์ให้ตรงทุกตัว รวมถึงแท็ก Ollama หรือแท็ก quantization ของ llama.cpp

```csharp
if (server is IModelDownloader downloader &&
    capabilities.ModelDownloading == ServingFeatureSupport.Supported)
{
    var progress = new Progress<ModelDownloadProgress>(p =>
        Console.WriteLine($"{p.ModelId}: {p.Stage} {p.CompletedBytes}/{p.TotalBytes}"));
    await downloader.DownloadModelAsync("qwen2.5:0.5b", progress, cancellation.Token);
}

if (server is IModelLifecycle lifecycle &&
    capabilities.ModelLoading == ServingFeatureSupport.Supported &&
    capabilities.ModelUnloading == ServingFeatureSupport.Supported)
{
    try
    {
        await lifecycle.LoadModelAsync("qwen2.5:0.5b", cancellation.Token);
        var afterLoad = await server.GetModelsAsync(cancellation.Token);
        foreach (var model in afterLoad)
            Console.WriteLine($"{model.Id}: {model.LoadState}");
    }
    finally
    {
        using var cleanup = new CancellationTokenSource(TimeSpan.FromSeconds(30));
        await lifecycle.UnloadModelAsync("qwen2.5:0.5b", cleanup.Token);
    }
}
```

ตัวอย่างใช้โมเดลเฉพาะสำหรับทดสอบและนำออกจากหน่วยความจำเมื่อเสร็จ แอปพลิเคชันจริงต้องเลือกเองว่าจะปล่อยโมเดลเมื่อใด อย่านำโมเดลที่คำขออื่นยังใช้งานอยู่ออกจากหน่วยความจำ การเก็บกวาดมีเวลาจำกัดของตนเองและอาจล้มเหลวหากเซิร์ฟเวอร์ไม่พร้อมใช้งาน

ความคืบหน้าหมายถึงไฟล์หรือขั้นตอนหนึ่ง ค่าไบต์ที่เป็น null ไม่ใช่ศูนย์หรือเปอร์เซ็นต์ของทั้งโมเดล การโหลดสำเร็จยืนยันคำสั่ง แต่ไม่ยืนยันความพร้อมหรือการคงอยู่ในหน่วยความจำตลอดไป หากความพร้อมสำคัญ ให้ติดตาม `LoadState` โดยจำกัดเวลารอ ดูคู่มือแพ็กเกจโดยตรงสำหรับโปรโตคอลดาวน์โหลดและข้อจำกัดเวอร์ชันของ llama.cpp Router หลังตรวจสอบการตั้งค่าเซิร์ฟเวอร์แล้ว สามารถลองคำสั่งที่ร้องขออย่างชัดเจนแม้สถานะรองรับเป็น `Unknown` ได้ แต่การสำรวจความสามารถเพียงอย่างเดียวจะไม่เริ่มคำสั่งนั้น

## การยกเลิกและข้อผิดพลาด

ส่ง cancellation token ให้ทั้งการตรวจสอบและคำสั่ง การยกเลิกหยุดงาน HTTP และการรอของไคลเอนต์นี้ แต่ไม่รับประกันการหยุดงานระยะไกล การย้อนกลับ หรือการลบเลเยอร์ที่ดาวน์โหลดแล้ว ตั้งค่า `HttpClient` ที่ส่งเข้ามาตามระยะเวลางาน ไคลเอนต์เหล่านี้ไม่รับสิทธิ์เป็นเจ้าของอินสแตนซ์นั้น

เก็บป้ายกำกับเมตริกเมื่อเปรียบเทียบโมเดลหรือเอนจิน เมตริกที่ไม่มีไม่ใช่ศูนย์ และค่าอาจมี `NaN` หรืออนันต์ `ServingException` เป็นชนิดข้อผิดพลาดร่วม ข้อผิดพลาดจากการจัดการร่วมจะไม่ใส่เนื้อหาคำตอบดิบหรือข้อมูลรับรอง การเรียก vLLM แบบเดิมยังคงรายละเอียดข้อผิดพลาดเดิมไว้

`GetHealthAsync` จัดประเภทความล้มเหลวของ endpoint เป็นสถานะสุขภาพ แต่ยังส่งต่อการยกเลิกของผู้เรียก การทำงานอื่นอาจโยน `ServingException` ส่วนโหมด llama.cpp ที่ทราบว่าไม่รองรับอาจโยน `NotSupportedException` ทั้ง timeout และคำขอที่ล้มเหลวไม่ยืนยันว่าการทำงานระยะไกลถูกย้อนกลับ เมธอดดาวน์โหลดจะสำเร็จเมื่อระบบรายงานว่าเสร็จแล้วเท่านั้น โดย Ollama ต้องมีข้อความสำเร็จสุดท้ายตามด้วย EOF ส่วน llama.cpp Router ต้องมีเหตุการณ์ `download_finished` ที่ตรงกัน
