# Text Splitters

ผลค้นหาต้องมีบริบทพอสำหรับตอบคำถาม แต่การรวมทั้งเอกสารเป็นหน่วยเดียวทำให้เลือกส่วนที่ต้องการได้ยาก การแบ่ง chunk ช่วยปรับสมดุลขนาดกับบริบท ตัวแบ่งเหล่านี้ทำงานด้วยกฎภายในเครื่อง ไม่ต้องใช้โมเดล AI ให้เลือกตามโครงสร้างเอกสารแล้วประเมินด้วยคำถามจริง

## Splitter ที่มีให้ใช้

### CharacterTextSplitter

ใช้กับข้อความธรรมดาเมื่อเพียงต้องการจำกัดขนาด โดยเลือกตัวคั่นที่ตั้งไว้หากทำได้ แต่อาจตัดกลางประโยค `RagBuilder` ใช้ `CharacterTextSplitter(300, 30)` เป็นค่าเริ่มต้น นามสกุล `.md` ไม่ได้เลือกตัวแบ่ง Markdown ให้อัตโนมัติ

```csharp
.WithTextSplitter(new CharacterTextSplitter(500, 50))
```

### RecursiveTextSplitter (แนะนำเป็นค่าเริ่มต้น)

ใช้เมื่ออยากเก็บย่อหน้าและคำไว้ด้วยกันเท่าที่ทำได้ ลำดับตัวคั่นเริ่มต้นคือบรรทัดว่าง → ขึ้นบรรทัดใหม่ → `. ` → ช่องว่าง → อักขระเดี่ยว นี่คือกฎข้อความ ไม่ใช่โมเดลตัดสินความหมาย จุดตามด้วยช่องว่างเป็นเพียงการประมาณขอบเขตประโยค

รายการซ้ำใน `Separators` จะใช้เพียงครั้งเดียวตามลำดับที่พบครั้งแรก การใส่ตัวคั่นเดิมซ้ำไม่เพิ่มรอบการแบ่ง รายการตัวคั่นที่ยาวจะถูกประมวลผลโดยไม่ซ้อนการเรียกแบบเรียกซ้ำลึกขึ้น

```csharp
.WithTextSplitter(new RecursiveTextSplitter(500, 50))
```

### TokenTextSplitter

ใช้สำหรับนับคำที่คั่นด้วยช่องว่างโดยประมาณเท่านั้น แม้ชื่อจะเป็น Token แต่ `MaxTokensPerChunk` และ `TokenOverlap` นับหน่วยที่แยกด้วย `TokenSeparators` (ค่าเริ่มต้นคือช่องว่าง แท็บ และขึ้นบรรทัดใหม่) ไม่ใช่ token ของโมเดล ผลลัพธ์จะเปลี่ยนตัวคั่นเป็นช่องว่าง ข้อความยาวที่ไม่มีช่องว่างอาจยังเป็นหน่วยเดียว จึงไม่รับประกันเพดาน token ของโมเดล

```csharp
.WithTextSplitter(new TokenTextSplitter(256, 32))
```

### MarkdownTextSplitter

ใช้กับเอกสาร Markdown หรือ Markdown จาก loader Office/HWP เมื่อต้องเก็บบริบทหัวข้อ แถวตาราง และบล็อกโค้ด รองรับหัวข้อ ATX (`#`–`######`) รั้วโค้ด และตาราง เป็นตัวแบ่งตามกฎ ไม่ใช่ตัววิเคราะห์ต้นไม้ไวยากรณ์ Markdown แบบครบถ้วน constructor รับเฉพาะ `chunkSize` และ Markdown ไม่มีพารามิเตอร์หรือตัวเลือก overlap

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500))
```

#### คุณภาพการแบ่งตาราง

ตาราง GFM ที่ตรวจพบจะแบ่งระหว่างแถว โดยทำซ้ำหัวตารางและแถวคั่นในแต่ละ chunk ของตาราง ไม่จำเป็นต้องมีขีดตั้งด้านนอก (รองรับ `Name | Value`) วิธีนี้เก็บชื่อคอลัมน์ไว้ แต่คุณภาพการค้นหายังขึ้นกับเอกสาร embedding และคำถาม

ข้อความตัวหนาในเซลล์เป็นเนื้อหาของแถวนั้น เช่น `**ไม่คืนเงิน**` ในแถวบริษัท A ต้องไม่กลายเป็นเงื่อนไขของบริษัท B เซลล์ตารางและบล็อกโค้ดจะไม่ถูกยกเป็นป้ายข้อความที่ทำซ้ำ บรรทัด `**ป้าย**` ที่อยู่เดี่ยวจะถูกตรวจเป็นป้ายเฉพาะเมื่อเริ่มย่อหน้าหรือบล็อกข้อความ หลังบรรทัดว่างหรือขอบเขตโครงสร้าง ข้อความตัวหนาที่ขึ้นบรรทัดใหม่กลางย่อหน้าเดิมจะไม่สร้างย่อหน้าใหม่หรือป้ายซ้ำ ป้ายที่ตรวจพบอาจทำซ้ำในส่วนย่อยของบล็อกนั้น และขอบเขตจะสิ้นสุดเมื่อพบตาราง รั้วโค้ด หัวข้อ หรือป้ายที่ตรวจพบถัดไป

```
ตารางต้นฉบับ:
| ชื่อ   | แผนก  | เงินเดือน |
|--------|-------|-----------|
| Alice  | Dev   | $90,000   |
| Bob    | PM    | $85,000   |
| Carol  | Design| $80,000   |

→ Chunk 1:
| ชื่อ   | แผนก  | เงินเดือน |
|--------|-------|-----------|
| Alice  | Dev   | $90,000   |
| Bob    | PM    | $85,000   |

→ Chunk 2:
| ชื่อ   | แผนก  | เงินเดือน |
|--------|-------|-----------|
| Carol  | Design| $80,000   |
```

#### การป้องกันบล็อกโค้ด

บล็อกที่ล้อมด้วย backtick หรือ tilde จะคงไว้ทั้งบล็อก รั้วปิดต้องใช้อักขระชนิดเดียวกันและยาวไม่น้อยกว่ารั้วเปิด รั้วที่สั้นกว่าภายในบล็อกจึงไม่ปิดบล็อก การเก็บทั้งบล็อกอาจทำให้เกิน `ChunkSize`

การเยื้องของรั้วเปิดจะถูกเก็บพร้อมโค้ด ทำให้การแบ่งไม่เปลี่ยนความหมายของการเยื้องในโค้ดที่แสดงผล ระบบอ่านข้อมูลรั้วเปิดเพียงครั้งเดียวต่อบล็อก จึงไม่ต้องสแกนรั้วที่ยาวซ้ำสำหรับทุกบรรทัดของเนื้อหา

#### เส้นทางหัวข้อ

`IncludeHeadingBreadcrumb` มีค่าเริ่มต้นเป็น `true` แต่ละ chunk จะทำซ้ำเส้นทางหัวข้อเพื่อเก็บบริบทของส่วนที่ค้นพบ เมื่อเป็น `false` จะหยุดเฉพาะการทำซ้ำ แต่ยังเก็บหัวข้อเดิมไว้ ส่วนที่มีเพียงหัวข้อก็ยังคงอยู่

`MinSplitHeadingLevel` รับค่า 1–6 เพื่อเลือกว่าหัวข้อระดับใดเริ่มส่วนใหม่ ค่าเริ่มต้นคือ 1 เมื่อหัวข้อระดับบนเปลี่ยน จะจบส่วนย่อยเดิมเพื่อไม่ให้นำเส้นทางหัวข้อเก่าไปใช้กับเนื้อหาใหม่

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500)
{
    IncludeHeadingBreadcrumb = false
})
```

## การเลือกพารามิเตอร์

`CharacterTextSplitter`, `RecursiveTextSplitter` และ `MarkdownTextSplitter` วัดหน่วยรหัส UTF-16 (`string.Length`) ไม่ใช่ token หรืออักขระที่มองเห็น คู่ surrogate เช่น emoji จะไม่ถูกตัดครึ่ง หากตั้งขนาดเป็น 1 คู่ที่ต้องใช้ 2 หน่วยอาจเกินขนาดได้ ไม่รับประกันว่าตัวอักษรผสมหรือกลุ่ม grapheme ทั้งกลุ่มจะอยู่ด้วยกัน

ขนาดต้องมากกว่า 0 และ overlap ต้องไม่ติดลบ ค่าที่ไม่ถูกต้องจะเกิด `ArgumentOutOfRangeException` ก่อนประมวลผล และตรวจคุณสมบัติที่แก้ได้ซ้ำตอนแบ่ง หาก overlap มากกว่าหรือเท่ากับขนาดจะปิด overlap เพื่อความเข้ากันได้ สำหรับ Character/Recursive overlap เป็นค่าเป้าหมายที่ปรับตามตัวคั่น ขอบเขต Unicode และพื้นที่ใน chunk ถัดไป `0` หมายถึงไม่ซ้อนทับ และจะไม่สร้าง chunk ท้ายที่มีเพียงส่วนซ้อนทับเดิม

สำหรับ Markdown `ChunkSize` เป็นงบของเนื้อหา **ไม่รวมเส้นทางหัวข้อที่ทำซ้ำ** บล็อกโค้ดทั้งบล็อกหรือหัวตารางพร้อมหนึ่งแถวเต็มอาจเกินงบได้ ข้อความทั่วไปจะอยู่ในขนาดที่กำหนด ยกเว้นคู่ surrogate ข้างต้น

การทำซ้ำหัวข้อและหัวตารางต้องไม่ทำให้เอกสารเล็กกลายเป็นข้อความสำหรับ embedding ที่โตอย่างไร้ขอบเขต Markdown จึงจำกัดผลลัพธ์รวมต่อเอกสารไว้ที่ `max(65536, 32 × document.Content.Length)` หน่วย UTF-16 โดยรวมความยาวของทุก chunk สุดท้าย รวมถึงเส้นทางหัวข้อ หัวตาราง และป้ายที่ซ้ำ ระบบตรวจงบก่อนสร้างข้อความซ้ำที่มากเกินไป และโยน `InvalidOperationException` หากจะเกิน โดยไม่ตัดเนื้อหาหรือคืนผลลัพธ์บางส่วน `ChunkSize` และข้อยกเว้นของบล็อกที่แบ่งไม่ได้ยังต้องอยู่ภายในเพดานรวมนี้ ในขั้นตอนสร้างดัชนี RAG เริ่มต้น ข้อผิดพลาดการแบ่งเกิดก่อน embedding หรือแทนที่ระเบียน จึงคงดัชนีเดิมของเอกสารไว้ ค่านี้เป็นเพดานข้อความผลลัพธ์ ไม่ใช่เพดาน token ของโมเดลหรือหน่วยความจำของกระบวนการ งบนี้ใช้ต่อการเรียก `Split` และเพิ่มตามความยาวต้นฉบับ จึงไม่ใช่เพดานขนาดเอกสารขาเข้าที่ตายตัว

เริ่มได้ด้วย `RecursiveTextSplitter(500, 50)` สำหรับข้อความทั่วไป หรือ `MarkdownTextSplitter(500)` สำหรับ Markdown แล้วประเมินด้วยคำถามตัวอย่าง chunk ใหญ่เก็บบริบทโดยรอบมากขึ้น ส่วน overlap ทำซ้ำเนื้อหาและเพิ่มงาน embedding ทั้งสองอย่างไม่ได้รับประกันว่าค้นหาได้ดีขึ้น

หากต้องรักษาเพดาน token อย่างเคร่งครัด ให้นับแต่ละ chunk สุดท้าย รวมหัวข้อและหัวตารางที่ทำซ้ำ ด้วย tokenizer ของโมเดลเป้าหมาย จำนวนอักขระ/คำและอัตราส่วนตามภาษาไม่ใช่งบ token ที่รับประกันได้ หากต้องการเพดานแน่นอน ให้ใช้ tokenizer นั้นในการสร้าง `ITextSplitter`

การแก้ไขนี้เปลี่ยนขอบเขต chunk ของเอกสารที่เกี่ยวข้อง ให้สร้างดัชนีใหม่โดยใช้ ID เอกสารเดิมเพื่อแทน chunk เก่า แล้วอัปเดตแคช embedding และค่าฐานการประเมินที่เกี่ยวข้อง chunk ที่บันทึกไว้จะไม่ถูกเขียนใหม่อัตโนมัติ

## Splitter ต่อเอกสาร

ใช้ splitter ต่างกันในแต่ละเอกสารใน `RagBuilder`:

```csharp
.WithRag(rag => rag
    .AddDocuments(new PlainTextDocumentLoader(), "readme.md", new MarkdownTextSplitter(600))
    .AddDocuments(new PlainTextDocumentLoader(), "data.txt",  new RecursiveTextSplitter(300, 30))
    .WithTextSplitter(new RecursiveTextSplitter(500, 50))  // ค่าเริ่มต้นสำหรับที่เหลือ
)
```

## Splitter แบบกำหนดเอง

หากต้องการเขียนโมดูลการแบ่งแบบกำหนดเองแล้วนำมาเชื่อมต่อ ให้ implement `ITextSplitter`:

การทำดัชนีไม่ควรรายงานว่าสำเร็จทั้งที่ชังก์หนึ่งเขียนทับอีกชังก์หนึ่ง ให้แต่ละชังก์มี ID ที่ไม่ว่างและไม่ซ้ำกันในคอลเลกชัน พร้อมคัดลอกเมทาดาทาของเอกสารเพื่อคงตัวกรองบริษัทหรือสิทธิ์เข้าถึง ตัวอย่างนี้รวม ID เอกสารกับลำดับชังก์ Pipeline จะปฏิเสธ ID ที่ขาดหายและ ID ซ้ำภายในเอกสารเดียวกัน โดยไม่สร้าง ID ทดแทน ดู[การตรวจสอบขณะทำดัชนี](rag-pipeline.md#indexing-validation)

```csharp
public class SentenceSplitter : ITextSplitter
{
    public IReadOnlyList<RagChunk> Split(RagDocument document)
    {
        var sentences = document.Content.Split(". ");
        return sentences.Select((s, i) => new RagChunk
        {
            Id = $"{document.Id}_chunk_{i}",
            Content = s,
            Index = i,
            DocumentId = document.Id,
            Metadata = new Dictionary<string, string>(document.Metadata)
        }).ToList();
    }
}

// Register:
.WithTextSplitter(new SentenceSplitter())
```
