# ควบคุมงาน AI ที่กำลังทำงานด้วย Run

> API เหล่านี้ต้องใช้ `Mythosia.AI` 7.1.0 ขึ้นไป ซึ่งรวม `Mythosia.AI.Abstractions` 3.1.0 ขึ้นไป ตัวอย่าง RAG ต้องใช้ `Mythosia.AI.Rag` 7.6.0 ขึ้นไป

## ทำไมต้องควบคุมงานระหว่างที่กำลังทำงาน?

การเขียนรายงานอาจต้องค้นหาเอกสารหลายครั้ง เรียก API และเขียนเนื้อหาหลายขั้นตอน ระหว่างนั้นผู้ใช้อาจต้องการดูความคืบหน้า หยุดงาน หรือเพิ่มเงื่อนไข เช่น “ใช้เฉพาะข้อมูลของปีนี้” แอปจึงต้องมีวิธีเชื่อมการกระทำเหล่านี้กับงานที่เริ่มไปแล้ว

Run ให้ออบเจ็กต์แทนงานซึ่งแอปเก็บไว้ได้ ตัวอย่างเช่น หน้าจอแชตสามารถแสดงข้อความที่ทยอยเข้ามา แสดงช่วงที่เรียกเครื่องมือ เชื่อมปุ่มหยุดกับการยกเลิก และส่งคำสั่งเพิ่มเติมเมื่อโมเดลรองรับ ทั้งหมดนี้ควบคุมการทำงานครั้งเดียวกัน

| สิ่งที่แอปต้องการ | วิธีที่ใช้ |
| --- | --- |
| รับคำตอบที่เสร็จแล้วโดยไม่ต้องควบคุมระหว่างทำงาน | ใช้ `GetCompletionAsync` ต่อได้ รวมทั้งโอเวอร์โหลดแบบกำหนดชนิดและ RAG |
| แสดงข้อความทันทีที่ได้รับและรวบรวมเมื่อทำงานเสร็จ | เริ่ม Run พร้อม `onText` แล้วรอ `run.Result` |
| แสดงการใช้เครื่องมือหรือรอการส่งเอาต์พุตแบบอะซิงโครนัส | อ่านเหตุการณ์จาก `run.StreamAsync()` |
| ให้ผู้ใช้หยุดงานที่กำลังทำ | เรียก `run.Cancel()` บนออบเจ็กต์ที่เก็บไว้ |
| เพิ่มเงื่อนไขก่อนงานเสร็จ | ตรวจ `run.CanSteer` แล้วใช้ `run.SteerAsync(...)` กับโมเดลที่รองรับ |

`StartRunAsync` เริ่มงานของโมเดลหนึ่งงานและส่งคืน `AIRun` งานจะดำเนินต่อไม่ว่าคุณจะอ่านเอาต์พุตหรือไม่ ใช้ออบเจ็กต์เดียวกันเพื่ออ่านสตรีม รับผลที่รวบรวมไว้ ยกเลิก และส่งคำสั่งเพิ่มเติมระหว่างทำงานเมื่อรองรับ ส่วน `GetCompletionAsync` รวมทั้งโอเวอร์โหลดแบบกำหนดชนิดและ RAG ยังคงเป็น API สาธารณะที่สะดวกสำหรับผู้ที่ต้องการเพียงผลลัพธ์เมื่อเสร็จ

## แสดงข้อความด้วย callback

สำหรับหน้าจอแชตหรือคอนโซล การแสดงข้อความส่วนแรกทันทีที่ได้รับช่วยให้ผู้ใช้ติดตามคำตอบยาว ๆ ได้ขณะที่โมเดลยังเขียนอยู่

```csharp
await using var run = await service.WithMaxRounds(10).StartRunAsync(
    "อ่านเอกสารแล้วเขียนรายงาน",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);

string answer = await run.Result;
```

`onText` เป็น `Action<string>` แบบเลือกใช้ ซึ่งลงทะเบียนก่อนเริ่มงาน โดยรับข้อความตามลำดับและไม่ได้เป็นผู้เรียกใช้เครื่องมือ หากต้องการเพียงผลลัพธ์ก็ไม่ต้องส่ง callback นี้ หาก callback เกิดข้อยกเว้น Run จะยกเลิกและ `Result` จะรายงานข้อผิดพลาดด้วย อย่าส่งแลมบ์ดา `async` ให้ `onText` เพราะจะกลายเป็น `async void` ทำให้ Run ไม่สามารถรอให้งานนั้นเสร็จหรือรับข้อผิดพลาดของมันได้ หากต้องส่งข้อมูลแบบอะซิงโครนัสให้ใช้สตรีมเหตุการณ์ และ callback ไม่ได้สลับไปทำงานบนเธรด UI โดยอัตโนมัติ

`Result` คือข้อความจากเหตุการณ์ของ Run ที่นำมาต่อกัน รวมถึงข้อความระหว่างการเรียกเครื่องมือและข้อความที่สร้างก่อนคำสั่งเพิ่มเติม ไม่ใช่การส่งคำขอใหม่ไปยังโมเดลหรือการเขียนคำตอบใหม่ทั้งหมด หากต้องการความหมายของผลลัพธ์แบบเดิม ก็ยังใช้ `GetCompletionAsync` ได้

## อ่านเหตุการณ์ข้อความ เครื่องมือ และการใช้โทเคน

เมื่องานค้นหาเอกสารหรือเรียก API ของระบบธุรกิจ ข้อความเพียงอย่างเดียวอาจไม่อธิบายว่าทำไมต้องรอ เหตุการณ์ที่แยกชนิดช่วยให้แสดงการใช้เครื่องมือควบคู่กับคำตอบ และบันทึกการใช้โทเคนเมื่อผู้ให้บริการส่งข้อมูลมา

```csharp
await using var run = await service.StartRunAsync(
    "ค้นหาเอกสารและอธิบายผลลัพธ์",
    cancellationToken: cancellationToken);

await foreach (var item in run.StreamAsync())
{
    switch (item.Type)
    {
        case StreamingContentType.Text:
            Console.Write(item.Content);
            break;
        case StreamingContentType.FunctionCall:
            Console.WriteLine("\n[กำลังเรียกเครื่องมือ]");
            break;
        case StreamingContentType.FunctionResult:
            Console.WriteLine("\n[ได้รับผลจากเครื่องมือแล้ว]");
            break;
        case StreamingContentType.Completion when item.Usage != null:
            Console.WriteLine($"\n[โทเคนทั้งหมด: {item.Usage.TotalTokens}]");
            break;
    }
}

string answer = await run.Result;
```

`run.StreamAsync()` รับได้เฉพาะโทเคนยกเลิกการสังเกตแบบเลือกใช้ ไม่รับพรอมป์ต์ใหม่ เพราะเป็นการอ่านงานที่เริ่มด้วย `StartRunAsync` แล้ว ไลบรารีเป็นผู้เรียก handler ของฟังก์ชันที่ลงทะเบียนไว้ จึงไม่ควรเรียกเครื่องมือซ้ำเมื่อได้รับเหตุการณ์เพื่อแสดงผล การตั้งค่าแสดงเฉพาะข้อความไม่ได้ปิดเครื่องมือของ Run

callback ที่ส่งตอนเริ่มงานและ `run.StreamAsync()` สามารถสังเกต Run เดียวกันพร้อมกันได้ แต่สตรีมเหตุการณ์รองรับผู้อ่านเพียงหนึ่งราย เช่น แสดงข้อความใน `onText` แล้วอ่านเฉพาะเหตุการณ์เครื่องมือจากสตรีม เพื่อไม่ให้แสดงข้อความซ้ำ บัฟเฟอร์เก็บเหตุการณ์ที่ยังไม่ได้อ่านได้ไม่เกิน 1,024 รายการ แม้จะมี callback อยู่แล้ว หากเริ่มอ่านภายหลังจะได้รับเหตุการณ์ตั้งแต่ต้นตราบใดที่ยังอยู่ในบัฟเฟอร์ เมื่อเกินขีดจำกัด การอ่านสตรีมจะล้มเหลวอย่างชัดเจน แต่ callback การทำงาน และ `Result` จะดำเนินต่อ อย่าใช้สตรีมเป็นบันทึกย้อนหลังที่เก็บได้ไม่จำกัด และไม่จำเป็นต้องอ่านสตรีมจนหมดเพื่อรอ `Result`

Run ที่ค้นหาเว็บหรือเอกสารสามารถแสดงแหล่งอ้างอิงของคำตอบได้ด้วย ดูตัวอย่าง `WithWebSearch`, `WithFileSearch`, `run.Citations` และเหตุการณ์แหล่งอ้างอิงใน[คู่มือการให้เหตุผลและการค้นหา](reasoning-and-search.md)

## จัดการเอาต์พุตแบบอะซิงโครนัส

ให้รอการทำงานแบบอะซิงโครนัสภายในลูปอ่าน แทนการส่ง callback แบบอะซิงโครนัสให้ `onText`:

```csharp
using var writer = new StreamWriter("report.txt");
await using var run = await service.StartRunAsync(
    "เขียนรายงาน", cancellationToken: cancellationToken);

await foreach (var item in run.StreamAsync())
{
    if (item.Type == StreamingContentType.Text && item.Content is string text)
        await writer.WriteAsync(text);
}
string answer = await run.Result;
```

## ยกเลิกและคืนทรัพยากร

- การออกจาก `await foreach` หรือยกเลิกโทเคนที่ส่งให้ `run.StreamAsync(token)` เท่านั้น จะหยุดการสังเกต แต่งานยังทำต่อ
- `run.Cancel()` โทเคนที่ส่งให้ `StartRunAsync` และการคืนทรัพยากรของ Run ที่ยังทำงานอยู่ จะยกเลิกการทำงาน
- `await using` ทำให้ `DisposeAsync()` รอส่วนผลิตเหตุการณ์และการเก็บกวาดของผู้ให้บริการ เครื่องมือที่ไม่รองรับการยกเลิกอาจต้องใช้เวลาจนทำงานเสร็จ และการคืนทรัพยากรไม่ได้ย้อนคืนสิ่งที่ทำสำเร็จไปแล้ว
- หนึ่งบริการมีงาน `StartRunAsync` ที่ทำงานอยู่ได้ครั้งละหนึ่งงาน การเริ่มงานซ้อนจะถูกปฏิเสธ ใช้บริการคนละอินสแตนซ์สำหรับงานพร้อมกันที่เป็นอิสระ และอย่าเรียก API เดิมร่วมกันหรือเปลี่ยนการตั้งค่าบริการขณะที่ Run ยังทำงาน

Run จะเก็บข้อมูลอินพุตและนโยบายเฉพาะคำขอที่รอใช้งานไว้ก่อนเริ่มทำงานเบื้องหลัง เนื้อหาข้อความ รูปภาพ และเสียงชนิดที่ไลบรารีรองรับ รวมทั้งอาร์เรย์ไบต์ของสื่อจะถูกคัดลอก ส่วนคลาสที่ผู้ใช้สืบทอดจาก `MessageContent` จะคงออบเจ็กต์เดิมไว้ จึงต้องไม่แก้ไขจนกว่า Run จะเสร็จ

ค่า `FunctionCallingPolicy.TimeoutSeconds` ที่เก็บไว้กำหนดเวลาสิ้นสุดร่วมกันเพียงครั้งเดียว ตั้งแต่การเตรียม Run ไปจนถึงทุก ๆ รอบของโมเดลและเครื่องมือ เมื่อหมดเวลาจะรายงาน `AIServiceException` ส่วนการยกเลิกโดยผู้ใช้จะทำให้ผลลัพธ์อยู่ในสถานะยกเลิก การเก็บกวาดยังคงรอ handler ที่ไม่รองรับการยกเลิกให้เสร็จ

## ส่งคำสั่งเพิ่มเติมระหว่างทำงาน

สมมติว่าผู้ใช้เริ่มให้ร่างแผนโครงการแล้วเพิ่งนึกได้ว่าต้องเสร็จภายในสองสัปดาห์ Steering ช่วยให้แอปส่งเงื่อนไขใหม่นี้ได้ขณะที่โมเดลยังทำงานอยู่ เหมาะสำหรับการแก้ไขหรือปรับขอบเขตที่พบระหว่างงานยาว ๆ หากเป็นคำถามใหม่หลังงานเสร็จแล้ว ให้เริ่มคำขอถัดไปตามปกติ

```csharp
await using var run = await service.StartRunAsync(
    "ร่างแผนโครงการ",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);

// เรียกจากตัวจัดการคำสั่งเพิ่มเติมของ UI ขณะที่งานยังทำงานอยู่
async Task SendUpdateAsync(string instruction)
{
    if (!run.CanSteer)
        throw new NotSupportedException("งานนี้ไม่รองรับคำสั่งเพิ่มเติมระหว่างทำงาน");

    await run.SteerAsync(instruction, cancellationToken);
}

string answer = await run.Result;
```

GPT-6 Astra รองรับคำสั่งเพิ่มเติมระหว่างทำงานผ่านการเชื่อมต่อ WebSocket ของ Responses API ผู้ให้บริการอื่นและโมเดลที่ไม่รองรับยังใช้ Run ปกติได้ แต่ `CanSteer` จะเป็น false และการส่งคำสั่งเพิ่มเติมจะรายงานว่าไม่รองรับ แทนการเปลี่ยนเป็นคำถามรอบใหม่โดยไม่แจ้ง ค่า `CanSteer` ไม่ได้รับประกันว่างานจะยังทำอยู่เมื่อคุณเรียกใช้ในภายหลัง

Run ของ Astra เปิดซ็อกเก็ตเฉพาะขึ้นมา `HttpClient` และ message handler ที่ส่งให้บริการยังใช้กับคำขอ HTTP และไม่ได้ดักการเชื่อมต่อซ็อกเก็ตนี้ หากต้องใช้ transport แบบกำหนดเอง สามารถ override `OpenAIService.ConnectRunWebSocketAsync` ได้

เมื่อ `SteerAsync` สำเร็จ หมายถึงเซิร์ฟเวอร์รับอินพุตเข้าคิวแล้ว ไม่ได้แปลว่าโมเดลนำไปใช้แล้ว ให้สังเกต Run เดิมต่อหรือรอผลลัพธ์ผ่านคำตอบที่ดำเนินต่อ ข้อความที่ส่งไปแล้วและสิ่งที่ทำสำเร็จจะไม่ถูกย้อนคืน และเครื่องมือที่เริ่มแล้วจะไม่ถูกยกเลิกเพียงเพราะส่งคำสั่งเพิ่มเติม ไลบรารีจัดการคำตอบต่อเนื่องและจับคู่ผลของเครื่องมือบนการเชื่อมต่อเดิม ดู[คู่มือคำสั่งเพิ่มเติมของ OpenAI](https://developers.openai.com/api/docs/guides/steering) และ[โหมด WebSocket](https://developers.openai.com/api/docs/guides/websocket-mode) อย่าสมมติว่าคำสั่งในคิวของการเชื่อมต่อเดิมยังอยู่หลังการเชื่อมต่อขาด และอย่าส่งคำสั่งที่รับแล้วซ้ำโดยไม่ตรวจสอบ

## งานที่ใช้เครื่องมือและเมธอด agent เดิม

คำถามอย่าง “ตรวจนโยบายการคืนสินค้าและสถานะของคำสั่งซื้อนี้” ต้องใช้ข้อมูลมากกว่าหนึ่งแหล่ง ให้ลงทะเบียนเครื่องมือค้นหาเอกสารและตรวจคำสั่งซื้อ แล้วให้โมเดลเลือกการเรียกที่จำเป็น ขีดจำกัดจำนวนรอบช่วยกำหนดว่าโมเดลจะขอใช้เครื่องมือต่อไปได้นานเพียงใดก่อนต้องจบหรือรายงานข้อผิดพลาด

การเรียกฟังก์ชันปกติรองรับการทำงานหลายรอบระหว่างโมเดลกับเครื่องมืออยู่แล้ว `StartRunAsync` ใช้ฟังก์ชันที่ลงทะเบียนและนโยบายชุดเดียวกัน ไม่ต้องมีโหมด agent ตัววางแผน หรือสวิตช์ `WithAgentic` แยกต่างหาก

`RunAgentAsync` และ `RunAgentStreamAsync` ยังเรียกได้ แต่จะแสดงคำเตือน `[Obsolete]` ระหว่างเปลี่ยนผ่านจะรักษาซิกเนเจอร์เดิม ค่าเริ่มต้น `maxSteps = 10` และพฤติกรรมข้อผิดพลาดเมื่อเกินขีดจำกัดแบบเดิมไว้ โค้ดเรียกใช้ใหม่ควรเขียนดังนี้:

```csharp
await using var run = await service.WithMaxRounds(10).StartRunAsync(
    "ค้นหานโยบาย ตรวจสอบคำสั่งซื้อ และอธิบายผลลัพธ์",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);
string answer = await run.Result;
```

ค่าเริ่มต้นของ `FunctionCallingPolicy.MaxRounds` ทั่วไปคือ 20 จึงควรกำหนดเป็น 10 หากต้องการคงขีดจำกัดเดิมของ agent โดย `WithMaxRounds` ตั้งนโยบายทับเฉพาะคำขอถัดไปหนึ่งครั้ง ไม่ได้เปลี่ยน `DefaultPolicy` ให้กำหนดก่อนเริ่มงาน ส่วนเมธอด agent เดิมจะคัดลอกนโยบายเริ่มต้นแล้วใช้ `maxSteps` ของการเรียกนั้น Run ใหม่ใช้รูปแบบข้อผิดพลาดร่วมของระบบ และไม่ได้รับประกันการแปลงเป็น `AgentMaxStepsExceededException` พร้อม `PartialResponse` แบบเดิม หากแอปพึ่งพาพฤติกรรมนี้ ให้คงการเรียกเดิมไว้จนกว่าจะปรับการจัดการข้อยกเว้นครบ

## RAG, MCP และขอบเขตแพ็กเกจ

- `RagEnabledService.StartRunAsync` รับสตริงหรือ `Message`, `onText`, `RagQueryOptions` ต่อคำขอ, `streamOptions` และการยกเลิก โดยค้นหาก่อนเริ่ม Run ภายใน รักษารูปภาพ เสียง และเมตาดาตา เก็บอินพุตเดิมในประวัติ แล้วส่งข้อความที่เสริมบริบทผ่าน request context การเสริมบริบทผูกกับคำถามแรกของผู้ใช้เท่านั้น จึงไม่เขียนทับผลของเครื่องมือหรือคำสั่งเพิ่มเติมภายหลังด้วยพรอมป์ต์ RAG เดิม Steering ส่งเงื่อนไขให้โมเดล แต่ไม่ได้ค้นหา RAG ใหม่โดยอัตโนมัติ
- `WithAgenticRag` ยังคงใช้ลงทะเบียนเครื่องมือค้นหา เรียกใช้งานผ่าน `StartRunAsync` แล้วโมเดลสามารถค้นหาเพิ่มเติมตามความจำเป็นได้ การลงทะเบียน MCP ด้วย `WithMcpServerAsync` ก็ไม่เปลี่ยน ให้คืนทรัพยากรการเชื่อมต่อ MCP ที่ใช้ร่วมกันแยกจาก Run
- `IAIRunService` เป็นความสามารถแบบเลือกใช้ใน `Mythosia.AI.Abstractions` จึงไม่มีสมาชิกบังคับใหม่ใน `IAIService` หากบริการที่ผู้ใช้สร้างเองต้องการเริ่ม RAG Run จะต้อง implement `IAIRunService` บริการที่ไม่รองรับจะถูกปฏิเสธก่อนเริ่มทำดัชนี RAG
- RAG ยังคงอ้างอิง Abstractions ส่วนผู้ให้บริการที่อยู่คนละแพ็กเกจยังคงมี public override ของการสร้างคำตอบและจุดขยายที่เข้าถึงได้ การเปลี่ยนนี้ไม่ได้ทำให้ API ของฐานข้อมูลเวกเตอร์ ตัวโหลดเอกสาร หรือการจัดการเซิร์ฟเวอร์เป็น API ที่เลิกใช้

## ความเข้ากันได้และเวอร์ชันหลักถัดไป

| API | สถานะปัจจุบัน |
| --- | --- |
| `GetCompletionAsync` / `GetCompletionAsync<T>` | ยังคงเป็น API สาธารณะและรองรับ รวมรุ่นของอินเทอร์เฟซ ผู้ให้บริการ และ RAG |
| `StartRunAsync` / `AIRun` | API ร่วมสำหรับเริ่มงานและควบคุมการทำงาน |
| `RunAgentAsync` / `RunAgentStreamAsync` | มีคำเตือนเลิกใช้ แต่รักษาพฤติกรรมเดิมเพื่อความเข้ากันได้ |
| `service.StreamAsync` และ RAG `StreamAsync` ที่รับอินพุต | ยังเรียกได้ในเวอร์ชันย่อยนี้ และมีแผนถอนจาก API สาธารณะในเวอร์ชันหลักถัดไป |
| `run.StreamAsync()` | สังเกตเอาต์พุตของงานที่มีอยู่แล้ว โดยไม่รับอินพุตใหม่ |
| `BeginStream(...).As<T>()` / `StructuredStreamRun<T>` | รักษา API สตรีมแบบกำหนดชนิดเดิมไว้ โดย `Stream()` ที่อ่านเอาต์พุตอย่างเดียวไม่ใช่เมธอดเริ่มคำขอของบริการแบบเดิม |

เวอร์ชันหลักถัดไปจะเปลี่ยนจุดเริ่มคำขอสตรีมที่เป็น API สาธารณะ โดยคงการทำงานภายในและจุดขยายของผู้ให้บริการที่จำเป็นไว้ การเปลี่ยนเมธอด public เป็น private หรือ protected ยังคงทำให้โค้ดต้นฉบับและไบนารีของผู้เรียกเดิมใช้ร่วมกันไม่ได้ แม้จะเก็บตัวเมธอดไว้ก็ตาม ตัวช่วยอย่าง message chain การเรียกครั้งเดียว การสรุป การเขียนคำค้นใหม่ และการจัดอันดับใหม่ ไม่ได้กลายเป็น API ที่เลิกใช้เพียงเพราะใช้เมธอดการทำงานเดิม
