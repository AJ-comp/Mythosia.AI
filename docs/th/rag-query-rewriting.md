# การเขียนคำถามใหม่

> 📍 **Q&A Pipeline:** **`การเขียนคำถามใหม่`** → การกรอง → Embedding (เมื่อจำเป็น) → [การดึงข้อมูล](rag-hybrid-search.md) → [Reranking](rag-reranking.md) → การสร้าง Context

ขั้นตอนคำถาม `Embedding` ขึ้นกับตัวค้นหา การค้นหาคำไม่รายงานขั้นตอนนี้ ตัวค้นหาที่กำหนดเองรายงานผ่าน `request.ProgressAsync` ได้ ส่วน embedding เอกสารไม่เปลี่ยนแปลง

## ทำไมต้องเขียนคำถามใหม่?

ในการสนทนาหลายรอบ ผู้ใช้มักใช้สรรพนามและการอ้างอิงแบบย่อ:

> ผู้ใช้: "บอกเรื่องนโยบายการคืนสินค้าให้หน่อย"
> ผู้ใช้: "แล้วข้อยกเว้นของ**มัน**ล่ะ?"

ถ้าส่ง "แล้วข้อยกเว้นของมันล่ะ?" ตรง ๆ ไปยัง vector store embedding ไม่รู้ว่า "มัน" หมายถึงอะไร ผลการค้นหาจะไม่เกี่ยวข้องและคำตอบด้อยคุณภาพ

**การเขียนคำถามใหม่** แก้ไขการอ้างอิงเหล่านี้ก่อนดึงข้อมูล ขยาย "มัน" → "ข้อยกเว้นของนโยบายการคืนสินค้า" เพื่อให้ embedding เข้าใจความตั้งใจเต็มรูปแบบ นอกจากนี้ยังมี **search gate** — ถ้า query ไม่ต้องการดึงข้อมูล (เช่น "ขอบคุณ!") จะข้าม vector search ทั้งหมด ประหยัดเวลาและค่าใช้จ่าย

## การตั้งค่า

`LlmQueryRewriter` ใช้ AI service เดิมเพื่อเขียน query ใหม่ก่อน embedding:

```csharp
.WithRag(rag => rag
    .WithQueryRewriter(250)          // ใช้ AI service เดิม
    .AddDocument("docs.txt")
)
```

บอท rewriter ตรวจ context การสนทนาและสร้าง query ค้นหาที่สมบูรณ์ในตัวเองซึ่ง vector store เข้าใจได้โดยไม่ต้องมีประวัติ

## RAG แบบหลายรอบ

เมื่อ query `RagStore` โดยตรง ให้ส่งประวัติการสนทนาด้วยเพื่อให้ rewriter แก้ไขการอ้างอิงได้:

```csharp
var history = new List<ConversationTurn>
{
    new ConversationTurn("นโยบายการคืนสินค้าคืออะไร?", "คุณสามารถคืนสินค้าได้ภายใน 30 วัน"),
    new ConversationTurn("แล้วสินค้าดิจิทัลล่ะ?", "สินค้าดิจิทัลไม่สามารถคืนได้")
};

var result = await store.QueryAsync(
    query: "มีข้อยกเว้นไหม?",
    conversationHistory: history
);
```

Rewriter เห็นประวัติทั้งหมดและเขียนใหม่ "มีข้อยกเว้นไหม?" เป็น "ข้อยกเว้นของนโยบายไม่คืนสินค้าดิจิทัล" ให้ผลการค้นหาที่ดีขึ้นมาก

## เปลี่ยนการเขียนคำถามใหม่ระหว่างให้บริการค้นหา

หากต้องการปิดการเขียนคำถามใหม่ชั่วคราวหรือเปลี่ยนตัวประมวลผลโดยไม่สร้างดัชนีใหม่ ให้ใช้ `store.SetQueryRewriter(null)` หรือ `store.SetQueryRewriter(rewriter)` เมื่อเรียกโอเวอร์โหลดของ `RagStore.QueryAsync` ที่รับ `conversationHistory` โดยตรง ระบบจะเก็บตัวเขียนคำถามใหม่ที่เลือกไว้ตั้งแต่เริ่มคำขอ แม้จะปิดหรือเปลี่ยนการตั้งค่าระหว่างรอการแจ้งความคืบหน้าหรือการเขียนคำถามใหม่ คำขอนั้นยังใช้อินสแตนซ์เดิม ส่วนคำขอถัดไปจะใช้การตั้งค่าใหม่ พฤติกรรมนี้ใช้กับการค้นหาผ่านสโตร์โดยตรง และไม่ได้เปลี่ยนตัวเขียนคำถามใหม่ที่แรปเปอร์ `RagEnabledService` เก็บไว้แล้ว

## Search Gate ทำงานอย่างไร

ไม่ใช่ทุกข้อความของผู้ใช้ที่ต้องการค้นเอกสาร Rewriter จำแนก query และส่ง query เปล่ากลับสำหรับข้อความอย่าง:

- "ขอบคุณ!"
- "เข้าใจแล้ว ขอบคุณมาก"
- "ช่วยสรุปสิ่งที่พูดมาให้หน่อยได้ไหม?"

เมื่อ gate ทำงาน pipeline การดึงข้อมูลทั้งหมดจะถูกข้ามไป — ไม่มี embedding ไม่มี vector search ไม่มี reranking — LLM ตอบตรง ๆ จาก context การสนทนา
