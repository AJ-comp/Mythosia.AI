# 쿼리 재작성

> 📍 **질문 응답 파이프라인:** **`쿼리 재작성`** → 임베딩 → 필터링 → [검색](rag-hybrid-search.md) → [재순위](rag-reranking.md) → 컨텍스트 구성

## 대화 속 검색이 어려운 이유

사람은 대화할 때 자연스럽게 앞에서 했던 말을 생략하거나 대명사로 대체합니다:

> 사용자: "환불 정책에 대해 알려주세요."
> AI: "30일 이내에 반품하시면 전액 환불됩니다."
> 사용자: "**그것**의 예외는 무엇인가요?"

여기서 "그것"은 "환불 정책"을 가리킵니다. 사람은 바로 알 수 있지만, 벡터 스토어에 "그것의 예외는 무엇인가요?"를 그대로 보내면 임베딩은 "그것"이 무엇인지 전혀 알 수 없습니다. 결과적으로 엉뚱한 문서가 검색되고, 답변 품질이 크게 떨어집니다.

## 쿼리 재작성이란?

**쿼리 재작성**은 이 문제를 해결하는 기술입니다. 벡터 스토어에 검색하기 **전에**, 대화 맥락을 읽고 대명사나 생략된 표현을 풀어서 완전한 검색 쿼리로 바꿔줍니다.

```
변환 전: "그것의 예외는 무엇인가요?"
변환 후: "환불 정책의 예외 사항"
```

이렇게 하면 임베딩이 전체 의도를 정확히 파악할 수 있어 검색 결과가 훨씬 좋아집니다.

또한 **검색 게이트** 기능도 함께 제공합니다. "감사합니다!"처럼 문서 검색이 필요 없는 메시지에서는 검색을 자동으로 건너뛰어 불필요한 비용과 지연을 줄여줍니다.

## 설정 방법

`.WithQueryRewriter()`를 추가하면 현재 사용 중인 AI 서비스가 쿼리 재작성도 함께 처리합니다:

```csharp
.WithRag(rag => rag
    .WithQueryRewriter(250)          // 동일한 AI 서비스 사용
    .AddDocument("docs.txt")
)
```

재작성기는 대화 맥락을 분석한 뒤, 벡터 스토어가 대화 기록 없이도 이해할 수 있는 독립적인 검색 쿼리를 생성합니다.

## 멀티턴 대화에서의 RAG

`RagStore`를 직접 쿼리할 때는 대화 기록을 함께 전달해야 재작성기가 맥락을 파악할 수 있습니다:

```csharp
var history = new List<ConversationTurn>
{
    new ConversationTurn("환불 정책이 무엇인가요?", "30일 이내에 반품할 수 있습니다."),
    new ConversationTurn("디지털 제품은요?", "디지털 제품은 환불이 불가합니다.")
};

var result = await store.QueryAsync(
    query: "거기에 예외가 있나요?",
    conversationHistory: history
);
```

재작성기가 전체 대화 흐름을 보고, "거기에 예외가 있나요?"를 "디지털 제품 환불 불가 정책의 예외"와 같이 구체적으로 재작성합니다. 모호한 질문이 명확한 검색 쿼리로 바뀌면서 검색 결과가 크게 개선됩니다.

## 검색 게이트의 동작 방식

모든 사용자 메시지가 문서 검색을 필요로 하는 것은 아닙니다. 재작성기는 메시지의 성격을 자동으로 분류해서, 검색이 불필요한 경우에는 빈 재작성 결과를 반환합니다:

- "감사합니다!"
- "알겠습니다, 도움이 되었어요."
- "방금 말씀하신 내용을 요약해 주세요."

검색 게이트가 작동하면 파이프라인의 나머지 단계(임베딩 → 벡터 검색 → 재순위)가 모두 건너뛰어지고, AI가 대화 맥락만으로 직접 응답합니다. 덕분에 불필요한 검색 비용과 응답 지연이 줄어듭니다.
