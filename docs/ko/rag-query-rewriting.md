# 쿼리 재작성

## 왜 쿼리 재작성이 필요한가?

멀티턴 대화에서 사용자는 자연스럽게 대명사와 짧은 참조를 사용합니다:

> 사용자: "환불 정책에 대해 알려주세요."
> 사용자: "**그것**의 예외는 무엇인가요?"

"그것의 예외는 무엇인가요?"를 벡터 스토어에 그대로 보내면, 임베딩은 "그것"이 무엇을 가리키는지 알 수 없습니다. 검색 결과가 부정확해지고 답변 품질이 저하됩니다.

**쿼리 재작성**은 검색 전에 이런 참조를 해석하여 "그것" → "환불 정책 예외"로 확장합니다. 임베딩이 전체 의도를 정확히 포착할 수 있게 됩니다. 또한 **검색 게이트**를 구현하여, "감사합니다!"처럼 검색이 필요 없는 쿼리에서는 벡터 검색을 건너뛰어 지연 시간과 비용을 절약합니다.

## 설정

`LlmQueryRewriter`는 임베딩 전에 AI 서비스 자체를 사용해 쿼리를 재작성합니다:

```csharp
.WithRag(rag => rag
    .WithQueryRewriter()             // 동일한 AI 서비스 사용
    .WithQueryRewriteMaxTokens(250)  // 재작성을 위한 토큰 예산
    .AddDocument("docs.txt")
)
```

재작성기는 대화 맥락을 분석하고, 벡터 스토어가 기록 없이도 이해할 수 있는 독립적인 검색 쿼리를 생성합니다.

## 멀티턴 RAG

`RagStore`를 직접 쿼리할 때는 대화 기록을 전달하여 재작성기가 참조를 해석할 수 있게 합니다:

```csharp
var history = new List<ConversationTurn>
{
    new ConversationTurn("환불 정책이 무엇인가요?", "30일 이내에 반품할 수 있습니다."),
    new ConversationTurn("디지털 제품은요?", "디지털 제품은 환불이 불가합니다.")
};

var result = await store.QueryAsync(
    query: "거기에 예외가 있나요?",
    conversationHistory: history
);
```

재작성기가 전체 기록을 보고 "거기에 예외가 있나요?"를 "디지털 제품 환불 불가 정책의 예외"와 같이 재작성하여 훨씬 더 나은 검색 결과를 제공합니다.

## 검색 게이트의 동작 방식

모든 사용자 메시지가 문서 검색을 필요로 하는 것은 아닙니다. 재작성기는 쿼리를 분류하고 다음과 같은 메시지에 대해 빈 재작성 결과를 반환합니다:

- "감사합니다!"
- "알겠습니다, 도움이 되었어요."
- "방금 말씀하신 내용을 요약해 주세요."

게이트가 작동하면 전체 검색 파이프라인 — 임베딩, 벡터 검색, 재순위 — 이 모두 건너뛰어지고, LLM이 대화 맥락에서 직접 응답합니다.
