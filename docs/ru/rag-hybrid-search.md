# Гибридный поиск

> 📍 **Пайплайн вопрос-ответ:** [Переписывание запросов](rag-query-rewriting.md) → Эмбеддинг → Фильтрация → **`Поиск`** → [Переранжирование](rag-reranking.md) → Построение контекста

## Зачем нужен гибридный поиск

Чистый векторный поиск отлично справляется с семантическим сопоставлением — запрос «отменить подписку» совпадёт с «прекратить членство», даже если слова не пересекаются. Однако он может пропустить **точные термины** — названия продуктов, коды ошибок или идентификаторы, которые пользователь вводит дословно.

Ключевой поиск BM25 прекрасно обрабатывает такие случаи, но не понимает семантики. **Гибридный поиск объединяет оба подхода**, давая лучшее из двух миров: семантическое понимание плюс точное совпадение по ключевым словам.

## Настройка

Объедините плотный векторный поиск с ключевым поиском BM25 одним вызовом метода:

```csharp
.WithRag(rag => rag
    .UseHybridSearch(vectorWeight: 0.6f)  // 60% вектор, 40% BM25
    .AddDocument("knowledge-base.txt")
)
```

`vectorWeight` принимает значения от 0.0 (чистый BM25) до 1.0 (чистый вектор). Значение в диапазоне **0.5–0.7** подходит для большинства задач.

## Рекомендации по выбору

| Сценарий | Рекомендуемый вес |
| --- | --- |
| Общие вопросы на естественном языке | 0.7–0.8 (больше вектора) |
| Техническая документация с конкретными терминами | 0.4–0.5 (сбалансированный) |
| Поиск кода или кодов ошибок | 0.2–0.3 (больше BM25) |

## Пример

```csharp
var service = new OpenAIService(apiKey, http)
    .WithRag(rag => rag
        .UseHybridSearch(vectorWeight: 0.5f)
        .AddDocument("product-catalog.txt")
        .AddDocument("error-codes.txt")
    );

// "ERR-4012" сопоставляется через BM25; семантический контекст — через вектор
var answer = await service.GetCompletionAsync("How do I fix ERR-4012?");
```
