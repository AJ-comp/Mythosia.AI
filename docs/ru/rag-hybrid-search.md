# Гибридный поиск

Коды товаров удобно искать по словам, а вопросы с другой формулировкой — по смыслу. Выбранный компонент готовит только нужное представление: лексический поиск больше не требует предварительного эмбеддинга запроса.

## Встроенные режимы

```csharp
// Семантический поиск (по умолчанию)
.UseVectorSearch()

// Лексический поиск без эмбеддинга запроса
.UseKeywordSearch()

// Взвешенный гибридный поиск
.UseHybridSearch(new HybridSearchOptions
{
    VectorWeight = 0.7f,
    CandidateMultiplier = 4,
    RrfK = 60
})
```

`HybridSearchOptions`: `using Mythosia.VectorDb;`

`UseKeywordSearch()` пропускает эмбеддинг запроса. При загрузке документы по-прежнему разбиваются и векторизуются для существующего хранилища; это не чисто текстовая индексация. При отложенной инициализации первая операция может вызвать эмбеддинги документов.

## Объединение лексических и семантических результатов

`VectorWeight` задаёт вес векторного поиска (0–1), `1 - VectorWeight` — лексического. `CandidateMultiplier` управляет кандидатами каждой ветви, `RrfK` — сглаживанием рангов во взвешенном Reciprocal Rank Fusion. Это отдельные настройки от множителя RAG-переранжировщика. Проверяйте их на своих документах и вопросах.

Чистые векторный и лексический режимы сохраняют исходные оценки. Настраиваемый гибрид использует нормализованный взвешенный RRF даже с одной ветвью; вес вектора 0 исключает эмбеддинг запроса. Оценки не являются вероятностями. `WeightedBlend` смешивает оценки поиска и переранжирования без калибровки; для некалиброванного лексического поиска предпочтителен `RerankerOnly`.

```csharp
using Mythosia.AI.Rag;
using Mythosia.VectorDb;

var service = new OpenAIService(apiKey, http)
    .WithRag(rag => rag
        .AddDocument("manual.txt")
        .UseHybridSearch(new HybridSearchOptions
        {
            VectorWeight = 0.7f,
            CandidateMultiplier = 4,
            RrfK = 60
        }));

string answer = await service.GetCompletionAsync("What is the refund policy?");
```

## Поддержка хранилищ и совместимость

InMemory, PostgreSQL и Qdrant поддерживают новый лексический поиск и настраиваемый взвешенный RRF. Текстовые оценки различаются: BM25 в InMemory, настроенный полнотекстовый или триграммный поиск в PostgreSQL, разреженный индекс в Qdrant. Оценки разных движков не равнозначны.

Pinecone сохраняет нативный гибридный путь через `UseHybridSearch()` с настройками по умолчанию на совместимом индексе `dotproduct`. Этот адаптер не поддерживает лексический режим и настраиваемый взвешенный RRF с обеими ветвями. Другим хранилищам нужны соответствующие дополнительные интерфейсы. Неподдерживаемые режимы и настройки явно вызывают ошибку, без скрытого перехода к векторному поиску и игнорирования весов.

Существующие адаптеры InMemory, PostgreSQL и Qdrant не устанавливают нейронную модель и не переносят индексы. Различение `C#` и `C++` зависит от анализатора. Для варианта PIXIE ниже также требуется проверка точного поиска идентификаторов.

См. [режимы и поддержку хранилищ](rag.md#retrieval-modes) и [собственные компоненты поиска](rag-pipeline.md#custom-retriever).

## Сравнение локального нейронного поиска с PIXIE

Если вопрос и документ сформулированы по-разному, обученный разреженный поиск может добавить связанные слова. Необязательный пакет `Mythosia.AI.Rag.Search.Pixie` локально кодирует документы и запросы с помощью PIXIE и объединяет результаты с существующими плотными эмбеддингами. Для PIXIE не нужны сервер Python и ключ API; выбранные поставщики плотных эмбеддингов и ответов всё ещё могут обращаться к внешнему API.

```csharp
using Mythosia.AI.Rag;
using Mythosia.AI.Rag.Search.Pixie;
using Mythosia.VectorDb;

using var encoder = new PixieSparseEncoder(new PixieOptions());
var searchStore = new PixieInMemoryStore(encoder);
RagStore rag = await RagStore.BuildAsync(builder => builder
    .UseEmbedding(embeddings)
    .UseStore(searchStore)
    .AddDocument("manual.txt")
    .UseHybridSearch(new HybridSearchOptions { VectorWeight = 0.7f }));

RagProcessedQuery result = await rag.QueryAsync("refund policy");
```

С этим хранилищем `UseKeywordSearch()` выбирает нейронный разреженный поиск: плотный эмбеддинг запроса не создаётся, но PIXIE обрабатывает вопрос. Загрузка документов RAG по-прежнему создаёт плотные эмбеддинги. `UseHybridSearch(...)` объединяет ранги разреженного скалярного произведения и плотного косинусного сходства настроенным взвешенным RRF.

Предварительная версия предоставляет `PixieInMemoryStore` с индексом в памяти. Подключение PIXIE к PostgreSQL, Qdrant и Pinecone не добавляется. После перезапуска или изменения модели/настроек перестройте индекс. Сохраняйте кодировщик до завершения всех операций и затем освободите его. Прежний поиск остаётся стандартным: сравните одинаковые документы и запросы с размеченной релевантностью перед переходом. PIXIE не гарантирует точное различение `C#`/`C++` или выполнение условий исключения.
