# Переписывание запросов

> 📍 **Пайплайн вопрос-ответ:** **`Переписывание запросов`** → Фильтрация → Эмбеддинг (при необходимости) → [Поиск](rag-hybrid-search.md) → [Переранжирование](rag-reranking.md) → Построение контекста

Этап запроса `Embedding` зависит от компонента; лексический поиск его не сообщает. Собственный компонент может сообщать этапы через `request.ProgressAsync`. Эмбеддинги документов не меняются.

## Зачем нужно переписывание

В многошаговом диалоге пользователи часто используют местоимения и краткие ссылки:

> Пользователь: «Расскажи о политике возврата.»
> Пользователь: «А какие есть исключения из **неё**?»

Если запрос «А какие есть исключения из неё?» отправить в векторное хранилище как есть, эмбеддинг не поймёт, к чему относится «неё». Поиск вернёт нерелевантные результаты, и качество ответа пострадает.

**Переписывание запросов** разрешает подобные ссылки перед поиском, разворачивая «неё» → «исключения из политики возврата», чтобы эмбеддинг уловил полный смысл. Кроме того, реализован механизм **шлюза поиска** — если запрос не требует обращения к базе (например, «Спасибо!»), поиск пропускается полностью, что экономит время и ресурсы.

## Настройка

`LlmQueryRewriter` использует тот же AI-сервис для переписывания запроса перед эмбеддингом:

```csharp
.WithRag(rag => rag
    .WithQueryRewriter(250)          // Использует тот же AI-сервис
    .AddDocument("docs.txt")
)
```

Переписывающий модуль анализирует контекст диалога и формирует самодостаточный поисковый запрос, который векторное хранилище может понять без истории беседы.

## Многошаговый RAG

При прямом запросе к `RagStore` передавайте историю диалога, чтобы переписывающий модуль мог разрешить ссылки:

```csharp
var history = new List<ConversationTurn>
{
    new ConversationTurn("What is the refund policy?", "You can return items within 30 days."),
    new ConversationTurn("What about digital products?", "Digital products are non-refundable.")
};

var result = await store.QueryAsync(
    query: "Are there any exceptions to that?",
    conversationHistory: history
);
```

Модуль видит полную историю и переписывает «Are there any exceptions to that?» во что-то вроде «exceptions to the digital product non-refundable policy», что значительно улучшает результаты поиска.

## Изменение переписывания при обработке запросов

Чтобы временно отключить переписывание или сменить его реализацию без перестроения индекса, используйте `store.SetQueryRewriter(null)` или `store.SetQueryRewriter(rewriter)`. Прямой вызов перегрузки `RagStore.QueryAsync`, принимающей `conversationHistory`, сохраняет выбранный переписыватель в начале запроса. Если отключить или заменить его во время ожидания уведомления о ходе выполнения или переписывания, текущий запрос продолжит использовать тот же экземпляр; следующие запросы используют новую настройку. Это относится к прямым запросам к хранилищу и не обновляет переписыватель, уже сохранённый обёрткой `RagEnabledService`.

## Как работает шлюз поиска

Не каждое сообщение пользователя требует обращения к документам. Переписывающий модуль классифицирует запрос и возвращает пустой результат для сообщений вроде:

- «Спасибо!»
- «Понял, это полезно.»
- «Можешь подытожить то, что только что сказал?»

Когда шлюз срабатывает, весь пайплайн извлечения пропускается — ни эмбеддинга, ни векторного поиска, ни переранжирования — и LLM отвечает напрямую из контекста диалога.
