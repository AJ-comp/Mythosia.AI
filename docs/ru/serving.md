# Управление работающими серверами моделей

Перед отправкой запроса интерфейсу выбора моделей или панели эксплуатации нужны сведения о состоянии сервера, доступных моделях и их загрузке. Пакеты Serving объединяют эти проверки для Ollama, llama.cpp и vLLM, оставляя специфические операции явными.

Используйте их для заполнения списка выбора моделей, отображения доступности сервера, управления пребыванием моделей в памяти, если среда это поддерживает, или чтения метрик движка. При смене среды выполнения общий код проверок приложения может остаться прежним.

Эти клиенты подключаются к существующему HTTP-серверу. Установка и размещение движка, аренда GPU, чат и генерация эмбеддингов относятся к отдельным компонентам. Чат по-прежнему выполняется через соответствующий сервис ИИ, например `QwenService` для vLLM; провайдеры эмбеддингов RAG остаются отдельными. Обнаружение не загружает модели автоматически. SGLang не реализован.

## Получение сведений без изменения состояния

Установите конкретный пакет своей среды. Пример использует Ollama; для других серверов выберите `VllmServer` или `LlamaCppServer` из соответствующего пространства имён. Обнаружение выполняет только запросы чтения, без команд загрузки в память, генерации или скачивания.

```bash
dotnet add package Mythosia.AI.Serving.Ollama --version 1.0.0
```

```csharp
using System;
using System.Net.Http;
using System.Threading;
using Mythosia.AI.Serving;
using Mythosia.AI.Serving.Ollama;

using var http = new HttpClient { Timeout = TimeSpan.FromMinutes(10) };
using var cancellation = new CancellationTokenSource();
IModelServer server = new OllamaServer("http://localhost:11434", http,
    apiKey: Environment.GetEnvironmentVariable("MODEL_SERVER_API_KEY"));

var health = await server.GetHealthAsync(cancellation.Token);
var info = await server.GetInfoAsync(cancellation.Token);
var capabilities = await server.GetCapabilitiesAsync(cancellation.Token);
var models = await server.GetModelsAsync(cancellation.Token);

foreach (var model in models)
    Console.WriteLine($"{model.Id}: {model.InstallationState} / {model.LoadState}");
```

Конечная точка — корень сервера, при необходимости с префиксом пути обратного прокси. Необязательный ключ API передаётся в каждом запросе как учётные данные Bearer. Клиент не изменяет `HttpClient.DefaultRequestHeaders` и не освобождает переданный `HttpClient`; повторно используйте и освобождайте его в соответствии с жизненным циклом приложения. В этом примере Ollama тайм-аут распространяется и на потоковое чтение тела ответа, поэтому предусмотрите достаточно времени для скачивания модели.

## Общие и дополнительные контракты

| Контракт | Назначение |
| --- | --- |
| `IModelServer` | Информация, состояние, модели и наблюдаемые возможности сервера. |
| `IModelLifecycle` | Явные команды загрузки в память и выгрузки; дополнительный интерфейс. |
| `IModelDownloader` | Явное скачивание с прогрессом; дополнительный интерфейс. |
| `IModelMetricsProvider` | Измерения метрик с метками; дополнительный интерфейс. |

Реализация интерфейса означает наличие операции у клиента; `ServingCapabilities` описывает подтверждённые возможности подключённой точки доступа. `Supported` не гарантирует права или успех для каждой модели. `Unsupported` означает недоступность в наблюдаемом режиме или endpoint. `Unknown` означает нехватку данных, в том числе при ошибках авторизации или связи; это не равнозначно отсутствию поддержки.

`InstallationState` и `LoadState` отражают разные наблюдения. `Unknown` не означает отсутствие модели или выгрузку. Непереданные `SizeBytes`, `MemoryBytes` и `ContextLength` остаются `null`, а не нулём. Исправность API управления не доказывает готовность конкретной модели к инференсу.

## Различия сред выполнения

| Операция | Ollama | llama.cpp, одна модель | llama.cpp Router | vLLM |
| --- | --- | --- | --- | --- |
| Информация, состояние и список моделей | Да | Да | Да | Да |
| Явная загрузка в память / выгрузка | Да, с помощью пустых запросов генерации | Не поддерживается | Да, после подтверждения режима Router | Не поддерживается этим клиентом |
| Скачивание модели | Да, с потоковым прогрессом | Не поддерживается | Явная операция; нужны конечная точка скачивания и события SSE | Не поддерживается этим клиентом |
| Метрики | Не реализованы | Метрики сервера, если включены | Специализированная перегрузка для модели; модель уже должна быть загружена | Метрики сервера, если доступны |

Таблица описывает операции клиентов и не обещает их поддержку для каждой версии сервера, набора разрешений или модели. Проверяйте возможности подключённой конечной точки и обрабатывайте ошибки операций.

**Ollama:** `/api/tags` возвращает зарегистрированные модели, `/api/ps` — выполняющиеся. Удалённая модель может быть зарегистрирована без локальных весов; при отсутствии локального процесса состояние загрузки остаётся неизвестным. Предзагрузка использует пустой запрос `/api/generate` и стандартный keep-alive сервера. Модели только для эмбеддингов не перенаправляются на другой API. Выгрузка использует `keep_alive: 0`, не удаляя файлы. Метрики не реализованы.

**llama.cpp:** перед командами жизненного цикла или скачивания `/props` должен явно подтвердить режим маршрутизатора. Режим одной модели не поддерживает эти команды и сохраняет наблюдаемое состояние сна. Скачивание в маршрутизаторе сначала подписывается на `/models/sse`, затем отправляет `POST /models` и завершается успешно только по событию `download_finished` целевой модели. Сама доступность SSE оставляет возможность скачивания неизвестной. Общесерверные метрики относятся к режиму одной модели; для маршрутизатора нужна конкретная перегрузка `GetMetricsAsync(modelId, token)`, отправляющая `autoload=false`, чтобы проверка не загружала модель.

**vLLM:** сохраняются обслуживаемые псевдонимы и необязательное поле `root`, но общие состояния установки и загрузки остаются неизвестными. Списки моделей и метрики проверяются по фактическим ответам; жизненный цикл и скачивание не поддерживаются. Прежние методы и DTO `VllmServer` доступны через конкретный клиент, общие методы состояния, моделей и метрик — через явно реализованные интерфейсы.

## Явный запуск операции управления

Скачивание и изменение пребывания модели в памяти расходуют сетевой трафик, дисковое пространство или память устройства. Выполняйте их, когда это нужно приложению. Продолжение примера Ollama ниже скачивает небольшую модель и ненадолго загружает её, чтобы проверить состояние. Используйте точные идентификаторы моделей сервера, включая тег Ollama или тег квантования llama.cpp.

```csharp
if (server is IModelDownloader downloader &&
    capabilities.ModelDownloading == ServingFeatureSupport.Supported)
{
    var progress = new Progress<ModelDownloadProgress>(p =>
        Console.WriteLine($"{p.ModelId}: {p.Stage} {p.CompletedBytes}/{p.TotalBytes}"));
    await downloader.DownloadModelAsync("qwen2.5:0.5b", progress, cancellation.Token);
}

if (server is IModelLifecycle lifecycle &&
    capabilities.ModelLoading == ServingFeatureSupport.Supported &&
    capabilities.ModelUnloading == ServingFeatureSupport.Supported)
{
    try
    {
        await lifecycle.LoadModelAsync("qwen2.5:0.5b", cancellation.Token);
        var afterLoad = await server.GetModelsAsync(cancellation.Token);
        foreach (var model in afterLoad)
            Console.WriteLine($"{model.Id}: {model.LoadState}");
    }
    finally
    {
        using var cleanup = new CancellationTokenSource(TimeSpan.FromSeconds(30));
        await lifecycle.UnloadModelAsync("qwen2.5:0.5b", cleanup.Token);
    }
}
```

В примере используется отдельная тестовая модель, которая затем выгружается. Рабочее приложение само определяет, когда освобождать модель; не выгружайте модель, ещё используемую другими запросами. Очистка имеет собственный срок ожидания и может завершиться ошибкой, если сервер недоступен.

Прогресс относится к отдельному артефакту или этапу. Отсутствующие счётчики байтов — не ноль и не процент всей модели. Успешный вызов загрузки подтверждает команду, а не готовность модели или бессрочное пребывание в памяти; если готовность важна, наблюдайте `LoadState` с ограниченным временем ожидания. Протокол скачивания Router в llama.cpp и ограничения версий описаны в руководстве конкретного пакета. Явно запрошенную операцию можно попытаться выполнить при поддержке `Unknown`, предварительно проверив конфигурацию сервера; само обнаружение возможностей её никогда не запускает.

## Отмена и ошибки

Передавайте токен отмены запросам и командам. Отмена прекращает HTTP-работу и ожидание этого клиента, но не гарантирует удалённую отмену, откат или удаление скачанных слоёв. Настройте передаваемый `HttpClient` с учётом длительности операции; клиенты не принимают его во владение.

Сохраняйте метки метрик при сравнении моделей и движков. Отсутствующая метрика — не ноль; значения могут включать `NaN` и бесконечность. Общий тип ошибки — `ServingException`; общие ошибки управления не содержат исходных тел ответов и учётных данных. Старые вызовы vLLM сохраняют прежние подробности ошибок.

`GetHealthAsync` представляет сбои конечной точки как состояния работоспособности, но по-прежнему передаёт отмену вызывающего кода. Другие операции могут выбрасывать `ServingException`, а заведомо неподдерживаемый режим llama.cpp — `NotSupportedException`. Ни тайм-аут, ни неудачный запрос не доказывают откат удалённого действия. Метод скачивания завершается успешно только после сообщения среды о завершении: терминального успеха с последующим EOF для Ollama или соответствующего события `download_finished` для llama.cpp Router.

## Что проверено

Автономные тесты охватывают контролируемый успех, некорректные ответы, ошибки и отмену. Отдельные проверки на реальных серверах выполнялись с одной NVIDIA A40, небольшими общедоступными моделями Qwen и следующими сборками движков:

| Среда выполнения | Проверенная модель | Проверенные операции управления |
| --- | --- | --- |
| Ollama 0.34.4 | `qwen2.5:0.5b` | Обнаружение, скачивание без локальной копии, загрузка/выгрузка, ошибки отсутствующей модели без чувствительных данных, предварительная отмена и отмена после частичного прогресса скачивания. |
| llama.cpp b11146, Router | `Qwen/Qwen2.5-0.5B-Instruct-GGUF:Q4_K_M` | Обнаружение, события скачивания, загрузка/выгрузка, метрики модели без автозагрузки, ошибки и отмена скачивания. |
| llama.cpp b11146, одна модель | Та же модель GGUF | Обнаружение, метрики сервера, отмена и явное отклонение команд жизненного цикла Router. |
| vLLM 0.30.0 | `Qwen/Qwen2.5-0.5B-Instruct` | Обнаружение, метрики сервера и предварительная отмена. |

Короткие нативные HTTP-запросы инференса также вернули сгенерированный текст во всех четырёх конфигурациях. Эти запросы подтверждают работу движков, но не чат-адаптеры сервисов ИИ, качество моделей, пропускную способность или совместимость со всеми сборками движков. Профили выше — проверенные конфигурации, а не минимальные поддерживаемые версии. Для проверки отмены скачивания использовались отдельные более крупные тестовые модели; удалённый откат не утверждался. Первое скачивание Ollama завершилось ошибкой; повторная попытка и новое скачивание после удаления модели прошли, но точная причина первого сбоя установлена не была.

Используйте [руководство по явно включаемой проверке на реальном сервере](https://github.com/AJ-comp/Mythosia.AI/blob/main/tests/Mythosia.AI.Serving.Live/README.md), чтобы проверить развёрнутую конечную точку. Оно различает включённый в репозиторий инструмент проверки управления и дополнительные пробы инференса и отмены, использованные при проверке. Подробные отчёты о выполнении остаются вне опубликованной документации.
