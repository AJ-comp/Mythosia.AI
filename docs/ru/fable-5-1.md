# Как наблюдать за длительными задачами Claude Fable 5.1

[Claude Opus 5.5](providers.md#claude-opus-55) доступен с Mythosia.AI 8.1.0 / Abstractions 4.1.0: мышление всегда активно, усилие по умолчанию medium, отображение скрыто. Читаемый прогресс нужно запросить явно; значения по умолчанию и привязка к модели отличаются от Fable 5.1.

> Настройки Fable 5.1 требуют `Mythosia.AI` 8.0.0 и `Mythosia.AI.Abstractions` 4.0.0 или новее. Для существующих API Run, рассуждений, поиска и GPT-6 Astra минимальные версии остаются 7.1.0 / 3.1.0.

## Зачем нужны эти настройки?

Исследование документов может потребовать нескольких поисков и вызовов инструментов, прежде чем появится ответ. Приложению бывает нужно показать ход работы, потребовать проверку только для текущего хода или продолжить разговор после изменения прежних сообщений. Fable 5.1 предоставляет соответствующие настройки, но при сохранении рассуждений сама история разговора становится частью контракта запроса.

Используйте [Run API](execution-api-transition.md) для наблюдения и отмены задачи, [общие настройки рассуждений и поиска](reasoning-and-search.md) для выбора усилия и источников, а настройки Claude ниже — для сообщений о ходе работы и обработки истории. Наличие функции у модели не означает, что Mythosia предоставляет каждый API поставщика.

## Явно выберите модель и уровень усилия

```csharp
using Mythosia.AI.Models;
using Mythosia.AI.Services.Anthropic;

var service = new AnthropicService(apiKey, httpClient);
service.ChangeModel(AIModels.Anthropic.ClaudeFable5_1);
service.WithAdaptiveThinkingParameters(ClaudeReasoningEffort.High);

string answer = await service.GetCompletionAsync("Проверьте этот план миграции.");
```

`ClaudeFable5_1` выбирает `claude-fable-5-1`. `ClaudeMythos5_1` выбирает `claude-mythos-5-1` и требует доступа Project Glasswing. Прежние константы Fable 5 и Mythos 5 остаются доступными. Обе модели 5.1 принимают текст и изображения и возвращают текст; окно контекста составляет 1 млн токенов, максимальный вывод — 128 тыс. токенов. [Обзор моделей](https://platform.claude.com/docs/en/models/fable-5-1/overview).

У самой модели effort по умолчанию равен `high`. Mythosia сохраняет прежнее преобразование `ThinkingBudget` при `ClaudeReasoningEffort.Auto`: включённый бюджет соответствует `High`, от 32 768 — `XHigh`, от 100 000 — `Max`. Запрос на отключение рассуждений выражается через низкое адаптивное усилие без читаемого текста рассуждений. Если нужен `High`, укажите его явно: `Auto` не означает, что библиотека всегда опускает effort и полагается на значение модели по умолчанию.

## Показывайте ход работы между вызовами инструментов

`ClaudeThinkingDisplay.Updates` запрашивает понятные сообщения о ходе работы, скрывая рассуждения. `Summarized` также включает краткое изложение рассуждений, а `Omitted` исключает читаемые блоки thinking. Сообщения появляются, только когда модель их создаёт; фиксированная периодичность не гарантируется. [Сообщения о ходе работы](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1#progress-updates-between-tool-calls-beta).

```csharp
using Mythosia.AI.Models.Streaming;

service.WithAdaptiveThinkingParameters(
    ClaudeReasoningEffort.High, ClaudeThinkingDisplay.Updates);

await using var run = await service.StartRunAsync(
    "Исследуйте отчёт с помощью зарегистрированных инструментов.",
    options: StreamOptions.FullOptions);

await foreach (var item in run.StreamAsync())
{
    if (item.Type == StreamingContentType.Reasoning)
        Console.WriteLine($"Ход работы: {item.Content}");
    else if (item.Type == StreamingContentType.Text)
        Console.Write(item.Content);
}
string result = (await run.Result).Text;
```

Сообщения передаются через существующее событие `StreamingContentType.Reasoning`. Включите его получение через `StreamOptions.FullOptions` или `StreamOptions.Default.WithReasoning()`. При обычном, непотоковом запросе прочитайте `service.LastThinkingContent` после завершения вызова. Текст о ходе работы отделён от итогового ответа и не раскрывает исходную цепочку рассуждений.

## Добавляйте указания для хода, сохраняя прежнюю историю

Блоки thinking в Fable 5.1 привязаны к системному промпту, инструментам и предшествующим сообщениям, на основе которых они были созданы. Изменение этих данных при сохранении последующих рассуждений может сделать их недействительными. Указание на один ход полезно, например, когда перед текущим ответом нужно проверить правила поддержки: оно добавляется в историю и остаётся там, но перестаёт действовать после следующего пользовательского сообщения. Переписывать верхнеуровневый системный промпт при каждом запросе не требуется. Изменение effort и добавление указаний — разные настройки.

```csharp
await service
    .WithTurnInstruction("Перед этим ответом проверьте правила через зарегистрированный инструмент поддержки.")
    .GetCompletionAsync("Можно ли вернуть распакованный товар?");

await service
    .WithConversationInstruction("До конца разговора отвечайте по-русски.")
    .GetCompletionAsync("Объясните следующий шаг.");
```

Оба метода фиксируют указания для следующего логического запроса. Mythosia добавляет системное сообщение после пользовательского ввода или результатов инструментов, сохраняя прежние сообщения. `WithTurnInstruction` использует `clear_at: "next_user_message"`; внутри одного логического запроса указание повторно добавляется после каждого хода с результатами инструментов, чтобы действовать до завершения запроса. `WithConversationInstruction` действует и в последующих ходах. Вызывайте эти методы до начала работы: они не заменяют `run.SteerAsync` и не вводят указание в уже выполняющийся ответ.

Для изменения effort между запросами с сохранением подходящего префикса кеша используйте `.WithReasoning(ReasoningLevel.High, cache: CachePreservation.Required)` из `Mythosia.AI.Extensions`. Библиотека отправляет обновление effort на уровне сообщения и сохраняет его в истории. Поддерживаемые сочетания описаны в [общем руководстве](reasoning-and-search.md). В 5.1 системные префиксы и суффиксы запроса из `AIRequestContext` превращаются в добавляемые указания на один ход, сохраняя прежний системный промпт.

Fable 5.1 может читать рассуждения прежних моделей Claude, но прежние модели не могут читать её рассуждения. Mythos 5.1 предоставляет те же возможности 5.1, однако не применяет обязательную проверку привязки префикса Fable. При изменении истории, переключении модели или удалении thinking проверяйте результат обработки, не предполагая, что прежние рассуждения сохранились. [Руководство по миграции](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide).

## Диагностируйте намеренные изменения истории

`ThinkingPrefixMismatchBehavior = null` оставляет проверку на усмотрение политики учётной записи поставщика. `WithThinkingBinding(ClaudeThinkingPrefixMismatchBehavior.Error)` явно запрашивает серверную проверку. Изменения истории, `SystemMessage` или инструментов, сделанные пользователем, передаются Anthropic; несовпадение префикса при `Error` приводит к ответу сервера 400. Повтор того же некорректного запроса проблему не устраняет.

Если приложение намеренно меняет прежние данные и допускает потерю связанных рассуждений, выберите `DropBlock`. Mythosia передаёт эту настройку Anthropic, не удаляя thinking незаметно перед отправкой.

```csharp
service.WithThinkingBinding(ClaudeThinkingPrefixMismatchBehavior.DropBlock);
service.SystemMessage = "Вы проверяете обновлённые правила.";
await service.GetCompletionAsync("Пересмотрите рекомендацию.");

foreach (ClaudeInputTransformation change in service.LastInputTransformations)
    Console.WriteLine($"{change.Type}: {change.Reason} ({change.Model})");
```

`LastInputTransformations` предоставляет полученные от поставщика `Type`, `Path` и `Reason`, а также `ResponseId` и `Model` для определения источника. `prefix_binding_mismatch` означает изменение префикса, `model_binding_mismatch` — невозможность целевой модели прочитать thinking. Удаление означает потерю рассуждений, а не их восстановление. Если требуется сохранение, оставляйте историю неизменной; для сброса начинайте новый разговор.

Mythosia сохраняет переданную историю, чтобы внутренняя обработка RAG и контекста не меняла её случайно. Для обычного разговора Fable 5.1 автоматическое локальное сжатие блокируется при настройке по умолчанию и `Error`. `DropBlock` разрешает сжатие, но рассуждения могут быть отброшены; попадание в кеш не гарантируется. Отдельная настройка `CachePreservation.Required` сохраняет более строгую защиту истории.

Снимки переданной истории привязаны к экземпляру сервиса и `ChatBlock`. Продолжайте такой разговор с теми же экземплярами: копирование только исходного `ChatBlock` в новый сервис не переносит прежние добавления RAG, контекста и системных указаний. При таком переносе не рассчитывайте на сохранение префикса; начните новый разговор, если полной переданной истории нет.

Общие настройки вроде `WithWebSearch` по-прежнему действуют на один запрос. Если не повторить их в следующем ходе, верхнеуровневый список `tools` может измениться и вызвать ошибку привязки префикса. Для продолжения с сохранёнными рассуждениями применяйте те же настройки инструментов; для намеренного изменения выбирайте `DropBlock` или новый разговор.

## Используйте обычный выбор инструментов

Fable 5.1 и Mythos 5.1 отклоняют принудительный выбор инструмента. Оставьте `ForceFunctionName` незаданным и объясните в запросе, когда следует использовать зарегистрированный инструмент. Если в данном ходе инструменты вызывать нельзя, используйте `FunctionsDisabled`. Для типизированного ответа используйте существующий API структурированного вывода вместо принудительного вызова функции только ради JSON.

## Учитывайте изменения, которыми управляет сервер

| Нативная настройка | Необходимый Anthropic beta |
| --- | --- |
| Effort на уровне сообщения | `mid-conversation-output-config-2026-07-01` |
| Системное сообщение на один ход | `mid-conversation-system-clear-at-2026-08-21` |
| `thinking.display: "updates"` | `thinking-display-updates-2026-08-18` |
| Привязка thinking и `input_transformations` | `thinking-binding-controls-2026-08-01` |

Mythosia добавляет нужный заголовок при включении соответствующей поддерживаемой настройки. Включение одной beta не включает остальные. Эта интеграция не добавляет серверное сжатие, нативные блоки добавления и удаления инструментов или автоматический переход на другую модель.

Обе модели требуют предусмотренных поставщиком условий хранения в течение 30 дней; ZDR требует явного разрешения Anthropic. Адаптивное рассуждение включено постоянно, ручной `budget_tokens` и отключение thinking недоступны, пользовательские параметры сэмплирования не отправляются. Доступ и условия хранения проверяет сервер. [Требования миграции](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide).

Текстовые водяные знаки, сведения о происхождении поддерживаемых медиа и цены чтения из кеша применяет Anthropic. Новая настройка запроса Mythosia для них не требуется. Интеграция не добавляет API создания сведений о происхождении медиа, переключатель водяных знаков или управление тарификацией. См. [изменения Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1).
