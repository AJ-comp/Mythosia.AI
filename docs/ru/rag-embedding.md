# Эмбеддинг

> 📍 **Пайплайн вопрос-ответ:** [Переписывание запросов](rag-query-rewriting.md) → [Фильтрация](rag-filtering.md) → **`Эмбеддинг (при необходимости)`** → [Поиск](rag-hybrid-search.md) → [Переранжирование](rag-reranking.md) → [Построение контекста](rag-context-build.md)

Этап запроса `Embedding` зависит от компонента; лексический поиск его не сообщает. Собственный компонент может сообщать этапы через `request.ProgressAsync`. Эмбеддинги документов не меняются.

## Что такое эмбеддинг?

Эмбеддинг — это процесс преобразования текста в **числовые векторы** (массивы чисел), которые отражают смысл. В этом векторном пространстве **тексты с похожим значением оказываются рядом друг с другом**.

Представьте города на карте: географически близкие города расположены рядом. Точно так же фразы «Как отменить подписку?» и «Хочу прекратить членство» порождают близкие векторы — несмотря на разные слова.

В RAG-пайплайне эмбеддинг используется дважды:

1. **Индексация документов** — каждый чанк векторизуется и сохраняется в хранилище
2. **На этапе запроса** — вопрос пользователя векторизуется для поиска по сходству

Эта страница посвящена эмбеддингу запроса (шаг 2).

## Встроенные провайдеры

Выбирайте провайдера эмбеддингов с учётом языка документов, размещения и требований к поиску.

### Perplexity

Стандартные эмбеддинги обрабатывают фрагменты независимо и реализуют `IEmbeddingProvider` для существующего RAG-построителя. Контекстные сохраняют порядок соседних фрагментов и группы документов. Отдельный API предотвращает объединение несвязанных документов в плоский вход.

[Perplexity Agent API, поиск и эмбеддинги](perplexity.md).

### OpenAI

```csharp
var embedder = new OpenAIEmbeddingProvider(
    apiKey: "sk-...",
    httpClient: new HttpClient(),
    model: "text-embedding-3-small",
    dimensions: 1536
);
```

Краткая форма через билдер:

```csharp
.WithRag(rag => rag
    .UseOpenAIEmbedding(apiKey, model: "text-embedding-3-small", dimensions: 1536)
    .AddDocument("docs.txt")
)
```

<a id="openai-dimensions"></a>

`text-embedding-ada-002` имеет фиксированную размерность **1536**. Провайдер не передаёт неподдерживаемое поле `dimensions` в одиночных и пакетных запросах; при настройке другой размерности возникает `ArgumentOutOfRangeException` до вызова API. Для `text-embedding-3-small` и `text-embedding-3-large` запросы по-прежнему содержат настроенное значение `dimensions`.

### Ollama (локально)

Запуск эмбеддингов локально через [Ollama](https://ollama.com/):

```csharp
var embedder = new OllamaEmbeddingProvider(
    httpClient: new HttpClient(),
    model: "qwen3-embedding:4b",
    dimensions: 1024,
    baseUrl: "http://localhost:11434"
);
```

<a id="ollama-dimensions"></a>

Векторы документов и запросов должны использовать одну модель и одинаковую размерность. `OllamaEmbeddingProvider` передаёт настроенное значение `dimensions` в `/api/embed` и проверяет длину каждого полученного вектора. По умолчанию провайдер по-прежнему использует `qwen3-embedding:4b` и **запрашивает 1024 измерения**; собственная размерность модели — 2560. Сервер Ollama и выбранная модель должны поддерживать запрошенную размерность. Неподдерживаемый запрос или ответ, игнорирующий настройку, приводит к ошибке, а не к скрытому изменению `Dimensions` или локальному изменению длины векторов.

При смене модели или размерности заново создайте эмбеддинги документов с теми же настройками, что и у запросов, и настройте векторное хранилище соответственно. Существующие векторы автоматически не преобразуются.

### vLLM (самостоятельный хостинг)

Для команд с собственным сервером [vLLM](https://docs.vllm.ai/):

```csharp
var embedder = new VllmEmbeddingProvider(
    httpClient: new HttpClient(),
    model: "Qwen/Qwen3-Embedding-0.6B",
    dimensions: 1024,
    baseUrl: "http://localhost:8002"
);
```

### Local (без API)

Легковесный провайдер на основе хеширования признаков, без API-ключа и внешних сервисов. Однако качество эмбеддингов значительно уступает нейросетевым моделям, поэтому **не рекомендуется для рабочего применения**.

```csharp
.WithRag(rag => rag
    .UseLocalEmbedding(dimensions: 1024)
    .AddDocument("docs.txt")
)
```

> **Совет:** Используйте `OpenAIEmbeddingProvider` с моделью `text-embedding-3-small`. Стоимость практически нулевая, а результаты значительно лучше.

## Пакетная обработка

При индексации чанки обрабатываются пакетами:

```csharp
var options = pipeline.Options.Clone();
options.EmbeddingBatchSize = 100; // по умолчанию: 100 чанков за вызов
pipeline.Options = options;
```

`EmbeddingBatchSize` должен быть положительным. Конвейер проверяет и фиксирует значение в начале каждого вызова индексации документа, до эмбеддинга или замены записей. Это предотвращает цикл пустых пакетов и пропуск чанков при изменении настройки во время асинхронного ожидания. Последующие вызовы могут использовать новое значение.

<a id="embedding-validation"></a>

## Соответствие каждого вектора своему фрагменту

Успешный HTTP-ответ всё равно может содержать пропущенные векторы или неверный порядок. Тогда текст будет сопоставлен со смыслом другого фрагмента. Пользовательский `IEmbeddingProvider` должен возвращать ровно один ненулевой `float[]` на каждый вход в исходном порядке и задавать положительный `Dimensions`. Длина каждого вектора должна равняться этой размерности, а все значения должны быть конечными, без `NaN` и бесконечности.

При индексации документов конвейер отклоняет неверные размерности, количество ответов или векторы с `InvalidOperationException` до записи или `onDocumentEmbedded`. Каждый принятый вектор копируется до запроса следующего пакета, поэтому повторное использование буфера провайдера в следующем пакете не изменит предыдущие фрагменты. Возвращённые данные должны оставаться неизменными во время чтения; конкурентные изменения во время проверки или копирования не поддерживаются. При ошибке проверки прежние записи документа сохраняются.

`OpenAIEmbeddingProvider` требует корректный уникальный `index` для каждого элемента ответа и восстанавливает исходный порядок. `VllmEmbeddingProvider` применяет то же правило при наличии индексов; для совместимости допускаются и ответы, где `index` отсутствует у всех элементов, с сохранением порядка ответа. Частично отсутствующие, повторяющиеся или выходящие за диапазон индексы отклоняются. Пользовательский провайдер или ответ без индексов сам отвечает за порядок; проверка структуры не проверяет смысл вектора.

<a id="query-embedding-validation"></a>

## Защищать вектор вопроса перед поиском

Повторное использование буфера не должно менять вопрос во время ожидания уведомлений или поиска. Встроенный плотный поиск, включая адаптер `IRetrievalStrategy`, требует положительное `Dimensions`, ненулевой вектор строго этой длины и конечные значения. Некорректный результат вызывает `InvalidOperationException` до поиска. Принятый вектор копируется сразу после возврата, до последующих уведомлений и поиска. Провайдер должен сохранять данные неизменными во время чтения; собственный `IRagRetriever` отвечает за свою подготовку и проверку.

`OllamaEmbeddingProvider` проверяет структуру, точное количество векторов, размерность и конечность значений также при прямых одиночных и пакетных вызовах. Некорректный JSON или вектор вызывает `InvalidOperationException` вместо неполного результата. Переданный `HttpClient` остаётся собственностью вызывающего кода; освобождение HTTP-запросов и ответов не освобождает клиент.
