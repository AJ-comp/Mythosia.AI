# Разделители текста

Результату поиска нужен контекст для ответа, но весь документ как один фрагмент мешает выделить нужное место. Разбиение задаёт баланс размера и контекста. Эти разделители работают локально по правилам без модели ИИ. Выбирайте по структуре документа и проверяйте поиск на своих вопросах.

## Доступные разделители

### CharacterTextSplitter

Для обычного текста, когда достаточно простого ограничения размера. Предпочитает заданный разделитель, но может разрезать предложение. По умолчанию `RagBuilder` использует `CharacterTextSplitter(300, 30)`; расширение `.md` не выбирает Markdown-разделитель автоматически.

```csharp
.WithTextSplitter(new CharacterTextSplitter(500, 50))
```

### RecursiveTextSplitter (рекомендуется по умолчанию)

Для текста, в котором абзацы и слова желательно сохранять вместе. Порядок по умолчанию: пустая строка → перенос строки → `. ` → пробел → отдельные символы. Это текстовые правила, а не оценка смысла моделью; точка с пробелом лишь приближённо определяет границу предложения.

Повторяющиеся элементы `Separators` применяются один раз, в порядке первого появления. Дублирование разделителя не добавляет проход разбиения. Длинные списки обрабатываются без глубоко вложенных рекурсивных вызовов.

```csharp
.WithTextSplitter(new RecursiveTextSplitter(500, 50))
```

### TokenTextSplitter

Только для приблизительного подсчёта слов, разделённых пробельными символами. Несмотря на название, `MaxTokensPerChunk` и `TokenOverlap` считают единицы `TokenSeparators` (по умолчанию пробел, табуляция и перенос строки), а не токены модели. В выводе разделители заменяются пробелами. Текст без пробелов может остаться одной длинной единицей; лимит токенов модели не гарантируется.

```csharp
.WithTextSplitter(new TokenTextSplitter(256, 32))
```

### MarkdownTextSplitter

Для Markdown-документов и Markdown из загрузчиков Office/HWP, когда важны заголовки, строки таблиц и блоки кода. Распознаёт ATX-заголовки (`#`–`######`), ограждённые блоки кода и таблицы. Это разделитель на правилах, не полный синтаксический анализатор Markdown. Конструктор принимает только `chunkSize`; у Markdown нет аргумента или настройки overlap.

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500))
```

#### Качество разбиения таблиц

Распознанные GFM-таблицы делятся между строками; заголовок и строка-разделитель повторяются в каждом табличном чанке. Внешние вертикальные черты необязательны (`Name | Value` поддерживается). Так сохраняются названия столбцов; качество поиска зависит также от документов, эмбеддингов и вопросов.

Жирный текст в ячейке относится к её строке: например, `**Без возврата**` в строке компании A не должен становиться условием для B. Ячейки таблиц и блоки кода не превращаются в повторяемые текстовые метки. Отдельная строка `**метка**` распознаётся только в начале абзаца или текстового блока, после пустой строки либо структурной границы. Жирная строка внутри продолжающегося абзаца не создаёт новый абзац или повторяемую метку. Распознанная метка может повторяться в частях этого блока; таблица, ограждение кода, заголовок или следующая распознанная метка заканчивает её область действия.

```
Исходная таблица:
| Имя    | Отдел | Зарплата |
|--------|--------|----------|
| Алиса  | Разраб. | 150 000    |
| Борис  | PM     | 140 000    |
| Вера   | Дизайн | 130 000    |

→ Чанк 1:
| Имя    | Отдел | Зарплата |
|--------|--------|----------|
| Алиса  | Разраб. | 150 000    |
| Борис  | PM     | 140 000    |

→ Чанк 2:
| Имя    | Отдел | Зарплата |
|--------|--------|----------|
| Вера   | Дизайн | 130 000    |
```

#### Защита блоков кода

Блоки в ограждениях из обратных кавычек или тильд остаются целыми. Закрывающее ограждение должно использовать тот же символ и быть не короче открывающего; короткое ограждение внутри блока не закрывает его. Ради сохранения блока допускается превышение `ChunkSize`.

Отступ открывающего ограждения сохраняется вместе с кодом, поэтому разбиение не меняет отступы отрисованного кода. Данные открывающего ограждения разбираются один раз на блок, а не повторно для каждой строки содержимого.

#### Хлебные крошки заголовков

По умолчанию `IncludeHeadingBreadcrumb` равен `true`: каждый чанк повторяет путь заголовков, сохраняя контекст найденного отрывка. `false` отключает только повторение, исходные заголовки остаются. Разделы, состоящие только из заголовка, также сохраняются.

`MinSplitHeadingLevel` принимает 1–6 и задаёт уровни заголовков, начинающих раздел; по умолчанию 1. При смене родительского заголовка предыдущий вложенный раздел завершается, чтобы его старый путь заголовков не применялся к новому содержимому.

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500)
{
    IncludeHeadingBreadcrumb = false
})
```

## Подбор параметров

`CharacterTextSplitter`, `RecursiveTextSplitter` и `MarkdownTextSplitter` измеряют кодовые единицы UTF-16 (`string.Length`), а не токены модели или видимые знаки. Суррогатная пара, например эмодзи, не разрезается. При размере 1 пара из 2 единиц может превысить лимит. Целостность комбинируемых символов и полных графем не гарантируется.

Размер должен быть положительным, перекрытие — неотрицательным. Неверные настройки вызывают `ArgumentOutOfRangeException` до обработки; изменяемые свойства проверяются повторно при разбиении. Перекрытие не меньше размера отключается для совместимости. В Character/Recursive это целевое значение, корректируемое по разделителям, границам Unicode и свободному месту следующего чанка; `0` означает отсутствие перекрытия. Дополнительный хвостовой чанк только из последнего перекрытия не создаётся.

У Markdown `ChunkSize` — бюджет содержимого **без повторяемого пути заголовков**. Целый блок кода или заголовок таблицы с одной полной строкой может его превысить. Обычный текст соблюдает размер с указанным исключением для суррогатной пары.

Повторение заголовков и шапок таблиц не должно превращать небольшой документ в неограниченный объём текста для эмбеддинга. Поэтому Markdown ограничивает общий вывод документа величиной `max(65536, 32 × document.Content.Length)` единиц UTF-16, суммируя длины всех итоговых чанков, включая повторяемые пути заголовков, шапки и метки. Проверка выполняется до создания чрезмерных повторений; при превышении выбрасывается `InvalidOperationException`, без усечения содержимого или возврата частичного результата. `ChunkSize` и исключения для неделимых блоков действуют в пределах этого общего ограничения. В стандартной индексации RAG ошибка разбиения возникает до эмбеддинга или замены записей, поэтому прежний индекс документа сохраняется. Это ограничение текста вывода, а не токенов модели или памяти процесса. Бюджет применяется к каждому вызову `Split` и растёт с длиной входа; это не фиксированный предел размера документа.

Начните, например, с `RecursiveTextSplitter(500, 50)` для текста или `MarkdownTextSplitter(500)` для Markdown и проверьте на типичных вопросах. Большие чанки сохраняют больше окружения; перекрытие повторяет текст и увеличивает работу эмбеддинга. Улучшение поиска не гарантируется.

Для строгого лимита считайте каждый итоговый чанк, включая повторённые заголовки, токенизатором целевой модели. Число символов/слов и языковые коэффициенты не задают безопасный бюджет токенов. При необходимости реализуйте `ITextSplitter` с этим токенизатором.

Исправления меняют границы чанков затронутых документов. Переиндексируйте те же ID документов, заменив старые чанки, и обновите связанные кэши эмбеддингов и эталонные результаты оценки. Сохранённые чанки не переписываются автоматически.

## Разделитель для каждого документа

В `RagBuilder` можно назначить отдельный разделитель для каждого документа:

```csharp
.WithRag(rag => rag
    .AddDocuments(new PlainTextDocumentLoader(), "readme.md", new MarkdownTextSplitter(600))
    .AddDocuments(new PlainTextDocumentLoader(), "data.txt",  new RecursiveTextSplitter(300, 30))
    .WithTextSplitter(new RecursiveTextSplitter(500, 50))  // по умолчанию для остальных
)
```

## Собственный разделитель

Если хотите написать собственный модуль разбиения и подключить его, реализуйте интерфейс `ITextSplitter`:

Индексация не должна сообщать об успехе, если один фрагмент перезаписывает другой. Задайте каждому фрагменту непустой ID, уникальный в коллекции, и скопируйте метаданные документа, чтобы сохранить фильтры по компании или правам доступа. В примере объединяются ID документа и номер фрагмента. Конвейер отклоняет отсутствующие ID и повторы внутри одного документа; новые ID взамен не создаются. См. [проверку при индексации](rag-pipeline.md#indexing-validation).

```csharp
public class SentenceSplitter : ITextSplitter
{
    public IReadOnlyList<RagChunk> Split(RagDocument document)
    {
        var sentences = document.Content.Split(". ");
        return sentences.Select((s, i) => new RagChunk
        {
            Id = $"{document.Id}_chunk_{i}",
            Content = s,
            Index = i,
            DocumentId = document.Id,
            Metadata = new Dictionary<string, string>(document.Metadata)
        }).ToList();
    }
}

// Регистрация:
.WithTextSplitter(new SentenceSplitter())
```
