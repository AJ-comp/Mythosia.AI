# Разделители текста

Разделители делят документы на чанки перед эмбеддингом. Размер чанка и перекрытие существенно влияют на качество поиска.

## Доступные разделители

### CharacterTextSplitter

Разбивает по количеству символов. Быстрый и простой, но может разрезать текст посреди предложения:

```csharp
.WithTextSplitter(new CharacterTextSplitter(500, 50))
```

### RecursiveTextSplitter (рекомендуется по умолчанию)

Старается разбивать по смысловым границам в порядке приоритета: абзацы → предложения → слова → символы. Даёт более связные чанки:

```csharp
.WithTextSplitter(new RecursiveTextSplitter(500, 50))
```

### TokenTextSplitter

Разбивает по количеству токенов, а не символов. Точнее учитывает лимиты контекстного окна LLM:

```csharp
.WithTextSplitter(new TokenTextSplitter(256, 32))
```

Полезен, когда модель эмбеддинга имеет строгие ограничения по количеству токенов.

### MarkdownTextSplitter

Структурно-осведомлённый разделитель, который понимает иерархию заголовков Markdown (H1–H6), блоки кода и таблицы, разбивая содержимое на семантически значимые единицы:

```csharp
.WithTextSplitter(new MarkdownTextSplitter(500, 50))
```

Оптимален для документации, README и выходных данных структурированных загрузчиков документов (Office, HWP).

> [!TIP]
> Загрузчики Word, Excel, PowerPoint и HWP внутренне преобразуют документы в Markdown. Использование `MarkdownTextSplitter` для этих документов гарантирует сохранение структуры таблиц и блоков кода при разбиении.

#### Качество разбиения таблиц

`MarkdownTextSplitter` разбивает Markdown-таблицы **построчно**. Строка никогда не разрезается пополам, а каждый результирующий чанк автоматически содержит **строку заголовка и разделитель**:

```
Исходная таблица:
| Имя    | Отдел | Зарплата |
|--------|--------|----------|
| Алиса  | Разраб. | 150 000    |
| Борис  | PM     | 140 000    |
| Вера   | Дизайн | 130 000    |

→ Чанк 1:
| Имя    | Отдел | Зарплата |
|--------|--------|----------|
| Алиса  | Разраб. | 150 000    |
| Борис  | PM     | 140 000    |

→ Чанк 2:
| Имя    | Отдел | Зарплата |
|--------|--------|----------|
| Вера   | Дизайн | 130 000    |
```

Каждый чанк является самостоятельной корректной таблицей, что гарантирует качество эмбеддингов и поиска.

#### Защита блоков кода

Блоки, ограниченные кодовыми оградами (`` ``` ``), обрабатываются как **атомарные единицы**. Блок кода никогда не разрывается, даже если он превышает размер чанка, сохраняя семантику кода.

#### Хлебные крошки заголовков

Каждый чанк автоматически получает префикс с путём заголовков, ведущим к его содержимому, обогащая контекст для векторного поиска:

```
# Руководство по продукту
## Установка
### Windows

(содержимое данного раздела)
```

Эта функция управляется свойством `IncludeHeadingBreadcrumb` (по умолчанию: `true`).

## Подбор параметров

| Параметр | Влияние |
|----------|---------|
| `chunkSize` (больше) | Больше контекста на чанк, меньше чанков, дешевле эмбеддинг |
| `chunkSize` (меньше) | Более точный поиск, больше чанков, больше эмбеддингов |
| `chunkOverlap` | Предотвращает потерю информации на стыках чанков |

Хорошая отправная точка: `chunkSize: 500, chunkOverlap: 50`.

## Размер чанка и количество токенов (многоязычность)

`chunkSize` измеряется в **символах**, но ограничения моделей эмбеддингов — в **токенах**. Одно и то же количество символов может давать совершенно разное число токенов в зависимости от языка:

| Язык | 1 000 символов ≈ токенов | Рекоменд. chunkSize |
|------|--------------------------|---------------------|
| Английский | ~250 токенов | 500–2 000 |
| Корейский / Японский / Китайский | ~800–1 500 токенов | 300–1 000 |

> [!WARNING]
> CJK-текст (корейский, японский, китайский) имеет значительно более высокое соотношение токенов на символ, чем английский. Если чанки превысят лимит токенов модели эмбеддингов (напр., 2 048 токенов), возникнет ошибка. Уменьшайте `chunkSize` с запасом при работе с CJK-документами.

Например, при модели эмбеддингов с лимитом 2 048 токенов:

```csharp
// Английские документы: 2000 симв. ≈ 500 токенов → с запасом
.WithTextSplitter(new MarkdownTextSplitter(2000, 200))

// Корейские документы: 1000 симв. ≈ 1000 токенов → безопасный диапазон
.WithTextSplitter(new MarkdownTextSplitter(1000, 200))
```

## Разделитель для каждого документа

В `RagBuilder` можно назначить отдельный разделитель для каждого документа:

```csharp
.WithRag(rag => rag
    .AddDocuments(new PlainTextDocumentLoader(), "readme.md", new MarkdownTextSplitter(600, 60))
    .AddDocuments(new PlainTextDocumentLoader(), "data.txt",  new RecursiveTextSplitter(300, 30))
    .WithTextSplitter(new RecursiveTextSplitter(500, 50))  // по умолчанию для остальных
)
```

## Собственный разделитель

Реализуйте интерфейс `ITextSplitter` для полностью пользовательской логики разбиения:

```csharp
public class SentenceSplitter : ITextSplitter
{
    public IReadOnlyList<RagChunk> Split(RagDocument document)
    {
        var sentences = document.Content.Split(". ");
        return sentences.Select((s, i) => new RagChunk
        {
            Content = s,
            Index = i,
            DocumentId = document.Id
        }).ToList();
    }
}

// Регистрация:
.WithTextSplitter(new SentenceSplitter())
```
