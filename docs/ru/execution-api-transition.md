# Управление выполняющимися задачами ИИ через Run

> Эти API требуют `Mythosia.AI` версии 7.1.0 или новее, включающей `Mythosia.AI.Abstractions` версии 3.1.0 или новее. Для примеров RAG нужен `Mythosia.AI.Rag` версии 7.6.0 или новее.

## Зачем управлять задачей во время выполнения?

Подготовка отчёта может включать несколько поисков по документам, обращений к API и этапов написания. Пока работа продолжается, пользователь может захотеть увидеть прогресс, остановить её или добавить условие, например: «Используйте только данные за этот год». Приложению нужен способ связать эти действия с уже выполняющейся задачей.

Run предоставляет объект задачи, который можно сохранить в приложении. Например, экран чата может показывать поступающий текст и вызовы инструментов, связывать кнопку «Стоп» с отменой и отправлять дополнительные указания, если модель это поддерживает. Все действия относятся к одному выполнению.

| Что нужно приложению | Что использовать |
| --- | --- |
| Получить готовый ответ без управления текущей работой | Продолжайте использовать `GetCompletionAsync`, включая типизированные и RAG-перегрузки. |
| Показывать текст по мере поступления и получить его целиком после завершения | Запустите задачу с `onText`, затем ожидайте `run.Result`. |
| Показывать работу инструментов или асинхронно обрабатывать вывод | Читайте события из `run.StreamAsync()`. |
| Позволить пользователю остановить работу | Вызовите `run.Cancel()` у сохранённого объекта. |
| Добавить условие до завершения задачи | Проверьте `run.CanSteer` и вызовите `run.SteerAsync(...)` для поддерживаемой модели. |

`StartRunAsync` запускает одну задачу модели и возвращает `AIRun`. Она продолжается независимо от того, читаете ли вы вывод. Один объект используется для потокового вывода, накопленного результата, отмены и поддерживаемых дополнительных указаний. `GetCompletionAsync`, включая типизированные и RAG-перегрузки, остаётся публичным удобным API для получения готового результата.

## Вывод текста через обратный вызов

В чате или консоли показ первых фрагментов сразу после их появления позволяет пользователю следить за длинным ответом, пока он ещё формируется.

```csharp
await using var run = await service.WithMaxRounds(10).StartRunAsync(
    "Прочитайте документы и подготовьте отчёт.",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);

string answer = await run.Result;
```

`onText` — необязательный `Action<string>`, который регистрируется до начала работы. Он получает текст по порядку, но не выполняет инструменты. Если нужен только результат, не передавайте его. Исключение в обратном вызове отменяет задачу и приводит к ошибке в `Result`. Не передавайте в `onText` лямбду `async`: она превратится в `async void`, поэтому задача не сможет ожидать её завершения или обработать её ошибки. Для асинхронной передачи используйте поток событий. Обратные вызовы не переключаются на поток UI автоматически.

`Result` объединяет текстовые события задачи, включая промежуточный текст между вызовами инструментов и текст, выданный до дополнительного указания. Это не второй запрос к модели и не заново переписанный ответ. Если нужна прежняя семантика завершённого ответа, можно продолжать использовать `GetCompletionAsync`.

## Чтение событий текста, инструментов и расхода токенов

Когда задача ищет документы или обращается к бизнес-API, одного текста бывает недостаточно, чтобы объяснить ожидание. Типизированные события позволяют показывать работу инструментов рядом с ответом и учитывать расход токенов, когда провайдер передаёт эти сведения.

```csharp
await using var run = await service.StartRunAsync(
    "Найдите документы и объясните результат.",
    cancellationToken: cancellationToken);

await foreach (var item in run.StreamAsync())
{
    switch (item.Type)
    {
        case StreamingContentType.Text:
            Console.Write(item.Content);
            break;
        case StreamingContentType.FunctionCall:
            Console.WriteLine("\n[Вызов инструмента]");
            break;
        case StreamingContentType.FunctionResult:
            Console.WriteLine("\n[Получен результат инструмента]");
            break;
        case StreamingContentType.Completion when item.Usage != null:
            Console.WriteLine($"\n[Всего токенов: {item.Usage.TotalTokens}]");
            break;
    }
}

string answer = await run.Result;
```

`run.StreamAsync()` принимает необязательный токен отмены наблюдения, но не промпт. Он наблюдает за задачей, уже запущенной через `StartRunAsync`. Зарегистрированные обработчики функций выполняются внутри библиотеки: не запускайте инструмент повторно при получении события для отображения. Настройки текстового вывода не отключают зарегистрированные инструменты задачи.

Обратный вызов при запуске и `run.StreamAsync()` могут наблюдать за одной задачей одновременно; поток событий поддерживает одного читателя. Например, выводите текст в `onText`, а в потоке обрабатывайте только события инструментов, чтобы не показывать текст дважды. Буфер хранит до 1 024 непрочитанных событий, даже если подключён обратный вызов. Поздний читатель получает события с начала, пока они помещаются в буфер. При превышении лимита чтение потока явно завершается ошибкой, но обратный вызов, выполнение и `Result` продолжаются. Не считайте поток неограниченным журналом для повторного воспроизведения. Для ожидания `Result` не требуется вычитывать поток событий.

## Асинхронная обработка вывода

Ожидайте асинхронную операцию внутри цикла чтения, а не передавайте асинхронный обратный вызов в `onText`:

```csharp
using var writer = new StreamWriter("report.txt");
await using var run = await service.StartRunAsync(
    "Подготовьте отчёт.", cancellationToken: cancellationToken);

await foreach (var item in run.StreamAsync())
{
    if (item.Type == StreamingContentType.Text && item.Content is string text)
        await writer.WriteAsync(text);
}
string answer = await run.Result;
```

## Отмена и освобождение ресурсов

- Выход из `await foreach` или отмена токена, переданного только в `run.StreamAsync(token)`, останавливает наблюдение; задача продолжает выполняться.
- `run.Cancel()`, токен, переданный в `StartRunAsync`, и освобождение активного объекта Run отменяют выполнение.
- `await using` гарантирует, что `DisposeAsync()` дождётся завершения производителя событий и очистки провайдера. Инструментам без поддержки отмены может потребоваться время на завершение; освобождение ресурсов не отменяет уже совершённые действия.
- Один сервис допускает одну активную задачу `StartRunAsync`. Попытка запуска второй одновременно отклоняется. Для независимых параллельных задач используйте отдельные сервисы; во время выполнения не смешивайте старые вызовы и не меняйте настройки сервиса.

До фонового выполнения задача фиксирует входные данные и ожидающую применения политику отдельного запроса. Встроенное текстовое, графическое и аудиосодержимое, а также массивы медиабайтов копируются. Пользовательские подклассы `MessageContent` сохраняют свою идентичность и не должны изменяться до завершения задачи.

Зафиксированное значение `FunctionCallingPolicy.TimeoutSeconds` задаёт один общий срок для подготовки задачи и всех раундов модели и инструментов. Его истечение приводит к `AIServiceException`; отмена пользователем переводит результат в отменённое состояние. Очистка по-прежнему ждёт обработчики, которые не поддерживают отмену.

## Дополнительные указания во время работы

Допустим, пользователь начал составлять план проекта, а затем понял, что нужно уложиться в две недели. Steering позволяет отправить это условие, пока модель ещё работает. Это полезно для исправлений и изменений объёма длительной задачи. Если после завершения возник новый вопрос, начните следующий запрос обычным способом.

```csharp
await using var run = await service.StartRunAsync(
    "Составьте план проекта.",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);

// Вызывайте из обработчика дополнительных указаний в UI, пока задача выполняется.
async Task SendUpdateAsync(string instruction)
{
    if (!run.CanSteer)
        throw new NotSupportedException("Эта задача не поддерживает дополнительные указания.");

    await run.SteerAsync(instruction, cancellationToken);
}

string answer = await run.Result;
```

Дополнительные указания во время выполнения поддерживает GPT-6 Astra через WebSocket-соединение Responses API. Другие провайдеры и неподдерживаемые модели могут выполнять обычные задачи Run, но `CanSteer` у них равен false, а попытка steering сообщает об отсутствии поддержки вместо скрытого создания следующего обычного запроса. `CanSteer` не гарантирует, что задача всё ещё будет активна к моменту последующего вызова.

Задачи Astra открывают отдельный сокет. Переданный `HttpClient` и его обработчики сообщений продолжают обслуживать HTTP-запросы и не перехватывают этот сокет. Для своего транспорта можно переопределить `OpenAIService.ConnectRunWebSocketAsync`.

Успешный `SteerAsync` означает, что сервер принял входные данные в очередь, а не что модель уже учла их. Продолжайте наблюдать за той же задачей или ждать результат последующего ответа. Уже переданный текст и совершённые действия не откатываются; начатые инструменты не отменяются только из-за отправки нового указания. Библиотека обрабатывает продолжение и сопоставление результатов инструментов в том же соединении. См. [руководство OpenAI по дополнительным указаниям](https://developers.openai.com/api/docs/guides/steering) и [режим WebSocket](https://developers.openai.com/api/docs/guides/websocket-mode). Нельзя предполагать, что очередь указаний текущего соединения пережила разрыв: не отправляйте принятое указание повторно без проверки.

## Задачи с инструментами и старые агентные методы

Вопросы вроде «Проверьте условия возврата и статус этого заказа» требуют нескольких источников. Зарегистрируйте инструменты поиска документов и проверки заказа, чтобы модель могла выбрать необходимые вызовы. Лимит раундов ограничивает число последующих запросов инструментов: задача должна завершиться или сообщить об ошибке.

Обычный вызов функций уже поддерживает повторяющиеся раунды модели и инструментов. `StartRunAsync` использует те же зарегистрированные функции и политики выполнения; отдельный агентный режим, планировщик или переключатель `WithAgentic` не требуется.

`RunAgentAsync` и `RunAgentStreamAsync` остаются доступными, но теперь выдают предупреждения `[Obsolete]`. На время перехода сохраняются прежние сигнатуры, значение по умолчанию `maxSteps = 10` и прежние ошибки превышения лимита. Новые места вызова оформляйте так:

```csharp
await using var run = await service.WithMaxRounds(10).StartRunAsync(
    "Найдите политику, проверьте заказ и объясните результат.",
    onText: text => Console.Write(text),
    cancellationToken: cancellationToken);
string answer = await run.Result;
```

Обычное значение `FunctionCallingPolicy.MaxRounds` по умолчанию равно 20, поэтому для сохранения прежнего агентного лимита укажите 10. `WithMaxRounds` задаёт переопределение политики на один запрос, не меняя `DefaultPolicy`. Настройте его до запуска. Старые агентные методы вместо этого копируют текущую политику по умолчанию и применяют свой аргумент `maxSteps`. Новый Run использует общий контракт ошибок выполнения и не обещает прежнее преобразование в `AgentMaxStepsExceededException` с `PartialResponse`. Если это важно для приложения, сохраняйте старый вызов до переноса обработки исключений.

## RAG, MCP и границы пакетов

- `RagEnabledService.StartRunAsync` принимает строку или `Message`, `onText`, `RagQueryOptions` для отдельного запроса, `streamOptions` и отмену. Поиск выполняется до запуска внутренней задачи; изображения, аудио и метаданные сохраняются, исходный ввод остаётся в истории, а дополненный текст передаётся через контекст запроса. Дополнение привязано к исходному вопросу пользователя, поэтому последующие результаты инструментов и дополнительные указания не заменяются исходным RAG-промптом. Steering передаёт уточнение модели, но не запускает RAG-поиск повторно автоматически.
- `WithAgenticRag` по-прежнему регистрирует инструмент поиска. Используйте его через `StartRunAsync`, и модель сможет запрашивать последующие поиски при необходимости. Регистрация MCP через `WithMcpServerAsync` также не меняется. Общие MCP-соединения освобождайте отдельно от использующих их задач.
- `IAIRunService` — необязательная возможность в `Mythosia.AI.Abstractions`; в `IAIService` не добавляются обязательные члены. Чтобы поддерживать запуск RAG Run, пользовательский сервис должен реализовать `IAIRunService`. Неподдерживаемые сервисы отклоняются до начала индексации RAG.
- RAG сохраняет зависимость от Abstractions, а провайдеры в отдельных пакетах — публичные переопределения методов генерации и доступные точки расширения. Этот переход не объявляет устаревшими API векторных хранилищ, загрузчиков документов или администрирования серверов.

О настройке рассуждения, веб-поиска или файлового поиска перед запуском Run и показе его источников см. [Рассуждение и ответы с источниками](reasoning-and-search.md).

## Совместимость и следующая мажорная версия

| API | Текущий статус |
| --- | --- |
| `GetCompletionAsync` / `GetCompletionAsync<T>` | Публичные и поддерживаемые, включая варианты интерфейса, провайдеров и RAG. |
| `StartRunAsync` / `AIRun` | Общий API выполнения и управления. |
| `RunAgentAsync` / `RunAgentStreamAsync` | Предупреждения об устаревании; прежнее поведение сохранено для совместимости. |
| Принимающие ввод `service.StreamAsync` и RAG `StreamAsync` | Доступны в этой минорной версии; запланировано исключение из публичного API в следующей мажорной. |
| `run.StreamAsync()` | Наблюдение за выводом существующей задачи без нового ввода. |
| `BeginStream(...).As<T>()` / `StructuredStreamRun<T>` | Прежний API типизированного потокового вывода сохранён; его выходной `Stream()` не является старым методом запуска запроса на сервисе. |

Следующая мажорная версия изменит публичные точки входа потоковых запросов, сохранив выполнение и необходимые точки расширения провайдеров. Изменение public-метода на private или protected всё равно нарушает исходную и бинарную совместимость, даже если тело метода сохранено. Цепочки сообщений, разовые вызовы, суммаризация, переписывание запросов и переранжирование не становятся устаревшими лишь потому, что используют существующие методы выполнения.
