# Управление диалогом

## Как работает история диалога

Каждый вызов `GetCompletionAsync` или `StreamAsync` добавляется во внутренний список сообщений сервиса. Таким образом модель располагает контекстом всех предыдущих ходов.

```csharp
await service.GetCompletionAsync("Мой любимый цвет — синий.");
var reply = await service.GetCompletionAsync("Какой мой любимый цвет?");
// → "Ваш любимый цвет — синий."
```

Чтобы начать заново:

```csharp
service.ClearMessages();
```

## Политика суммаризации

### Зачем нужна автоматическая суммаризация

Все сообщения истории отправляются модели с каждым запросом. По мере роста диалога возникают две проблемы:

1. **Стоимость** — длинная история означает больше входных токенов на запрос
2. **Превышение контекста** — если история выходит за контекстное окно модели, запрос просто не пройдёт

**`SummaryConversationPolicy`** автоматически сжимает старые сообщения в лаконичное резюме, сохраняя последние сообщения в оригинале. Модель видит суть всего разговора при минимальном расходе токенов.

### По количеству сообщений

```csharp
service.ConversationPolicy = SummaryConversationPolicy.ByMessage(
    triggerCount: 20,   // Суммаризировать, когда сообщений больше 20
    keepRecentCount: 5  // Последние 5 сообщений оставить как есть
);
```

### По количеству токенов

```csharp
service.ConversationPolicy = SummaryConversationPolicy.ByToken(
    triggerTokens: 3000,
    keepRecentTokens: 1000
);
```

### Комбинированный триггер (OR)

```csharp
service.ConversationPolicy = SummaryConversationPolicy.ByBoth(
    triggerTokens: 4000,
    triggerCount: 30,
    keepRecentTokens: 1300,
    keepRecentCount: 7
);
```

После настройки суммаризация происходит автоматически при вызове `GetCompletionAsync`.

### Как это работает

1. Перед каждым обращением к модели политика проверяет, не превышает ли диалог заданный порог.
2. Если порог превышен, старые сообщения суммаризуются в лаконичный текст с помощью stateless-вызова LLM.
3. Резюме внедряется как префикс системного сообщения — модель воспринимает его как предшествующий контекст.
4. Последние сообщения (управляемые параметрами `KeepRecentCount` или `KeepRecentTokens`) сохраняются дословно.

При использовании токенных триггеров политика автоматически использует **фактическое количество входных токенов**, сообщённое API (из последнего стримингового ответа), вместо локальной оценки, что обеспечивает точное срабатывание.

### Стриминг

Во время `StreamAsync` суммаризация автоматически не срабатывает. Вызовите её явно заранее:

```csharp
await service.ApplySummaryPolicyIfNeededAsync();

await foreach (var chunk in service.StreamAsync("Продолжим..."))
    Console.Write(chunk.Content);
```

## Сохранение и восстановление резюме

Сохраняйте резюме между сессиями, чтобы модель помнила контекст после перезапуска:

```csharp
// Сохранить
string saved = service.ConversationPolicy.CurrentSummary;

// Восстановить в новой сессии
service.ConversationPolicy.LoadSummary(saved);
```
