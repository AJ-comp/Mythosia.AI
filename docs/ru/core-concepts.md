# Основные понятия

На этой странице собраны базовые понятия, которые упоминаются в остальной документации. Со временем сюда будут добавляться новые понятия.

## Что такое раунд?

> [!NOTE]
> **Раунд (Round)** — это одна полная поездка туда и обратно между вашим приложением и моделью: приложение отправляет промпт, модель отвечает, и этот обмен составляет один раунд. Обычное сообщение в чате — это 1 раунд. Function calling и агенты могут соединять несколько раундов для одного сообщения пользователя.

### Самый простой случай: 1 раунд

В обычном сообщении чата вся беседа укладывается в один раунд.

```
приложение  →  "Сколько будет 2 + 2?"  →  модель
приложение  ←  "Четыре."                 ←  модель
```

`RoundUsage` срабатывает один раз с токенами этого раунда. `Completion.Usage` срабатывает в конце stream с тем же итогом, потому что раунд только один.

### Несколько раундов: function calling

Раунды множатся, когда модель не может ответить сама. Допустим, пользователь спрашивает *«Какая сейчас погода в Москве?»* — у модели нет доступа к погоде в реальном времени, поэтому ей нужно вызвать инструмент.

**Раунд 1 — модель решает вызвать инструмент**

Приложение отправляет модели сообщение пользователя вместе со списком зарегистрированных инструментов (например, `GetWeather`). Модель видит такую беседу:

```
system: Ты — погодный ассистент. Ты можешь вызывать GetWeather(city).
user:   Какая сейчас погода в Москве?
```

Вместо финального ответа модель возвращает **запрос на вызов инструмента**:

```
tool_call: GetWeather(city="Moscow")
```

Ход модели завершается, и раунд 1 тоже. `RoundUsage` срабатывает с токенами, потраченными в раунде 1. **Финального ответа для пользователя ещё нет.**

**Между раундами — приложение выполняет функцию**

Этот шаг **не** является вызовом LLM. Runtime Mythosia.AI вызывает вашу зарегистрированную реализацию `GetWeather` и получает `«15°C, облачно»`. Токены не расходуются.

**Раунд 2 — модель пишет финальный ответ**

Приложение добавляет результат инструмента в беседу и вызывает модель **ещё раз**. Модель теперь видит:

```
system:      Ты — погодный ассистент. Ты можешь вызывать GetWeather(city).
user:        Какая сейчас погода в Москве?
assistant:   [вызвал GetWeather(city="Moscow")]
tool_result: 15°C, облачно
```

Имея всю нужную информацию, модель пишет текст:

```
Сейчас в Москве 15°C и облачно.
```

Раунд 2 завершается. `RoundUsage` срабатывает второй раз — на этот раз только с токенами раунда 2 (входные токены обычно больше, чем в раунде 1, поскольку беседа стала длиннее). Когда stream закрывается, `Completion.Usage` срабатывает один раз с **суммой раундов 1 и 2**.

### Кратко

| Шаг | Вызов LLM? | Что происходит | Событие |
|---|---|---|---|
| Раунд 1 | ✅ | Модель решает вызвать `GetWeather` | `RoundUsage` (`RoundIndex=1`) |
| Между раундами | ❌ | Приложение выполняет функцию, получает `«15°C, облачно»` | `FunctionCall`, `FunctionResult` |
| Раунд 2 | ✅ | Модель видит результат и пишет финальный ответ | `RoundUsage` (`RoundIndex=2`, `IsFinalRound=true`) |
| Stream завершён | — | — | `Completion` (Usage = раунд 1 + раунд 2) |

### Больше инструментов — больше раундов

Если модели нужно выполнить цепочку из нескольких вызовов инструментов, раунды накапливаются. Для *«Сравни погоду в Москве и Санкт-Петербурге»*:

1. **Раунд 1** — модель вызывает `GetWeather("Moscow")`
2. Приложение выполняет → `«15°C, облачно»`
3. **Раунд 2** — модель видит результат и также вызывает `GetWeather("Saint Petersburg")`
4. Приложение выполняет → `«12°C, дождь»`
5. **Раунд 3** — модель объединяет оба результата в финальный ответ

Всего три раунда, и `Completion.Usage` суммирует все три. Индикатор контекста в UI должен использовать `RoundUsage.TotalTokens` последнего раунда — в этом примере раунда 3.
