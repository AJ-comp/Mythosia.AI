# Показывать функции, поддерживаемые выбранной моделью

Интерфейс чата должен предлагать рассуждения, поиск, инструменты и изображения с учётом подключения. Списки моделей в каждом приложении дублируют правила библиотеки и расходятся при смене провайдера, протокола или развёртывания. Снимки возможностей дают интерфейсу и проверкам выполнения общие определения моделей.

API входит в Mythosia.AI 8.0.0. Снимки — неизменяемые локальные описания известной поддержки, а не проверка аккаунта или сервера в реальном времени. Типы находятся в `Mythosia.AI.Models.Capabilities`.

## Before / After

Before: приложение поддерживает собственные списки. Ниже показан код приложения, а не API библиотеки.

```csharp
bool showReasoning = mySupportedReasoningModels.Contains(service.Model);
bool showSearch = mySupportedSearchModels.Contains(service.Model);
```

After: проверьте настроенный запрос и выберите поддерживаемые параметры. К модели обращается только заключительный вызов completion; просмотр возможностей не вызывает API.

```csharp
using Mythosia.AI.Models;
using Mythosia.AI.Models.Capabilities;

var request = service.CreateRequest("Объясни документы.");
AIModelCapabilities capabilities = request.GetCapabilities();

if (capabilities.GetReasoningSupport(ReasoningLevel.High)
    == CapabilitySupport.Supported)
{
    request = request.WithReasoning(ReasoningLevel.High);
}

string answer = await request.GetCompletionAsync();
```

`CapabilitySupport` различает `Supported`, `Unsupported` и `Unknown`. Для собственного развёртывания или серверного выбора может не хватать данных: `Unknown` не означает отсутствие поддержки. Пример включает дополнительные рассуждения только при известной поддержке. При неизвестной приложение выбирает сохранение настроек по умолчанию или разрешение попытки запроса.

`request.GetCapabilities()` читает модель, параметры провайдера и профиль, зафиксированные билдером. `service.GetCapabilities()` проверяет настройки сервиса по умолчанию, не расходуя параметры следующего вызова. Они не отправляют HTTP, не вызывают callbacks контекста или проверки выполнения, не меняют историю и не запускают работу. Списки доступны только для чтения. Запрос к сервису также просматривает настройки функций, ожидающие следующего вызова, сохраняя их для фактического запроса. Проверка не сериализует значения параметров функций по умолчанию или параметры размещённых инструментов и не выполняет подготовку профиля к запуску либо резервирование бюджета токенов.

Возможности описывают поддержку подключения, а не включённые настройки. Важны провайдер, API-протокол и режим, не только имя модели. Идентификатор учитывает переопределения и преобразование Qwen/Ollama; без единственной выбранной модели он может быть `null`. Пример Chat UI обновляет элементы управления по активному подключению и текущим настройкам, включая зарегистрированные инструменты, а не только по каталогу моделей. Поддержка семплирования может зависеть от режима рассуждений и наличия инструментов; после изменения этих настроек выполните проверку повторно. Неизвестная поддержка отображается отдельно от отсутствующей.

| API | Значение |
| --- | --- |
| `Reasoning`, `ReasoningLevels`, `GetReasoningSupport(...)` | Поддержка и уровни общего `WithReasoning`. |
| `NativeReasoning`, `NativeReasoningLevels`, `ThinkingBudgetPresets`, `ThinkingToggle` | Собственные настройки рассуждений провайдера и предлагаемые бюджеты. |
| `Streaming`, `FunctionCalling`, `AsyncFunctionCalling`, `Steering` | Поток, инструменты, нативные асинхронные инструменты и инструкции во время работы. |
| `WebSearch`, `FileSearch`, `ReasoningCachePreservation`, `ImageInput`, `StructuredOutput` | Размещённый поиск, изменение рассуждений с сохранением кеша, входные изображения и структурированный вывод. |
| `Temperature`, `TopP`, `FrequencyPenalty`, `PresencePenalty`, `MaxOutputTokens` | Поддерживаемый sampling и известный предел выходных токенов, допускающий null. |
| `Provider`, `Model` | Провайдер и отправляемая модель; идентификаторы могут быть неизвестны. |

`ReasoningLevels` относится к общему `WithReasoning`, `NativeReasoningLevels` — к собственным настройкам провайдера. `ThinkingBudgetPresets` предлагает варианты для UI, а не все допустимые бюджеты или полный числовой диапазон. `AsyncFunctionCalling` означает нативное асинхронное выполнение инструментов, а не просто локальный `Task` или параллельный запуск. `StructuredOutput` охватывает общий API типизированного вывода, включая запасной путь через промпт и исправление, и не гарантирует нативное ограниченное декодирование. Оба списка уровней используют `ReasoningLevel`; бюджеты являются целыми числами.

Снимок не гарантирует доступ аккаунта или готовность сервера и не делает неверные сочетания настроек допустимыми. Проверки и ошибки выполнения сохраняются. Перед дополнительной инструкцией проверьте `run.CanSteer`: поддержка модели не гарантирует, что Run ещё активен.

## Проверять генерацию изображений отдельно

Модель изображения выбирается независимо от чата. `service.GetImageCapabilities(imageModel)` проверяет заданную модель; без аргумента — модель изображений провайдера по умолчанию. Билдер чата не выбирает её. `Generation`, `Editing` и `Mask` помогают показать нужные действия.

```csharp
using Mythosia.AI.Models.Capabilities;

ImageModelCapabilities capabilities = service.GetImageCapabilities();
bool showEditing = capabilities.Editing == CapabilitySupport.Supported;
bool showMask = capabilities.Mask == CapabilitySupport.Supported;

foreach (var quality in capabilities.Qualities)
    Console.WriteLine(quality);

int? maximumImages = capabilities.MaxImages;
```

`Qualities`, `Backgrounds`, `OutputFormats`, `SizeKinds`, `Resolutions` и `AspectRatios` — типизированные списки только для чтения. `MaxImages` и `MaxInputImages` — известные пределы, допускающие null. Список не гарантирует любые сочетания: проверки размера, формата, качества, маски и модели остаются. Собственные или неизвестные модели не объявляются неподдерживаемыми.

Собственный `AIService` с надёжными определениями может переопределить protected `ResolveRequestCapabilities()`. По умолчанию возвращается `AIModelCapabilities.Unknown`. Отсутствие в каталоге не делает развёртывание неподдерживаемым. В `IAIService` нет новых обязательных членов; методы принадлежат `AIService` и его билдеру.

Если профиль собственного провайдера меняет флаги нативного режима, переопределите `ApplyCapabilityRequestProfile(AIRequestProfile)` и применяйте через `SetExecutionSetting(...)` только флаги, нужные для определения возможностей. По умолчанию этот хук ничего не делает. Общие настройки профиля уже захвачены builder; проверка не вызывает `ApplyRequestProfile` или `ApplyProviderSpecificRequestProfile`. Хук не должен выполнять валидацию, обратные вызовы, сериализацию, резервирование бюджета или менять состояние сервиса либо вызывающего кода. Временные настройки восстанавливаются после проверки, в том числе при исключении в переопределённом методе.
