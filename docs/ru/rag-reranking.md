# Переранжирование и настройка поиска

## Зачем нужно переранжирование

Векторный поиск возвращает кандидатов, отсортированных по близости эмбеддингов, но эта близость — лишь **приближение**. Чанк с оценкой 0.82 может быть на самом деле релевантнее чанка с оценкой 0.85 — эмбеддинг просто не смог их различить.

**Переранжирование** берёт начальный список кандидатов и оценивает каждый чанк относительно исходного запроса более мощной моделью, что даёт значительно более точное ранжирование по релевантности. Это особенно ценно, когда:

- В корпусе много похожих чанков (например, записи FAQ)
- Топ-результаты векторного поиска кажутся «близкими, но не совсем теми»
- Нужна высокая точность ответов в критически важных сценариях

## Варианты переранжирования

### LLM Reranker

Использует ваш AI-сервис для оценки результатов. Эффективен, но добавляет задержку:

```csharp
.WithRag(rag => rag
    .WithReranker(new LlmReranker(aiService))
    .AddDocument("corpus.txt")
)
```

### Cohere Reranker

Обращается к Cohere Rerank API — быстрый и точный:

```csharp
.WithRag(rag => rag
    .WithReranker(new CohereReranker(cohereApiKey))
    .AddDocument("corpus.txt")
)
```

### vLLM Reranker

Использует локально развёрнутый vLLM-эндпоинт переранжирования:

```csharp
.WithRag(rag => rag
    .WithReranker(new VllmReranker("http://localhost:8000"))
    .AddDocument("corpus.txt")
)
```

## Параметры извлечения

Управление количеством кандидатов и фильтрацией перед финальным отбором:

```csharp
.WithRag(rag => rag
    .WithTopK(5)                   // Итоговое число чанков
    .WithRetrievalMultiplier(3)    // Извлечь topK × 3 кандидатов (для переранжирования)
    .WithMinScore(0.6)             // Минимальная оценка сходства
    .AddDocument("corpus.txt")
)
```

- **`TopK`** — сколько чанков попадёт в контекст LLM
- **`RetrievalMultiplier`** — расширяет воронку, чтобы переранжирование имело больше материала для работы. Множитель 3 означает, что извлекаются 15 кандидатов, из которых после переранжирования остаются лучшие 5.
- **`MinScore`** — отсеивает всё ниже данного порога сходства, даже если результатов окажется меньше `TopK`

## Режим финального отбора

При использовании переранжирования можно выбрать способ расчёта финальной оценки:

```csharp
using Mythosia.AI.Rag;

// По умолчанию: учитываются только оценки переранжирования
.WithFinalSelectionPolicy(RagFinalSelectionMode.RerankerOnly)

// Смешивание оценок поиска и переранжирования
.WithFinalSelectionPolicy(RagFinalSelectionMode.WeightedBlend, retrievalWeight: 0.65)  // 65% поиск, 35% переранжирование
```

**`RerankerOnly`** — безопасный вариант по умолчанию: оценка переранжирования полностью заменяет начальную оценку поиска.

**`WeightedBlend`** — сохраняет исходный сигнал поиска, дополняя его оценкой переранжирования. Полезен, когда эмбеддинги уже высокого качества и переранжирование должно выступать в роли арбитра, а не полной замены.
