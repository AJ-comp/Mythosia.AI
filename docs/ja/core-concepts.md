# 基本概念

このページには、ドキュメント全体で繰り返し参照される基本概念をまとめています。概念が増えるたびに、このページにセクションが追加されていきます。

## ラウンドとは何か

> [!NOTE]
> **ラウンド (Round)** とは、アプリがモデルを 1 回呼び出して応答を受け取るまでの **1 往復** のことです。プロンプトを送り、モデルが返す、これで 1 ラウンドです。通常のチャットは 1 ラウンドで終わりますが、function calling や agent では 1 つのユーザーメッセージに対して複数のラウンドが連鎖することがあります。

### もっとも単純なケース: 1 ラウンドで完結する対話

通常のチャットメッセージでは、モデルは 1 回の呼び出しで回答を完結させます。

```
アプリ  →  "2 + 2 は?"            →  モデル
アプリ  ←  "4 です。"              ←  モデル
```

この場合、`RoundUsage` はこの 1 回の呼び出しで使われたトークンを保持し、ストリーム終了時に発火する `Completion.Usage` にも同じ値 (1 ラウンドだけの合計) が入ります。

### 複数ラウンドが発生するケース: Function Calling

モデルが単独で回答できないとき、ラウンドは増えます。ユーザーが *「今の東京の天気を教えて」* と尋ねたとします。モデルはリアルタイムの天気を知る手段がないため、ツール (関数) を呼び出そうとします。

**ラウンド 1 — モデルがツール呼び出しを決定**

アプリはユーザーメッセージと登録済みツール一覧 (例: `GetWeather`) をモデルに渡します。この時点でモデルに見えている会話は次の通りです。

```
system: あなたは天気 assistant です。GetWeather(city) を呼び出せます。
user:   今の東京の天気を教えて
```

モデルは最終回答を書く代わりに、**ツール呼び出し要求**を返します。

```
tool_call: GetWeather(city="Tokyo")
```

モデルのターンが終わり、ラウンド 1 も終わります。ここで `RoundUsage` が発火し、ラウンド 1 で使ったトークンが入ります。**ユーザー向けの最終回答はまだありません。**

**ラウンドの間 — アプリが関数を実行**

ここは **LLM 呼び出しではありません。** Mythosia.AI のランタイムが、あなたが登録した `GetWeather` の実装を直接呼び出し、結果 `"15°C、くもり"` を受け取ります。トークンは消費されません。

**ラウンド 2 — モデルが結果を見て最終回答を作成**

アプリは **ラウンド 1 でモデルが出した function_call と、その実行結果を一緒に** 会話に追加し、モデルを **もう一度** 呼び出します。モデルに見えている会話は次のようになります。

```
system:      あなたは天気 assistant です。GetWeather(city) を呼び出せます。
user:        今の東京の天気を教えて
assistant:   [GetWeather(city="Tokyo") を呼び出した]
tool_result: 15°C、くもり
```

必要な情報が揃ったモデルは、今度はテキストで回答します。

```
現在、東京は 15°C でくもりです。
```

ラウンド 2 が終わります。`RoundUsage` がもう一度発火し、今度はラウンド 2 のトークンだけが入ります (会話が長くなっているため、通常は入力トークンがラウンド 1 より多くなります)。ストリームが閉じると `Completion.Usage` が発火し、ここに **ラウンド 1 + ラウンド 2 の合計** が入ります。

### 全体像

| ステップ | LLM 呼び出し | 何が起こるか | イベント |
|---|---|---|---|
| ラウンド 1 | ✅ | モデルが `GetWeather` の呼び出しを決定 | `RoundUsage` (`RoundIndex=1`) |
| ラウンドの間 | ❌ | アプリが関数を実行 → `"15°C、くもり"` を受信 | `FunctionCall`, `FunctionResult` |
| ラウンド 2 | ✅ | モデルが結果を見て最終回答を作成 | `RoundUsage` (`RoundIndex=2`, `IsFinalRound=true`) |
| ストリーム終了 | — | — | `Completion` (Usage = ラウンド 1 + ラウンド 2) |

### ツールが増えればラウンドも増える

モデルが複数のツールを連鎖的に呼び出す必要がある場合、ラウンドは積み上がります。*「東京とソウルの天気を比較して」* の場合:

1. **ラウンド 1** — モデルが `GetWeather("Tokyo")` を呼び出す
2. アプリが実行 → `"15°C、くもり"`
3. **ラウンド 2** — モデルが結果を見て、さらに `GetWeather("Seoul")` も呼び出す
4. アプリが実行 → `"18°C、晴れ"`
5. **ラウンド 3** — モデルが両方の結果を統合して最終回答を作成

合計 3 ラウンドで、`Completion.Usage` はその 3 つの合計になります。UI のコンテキストメーターには、最後のラウンド (この例ではラウンド 3) の `RoundUsage.TotalTokens` を使えば十分です。
