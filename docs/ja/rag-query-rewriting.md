# クエリ書き換え

> 📍 **質問応答パイプライン:** **`クエリ書き換え`** → 埋め込み → フィルタリング → [検索](rag-hybrid-search.md) → [再ランキング](rag-reranking.md) → コンテキスト構築

## 会話の中での検索が難しい理由

人は会話するとき、前に話した内容を自然に省略したり代名詞で置き換えたりします：

> ユーザー：「返金ポリシーについて教えてください。」
> AI：「30日以内に返品すれば全額返金されます。」
> ユーザー：「**それ**の例外は何ですか？」

ここで「それ」は「返金ポリシー」を指しています。人はすぐわかりますが、「それの例外は何ですか？」をそのままベクターストアに送ると、埋め込みは「それ」が何を指すかまったくわかりません。その結果、的外れなドキュメントが検索され、回答品質が大きく低下します。

## クエリ書き換えとは？

**クエリ書き換え**はこの問題を解決する技術です。ベクターストアに検索する**前に**、会話の文脈を読んで代名詞や省略された表現を展開し、完全な検索クエリに変換します。

```
変換前：「それの例外は何ですか？」
変換後：「返金ポリシーの例外事項」
```

こうすることで埋め込みが質問の意図を正確に捉えられるようになり、検索結果が大幅に改善されます。

また**検索ゲート**機能も併せて提供します。「ありがとう！」のようにドキュメント検索が不要なメッセージでは検索を自動的にスキップし、不要なコストと遅延を削減します。

## 設定方法

`.WithQueryRewriter()`を追加すると、現在使用中のAIサービスがクエリ書き換えも処理します：

```csharp
.WithRag(rag => rag
    .WithQueryRewriter(250)          // 同じAIサービスを使用
    .AddDocument("docs.txt")
)
```

書き換え機は会話の文脈を分析し、ベクターストアが会話履歴なしでも理解できる独立した検索クエリを生成します。

## マルチターン会話でのRAG

`RagStore`を直接クエリする際は、会話履歴を一緒に渡すことで書き換え機が文脈を把握できるようにします：

```csharp
var history = new List<ConversationTurn>
{
    new ConversationTurn("返金ポリシーは何ですか？", "30日以内に返品できます。"),
    new ConversationTurn("デジタル製品は？", "デジタル製品は返金不可です。")
};

var result = await store.QueryAsync(
    query: "それに例外はありますか？",
    conversationHistory: history
);
```

書き換え機が会話の流れ全体を見て、「それに例外はありますか？」を「デジタル製品返金不可ポリシーの例外」のように具体的に書き換えます。あいまいな質問が明確な検索クエリに変わることで、検索結果が大きく改善されます。

## 検索ゲートの仕組み

すべてのユーザーメッセージがドキュメント検索を必要とするわけではありません。書き換え機はメッセージの性質を自動的に分類し、検索が不要な場合には空の書き換え結果を返します：

- 「ありがとう！」
- 「わかりました、助かります。」
- 「今おっしゃった内容を要約してください。」

検索ゲートが作動すると、パイプラインの残りのステージ（埋め込み → ベクター検索 → 再ランキング）がすべてスキップされ、AIが会話の文脈だけで直接応答します。不要な検索コストと応答遅延が削減されます。
