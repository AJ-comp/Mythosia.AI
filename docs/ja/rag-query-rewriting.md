# クエリ書き換え

## なぜクエリ書き換えが必要か？

マルチターン会話では、ユーザーは自然に代名詞や短い参照を使います:

> ユーザー: "返金ポリシーについて教えてください。"
> ユーザー: "**それ**の例外は何ですか？"

「それの例外は何ですか？」をそのままベクターストアに送ると、埋め込みは「それ」が何を指すかわかりません。検索結果が不正確になり、回答品質が低下します。

**クエリ書き換え**は検索前にこれらの参照を解決し、「それ」→「返金ポリシーの例外」に展開します。埋め込みが完全な意図を正確に捉えられるようになります。また**検索ゲート**も実装しており、「ありがとう！」のように検索が不要なクエリではベクター検索をスキップし、レイテンシーとコストを節約します。

## 設定

`LlmQueryRewriter`は埋め込み前にAIサービス自体を使ってクエリを書き換えます:

```csharp
.WithRag(rag => rag
    .WithQueryRewriter()             // 同じAIサービスを使用
    .WithQueryRewriteMaxTokens(250)  // 書き換えのトークン予算
    .AddDocument("docs.txt")
)
```

書き換え機は会話コンテキストを分析し、ベクターストアが履歴なしでも理解できる独立した検索クエリを生成します。

## マルチターンRAG

`RagStore`を直接クエリする際は、会話履歴を渡して書き換え機が参照を解決できるようにします:

```csharp
var history = new List<ConversationTurn>
{
    new ConversationTurn("返金ポリシーは何ですか？", "30日以内に返品できます。"),
    new ConversationTurn("デジタル製品は？", "デジタル製品は返金不可です。")
};

var result = await store.QueryAsync(
    query: "それに例外はありますか？",
    conversationHistory: history
);
```

書き換え機が全履歴を見て、「それに例外はありますか？」を「デジタル製品返金不可ポリシーの例外」のように書き換え、はるかに優れた検索結果を提供します。

## 検索ゲートの仕組み

すべてのユーザーメッセージがドキュメント検索を必要とするわけではありません。書き換え機はクエリを分類し、以下のようなメッセージに対して空の書き換え結果を返します:

- 「ありがとう！」
- 「わかりました、助かります。」
- 「今おっしゃった内容を要約してください。」

ゲートが作動すると、検索パイプライン全体 — 埋め込み、ベクター検索、再ランキング — がすべてスキップされ、LLMが会話コンテキストから直接応答します。
