## 현재 결과를 정하는 규칙

집계 대상은 **2026-09-24 09:46 UTC 이후 시작한 이번 실행의 완료된 TRX**와 아래에 명시한 중단 실행의 콘솔 근거 39건이다. 결과의 `className + 표시 testName`을 고유 키로 사용한다. 매 실행마다 달라질 수 있는 데이터 행 ID는 중복 제거 키로 사용하지 않는다.

1. 수정된 빌드로 검증한 케이스에는 명시적인 수정본 우선순위를 적용한다. 범위는 보고서 경로·클래스·테스트 이름으로 제한하며, 성공뿐 아니라 실패에도 같은 규칙을 적용한다.
2. 같은 우선순위에서는 **개별 `UnitTestResult.endTime`**이 가장 늦은 결과를 선택한다. 전체 보고서 종료 시간은 선택에 사용하지 않는다. 오래 실행된 원본 바이너리의 보고서가 나중에 끝났다는 이유로 수정 검증을 덮어쓰지 않는다.
3. 최초 실패, 후속 시도, 제외 사유와 원본 TRX 경로를 모두 남긴다. 최신 결과가 통과해도 이전 실패를 삭제하거나 처음부터 통과한 것으로 표현하지 않는다.
4. 각 TRX의 실제 결과 노드 수·상태별 수·실행 수를 TRX 카운터와 대조한다. 불일치나 불완전한 보고서는 완료 근거로 사용하지 않는다.

수정본 우선순위에는 OpenAI steering, Perplexity RAG/MCP, xAI 컨텍스트 오류 감지, xAI/DeepSeek 함수 체이닝, DeepSeek 기존 테스트, Google fixture 및 스트림 오류 진단 등이 명시되어 있다. 정확한 최신 범위는 로컬 `coverage-precedence.json`이 기준이다.

초기 Key Vault 접근이 샌드박스 네트워크 제한으로 막힌 보고서는 외부 제공자 호출 0건의 인프라 실패로 보존하고, 실제 API 결과에서는 제외했다. 중단된 일괄 실행이 존재하면 별도 클래스 실행으로 대체하되 그 시도도 제외 사유와 함께 남긴다. 계정·제공자 오류가 발생한 정상 네트워크 실행을 이 규칙으로 제외하지 않는다.

Pro의 SSE 본문 수신 중 취소나 서버 측 작업 중단까지 검증한 것은 아니다. 다른 모델의 기존 취소 테스트 통과는 이전 fixture 기준이므로 이 강화된 취소 확인 계약까지 검증했다고 해석하지 않는다. 원본 실패와 수정 검증을 모두 보존했으며 제품 코드 변경은 없었다.
- **GPT-5.6 Terra 함수 스트림:** 최초 실행은 함수 호출·결과 이벤트 이후 마지막 대화 역할이 `Function`인 상태로 끝나 `Assistant` 기록 검증에 실패했다. 원본 테스트가 `Error` 이벤트를 출력하지 않아 당시 제공자·전송 오류와 정상 종료의 빈 응답을 구분할 수 없다. 오류 즉시 실패와 이벤트·대화 역할 진단을 추가한 1회 재검증은 통과했다. 최종 `Assistant` 검증은 유지했으며, 실제 제품 코드의 결함을 수정한 것으로 주장하지 않는다. 최초 실패 원인은 미확정 상태로 보존한다.
- **Google:** Gemini 2.5 Pro의 추론과 출력에 필요한 토큰 예산을 조정한 configuration 검증은 통과했다. summary 검증은 재실행에서도 실패하여 성공으로 바꾸지 않았다. 별도 스트림 진단은 오류 이벤트를 명시적으로 실패 처리하도록 보강한 뒤 1건이 통과했다.
- **Anthropic Fable turn clearing:** 초기 응답에는 이전 turn의 합성 표식이 남아 2건이 실패했다. wire history·`clear_at`·현재 사용자 위치 등의 진단을 추가하되 최종 표식 부재 검증은 유지했다. 제품 코드 변경 없이 같은 2건의 진단 재실행은 통과했다. 최초 실패와 재현 변동은 이력에 남기며, 진단 추가만으로 제공자 동작이 수정되었다고 주장하지 않는다.

Perplexity RAG/MCP, Fable 진단, DeepSeek 기능 설정, xAI 체이닝, Google 토큰 예산 및 공통 함수 스트림 변경을 검토했으며 기존 핵심 검증식 삭제는 없었다. 테스트 입력·현재 API 도구명·지원 기능 설정을 바로잡고 오류 관찰을 강화한 변경과, 실제 제품 코드인 xAI 오류 감지 수정을 구분한다. 수정 후 통과 여부는 해당 TRX와 명시된 수정본 우선순위로 판단한다.

## 확인된 제공자·계정 한계

이 절은 실행 중 확인된 원인과 한계를 정리한다. 전체 최신 미결 목록과 개별 메시지는 `failure-current.json`을 기준으로 한다.

| 항목 | 관찰 및 판정 |
| --- | --- |

XLSX는 생성·검증·공유 흐름의 실제 실패다. 테스트를 약하게 바꾸거나 통과할 때까지 반복하지 않았다. 이 증거만으로 Excel이 실제 파일을 열지 못한다고 단정하지 않는다. Perplexity 전용 세 suite의 현재 유효 결과는 **46건 중 45건 통과, XLSX 1건 실패**이며, 등록 리소스 3건은 별도 차단 상태다.

## 설정이 없어 실행하지 못한 범위

Perplexity Profile·CustomSkill·Connector에 필요한 프로세스 설정 **9개가 모두 없는 것**을 값 노출 없이 확인했다. 등록 리소스 runner의 preflight가 실제 API 요청 전에 중단되었고, 해당 **3건은 blocked**다. 테스트용 외부 Profile·CustomSkill·Connector를 임의로 만들지 않았다.

`MYTHOSIA_PG_CONN`도 없어 별도 VectorDb 프로젝트의 실제 PostgreSQL 통합 검사 **23건은 차단**되었다. 이번 실행을 위해 DB를 새로 구축하지 않았다. 과거 실행의 임시 PostgreSQL/Qdrant 결과는 이번 검증 성공으로 재사용하지 않는다.

현재 조사한 Alibaba/Qwen, vLLM control-plane, 독립 MCP, RAG, Qdrant/Pinecone 테스트에는 mock/local 검증이 포함되어 있다. 이번에 설정된 실제 엔드포인트 전용 suite를 찾지 못한 범위는 실제 클라우드·서버 검증 완료로 표시하지 않는다. 공개 MCP 실행은 위 Perplexity 케이스로, OpenAI 임베딩은 아래 추가 진단으로 구분한다. 키가 존재한다는 사실만으로 해당 백엔드 검증이 완료되지는 않는다.

## 추가 OpenAI 임베딩 실제 호출

RAG 프로젝트의 mock 임베딩 검사와 별도로, 기존 빌드 DLL을 참조하는 격리 진단에서 아래 **6개 구성**을 확인했다. 각 요청은 짧은 합성 입력 2개를 새로 전송했으며 평가 캐시를 사용하지 않았다.

| 모델·생성자 설정 | 검증한 차원 | 실제 요청의 `dimensions` |
| --- | ---: | --- |
| `text-embedding-ada-002` | 1,536 | 생략 |
| `text-embedding-3-small` 기본값 | 1,536 | 1,536 |
| `text-embedding-3-small` 사용자 지정 | 128 | 128 |

검사 항목은 실제 전송 차원, 벡터 수와 인덱스·입력 순서, 원본 응답 값과의 일치, 정확한 벡터 길이, 모든 값의 유한성, 0이 아닌 벡터 norm이다. Ada에는 지원하지 않는 `dimensions`를 보내지 않았음을 확인했다.

총 **7건의 실제 HTTP 요청이 모두 200**이었다. 처음 6건 중 Ada의 응답 모델명이 `text-embedding-ada-002-v2`로 정규화되어 모델명 완전 일치를 요구한 진단이 실패했다. 해당 정규화 이름을 명시적으로 기록하는 Ada 진단을 1회 추가하여 모든 검사를 통과했다. 최초 진단 실패를 숨기지 않으며, 이 7건을 3,207개 MSTest 케이스에 더하지 않는다.

Perplexity에서 확인한 background 작업은 종료 상태였고 취소 검증은 `cancelled`에 도달했다. 알려진 background cleanup 실패는 없었다. 합성 sandbox 산출물은 제공자 측에 남아 있을 수 있으며, 별도 삭제 API를 호출하지 않았다. 다른 suite의 파일·스토어 정리는 해당 runner 증거로 따로 확인한다.
